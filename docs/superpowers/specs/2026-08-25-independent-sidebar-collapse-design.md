# 独立侧栏收缩与临时展开设计

## 目标

在桌面端进一步释放文档正文的横向空间，同时保留主导航和文档目录的可发现性。主导航与目录树各自拥有独立的收缩开关，任何一侧的状态变化都不改变另一侧的状态。

本设计只调整桌面端的侧栏布局与交互，不引入新的 UI 依赖，也不改变文档路由、内容清单和移动端的整体导航结构。

## 已确认交互

### 主导航

主导航始终存在，支持两个持久状态：

| 状态 | 面板行为 | 内容行为 |
| --- | --- | --- |
| 普通 | 文字可见；保留现有拖拽分隔线，可在当前最小/最大宽度范围内调整 | 正文使用剩余空间 |
| 紧凑 | 面板收缩到约 56px；只显示品牌标识和图标，分隔线不可拖拽 | 正文获得主导航释放的横向空间 |

主导航底部增加切换按钮：

- 普通状态显示“收起文字”语义的图标按钮，切换到紧凑状态。
- 紧凑状态显示“展开文字”语义的图标按钮，切换回普通状态。
- 紧凑状态下鼠标移入主导航图标轨道时，整个主导航面板临时恢复到用户最近一次保存的普通宽度；文字在原面板内出现，正文同步让位。
- 鼠标离开主导航区域后恢复 56px 紧凑宽度；不出现浮层或独立的悬浮导航面板。
- 键盘焦点进入紧凑主导航时执行与 hover 相同的临时展开，焦点离开主导航后恢复紧凑状态。
- 临时展开不改变“紧凑”持久状态，也不覆盖用户保存的普通宽度。用户需要通过底部按钮显式切换回普通状态，之后才可以拖拽调整宽度。

### 文档目录

目录树支持两个独立状态：

| 状态 | 面板行为 | 内容行为 |
| --- | --- | --- |
| 普通 | 使用现有可拖拽目录面板；保留当前最小/最大宽度范围 | 正文使用剩余空间 |
| 缩入 | 目录面板收缩到 0px；目录内容和分隔线不占空间 | 正文获得目录树释放的横向空间 |

目录树在普通状态的底部增加切换按钮。缩入后，底部按钮随面板一起隐藏，正文区域左上角显示一个浮动的“展开文档目录”图标按钮。该按钮使用绝对定位，不增加正文的纵向高度；点击后恢复目录树最近一次保存的普通宽度，并将焦点移入目录区域。

目录树没有 hover 临时展开行为。它只在普通状态与缩入按钮状态之间切换，避免用户在阅读正文时因鼠标经过左上角而意外打开目录。

### 独立性

主导航和目录树共有四种组合，但状态互不联动：

1. 主导航普通 + 目录树普通
2. 主导航紧凑 + 目录树普通
3. 主导航普通 + 目录树缩入
4. 主导航紧凑 + 目录树缩入

切换任意一侧时，只更新该侧的面板尺寸、按钮状态和可见性。

## 实现边界

### 面板与持久化

继续使用现有 `react-resizable-panels` 和 `usePersistentPanelLayout`：

- 保留 `pm-dashboard-app-shell`，继续保存主导航普通状态下的拖拽布局。
- 保留 `pm-dashboard-docs-layout`，继续保存目录树普通状态下的拖拽布局。
- 为状态增加独立的浏览器存储键：
  - `pm-dashboard-app-shell-sidebar-mode`
  - `pm-dashboard-docs-sidebar-mode`
- 状态首次读取不到时默认使用普通状态，保证现有用户升级后不会突然失去导航。
- 主导航使用 `Panel` 的 `panelRef` 和约 56px 的 `collapsedSize`；目录树使用 `panelRef` 和 `0px` 的 `collapsedSize`。普通宽度由现有布局持久化结果决定，不硬编码为新的固定宽度。
- 收缩、hover 临时展开、focus 临时展开和恢复动作都不写入普通布局存储。只有普通状态下的实际拖拽才更新普通宽度。
- 紧凑主导航状态下禁用或隐藏分隔线拖拽；目录树缩入状态下隐藏分隔线交互，避免通过拖拽破坏两个状态的语义。

### 组件职责

- `ResizableAppShell`
  - 持有主导航模式、面板引用和 hover/focus 临时展开状态。
  - 负责把普通布局回调与临时 resize 区分开，避免临时操作污染持久化宽度。
  - 将紧凑状态、切换回调和临时展开事件传给 `Sidebar`。
- `Sidebar`
  - 根据模式隐藏/显示导航文字。
  - 在底部渲染切换按钮，并为紧凑状态的图标按钮提供 `aria-label`、`title` 和 focus 样式。
  - 继续复用 `SidebarLinks`，移动端不启用桌面紧凑模式。
- `ResizableDocsLayout`
  - 持有目录树模式、面板引用和普通布局恢复逻辑。
  - 在 `docs-main` 内容容器内渲染缩入后的浮动召回按钮。
  - 通过轻量的 client context 向目录树内容提供“缩入目录”的回调，避免改变现有服务端 `DocsSidebar` 的 manifest 读取边界。
- `DocsSidebarClient`
  - 继续负责目录树展开、当前文件定位和文件下载入口。
  - 在桌面目录栏底部使用 context 提供的回调渲染缩入按钮。
  - 移动端保持现有 TOC 置顶和“展开全部目录”逻辑，不显示桌面缩入按钮。
- `usePersistentPanelLayout`
  - 保持现有布局读取/写入接口；如需扩展，仅增加对临时 resize 抑制的明确封装，不改变已有两个存储 ID。

## 交互与可访问性细节

- 使用 `lucide-react` 的面板收缩/展开图标，不手写新的图标 SVG。
- 所有仅图标按钮都必须有明确的 `aria-label` 和 tooltip；按钮保持原生 tab 顺序和可见 focus ring。
- hover 展开必须同时支持 `:focus-within` 或等价的键盘焦点逻辑，不能只依赖鼠标。
- 主导航临时展开增加一个很短的离开延迟，避免鼠标从图标轨道移动到文字区域时发生闪烁。
- 从目录树缩入状态恢复时，浮动按钮应在动画完成后把焦点交给目录树中的可见导航区域；若焦点所在元素已被隐藏，先将焦点移回召回按钮或正文容器。
- 面板收缩/恢复不改变当前路由、当前文档、目录树已展开的目录节点或下载入口。

## 移动端边界

在 `768px` 以下继续使用现有移动端路径：

- 主导航继续由 `MobileNav` 的 Sheet 承载，不显示桌面图标轨道和 hover 展开。
- 文档目录继续显示在正文上方，并保留当前针对大量目录的折叠逻辑。
- 桌面端保存的两个模式可以继续留在 localStorage，但移动端不应用它们；回到桌面端时再恢复用户最后一次桌面状态。

## 验证方案

### 自动化检查

- 为模式存储和布局回调增加纯逻辑测试，覆盖默认普通状态、模式读取失败回退、普通拖拽持久化以及临时 resize 不持久化。
- 保留并运行现有组件与 manifest 相关测试。
- 运行 `npm run lint` 和 `npm run build`。

### 浏览器验收

在桌面宽度至少 1280px 下验证：

1. 普通主导航可以拖拽，刷新后宽度保持。
2. 主导航切换到紧凑后，文字不可见、图标轨道保留，分隔线不能调整布局。
3. 鼠标移入紧凑主导航时，整个面板扩展到普通宽度，文字出现在原位置，正文让位；鼠标离开后恢复紧凑宽度。
4. 键盘 Tab 进入紧凑主导航时也会临时扩展，离开后恢复紧凑宽度。
5. 目录树缩入后面板与分隔线不占空间，正文左上角浮动按钮可见且不增加纵向空白。
6. 点击浮动按钮恢复目录树之前保存的宽度；重新缩入不会丢失该宽度。
7. 依次验证四种组合，确认两侧的切换互不影响。
8. 在移动端验证现有 Sheet 导航和目录置顶行为未回归。

## 不在本次范围

- 不改变文档正文最大宽度、Markdown 渲染、目录树节点展开规则或路由结构。
- 不将主导航和目录树合并为一个统一侧栏。
- 不增加全局“专注阅读”模式、快捷键系统或跨设备同步设置。
