# 缺口与矛盾复查

2026-11-13；对第一轮“多品牌平台可能都有父子树”的直觉做定向回查。

| 初始易错解释 | 回查证据 | 修正 |
|---|---|---|
| sub-brand / group等词足以证明品牌实体树 | CM02、CM04、EN05、EN07、EN11 | 区分组织治理、品牌集合、产品路径、文件夹；完整品牌树未知 |
| 能跨Group/Workspace统一看全部数据 | SA02、SA06、CM09 | Sprout常规明确无cross-group analytics；Influencer工作区隔离不证明跨空间汇总 |
| Emplifi所有比较都能切总量 | SA08 | 单profile对label图表为均值；多label比较才明确可切total/average |
| Compare与Combine是同一件事 | CM10、EN10、EN13 | 分项比较与逻辑合并分开描述；合并后指标去重仍需实测 |
| 看板有全局筛选，所有数字都会变 | SA10、SA15 | post/profile级widget和自定义tile有例外 |
| Rival IQ集合范围在各处一致 | RI02、RI03、RI05 | 普通筛选、集合汇总行和benchmark平均是否含Focus Company不同；不视为文档冲突 |
| 编辑集合后所有报表自动跟随 | SA04、CM13 | Reporting选中集合需重选；关键词组变动影响引用处，具体历史重算仍未知 |
| 厂商能力和用户效果可以互证 | CM01–08、UV01 | 多份官方文档仍是同厂商来源；单条历史评论只作弱线索 |

复查方法：追加parent/sub-brand/hierarchy、deduplication、workspace、combined、filter inheritance、Company Set summaries等检索，并直接打开命中文档。Meltwater部分旧链接重定向、新Analyze文档403，未将搜索摘要升为事实；Hootsuite反馈组件报错但正文可读，仅采用正文；Brandwatch旧定义与较新Retrieving文档核对对象存在性。各分组原始档保留访问限制。

已完成一轮反证，不等于所有重要未知项都消除。后续重点是带重叠数据的产品演示和真实客户任务，而不是继续堆产品名。
