## 已继承的阶段性结论

- 智能精选不是标准搜索的替代入口。
- 智能精选不提供“从 0 开始搜全库”的主路径。
- 输入应来自当前标准搜索结果生成的候选频道快照或引用。
- `query` 改为 `精选策略说明`，只影响 Agent 如何筛当前结果。
- 搜索结果列表右上方统一提供 `对当前结果做智能精选`。
- 主搜索框按钮保持经典搜索心智，不直接打开智能精选抽屉。
- `下一批` 不作为产品动作出现；长时间任务用批次进度表达。
- `重新精选` 基于原搜索结果快照创建新的并列 session。
- `继续精选` 在当前 session 内开启下一轮，以上一轮精选名单作为输入继续收窄。
- 第一版不提供基底选择器、轮次切换 UI 或树状历史。
- 不做树图，不开放全量历史轮次。
- session 以来源快照和当前结果为核心锚点；不同 session 并列独立，当前 session 只展示最新一轮结果。

## 当前风险

### 风险 1：旧 demo 心智仍然很强

处理：

- 新 demo 不再沿用“场景说明器”外壳。
- 只保留可复用数据和部分视觉 token。
- 按真实频道搜索结果页和工作台来重建。

### 风险 2：策略层容易做重

处理：

- 第一版采用半透明模式。
- 用户主入口仍是一句自然语言策略指令。
- 系统只展示轻量“理解摘要”，不开放完整策略编辑器。

### 风险 3：重新精选与继续精选容易混淆

处理：

- `重新精选` 使用原搜索结果快照，并创建新 session。
- `继续精选` 使用当前精选名单，并留在当前 session 内。
- 抽屉标题区明确展示本次输入来源。
- 运行中锁定两类动作，避免用户在生成中叠加新任务。

### 风险 4：列表快照与精选结果关系复杂

处理：

- 第一版只做轻量来源说明。
- 当前任务摘要展示 `第 N 轮 / 本轮输入`。
- 继续精选时，本轮输入显示为上一轮精选名单。
- 不做重型 diff 视图。
