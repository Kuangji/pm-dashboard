## 已继承的阶段性结论

- 智能精选不是标准搜索的替代入口。
- 智能精选不提供“从 0 开始搜全库”的主路径。
- 输入应是 `冻结的频道列表快照 / 引用 + 来源搜索条件集`。
- `query` 改为 `精选策略指令`。
- `下一批` 从产品动作中移除，分页或增量加载后续作为展示层问题单独设计。
- 默认动作是 `继续筛`，即基于当前结果继续收窄。
- `重新筛` 必须显式触发，基于本轮直接基底重算。
- 基底选择器只服务“下一条策略将作用于哪份列表”。
- 第一版基底选择器只开放 `当前列表 / 原始快照 / 最近 3 轮结果`。
- 不做树图，不开放全量历史轮次。
- session 以来源快照为核心锚点，session 之间完全独立。

## 当前风险

### 风险 1：旧 demo 心智仍然很强

处理：

- 新 demo 不再沿用“场景说明器”外壳。
- 只保留可复用数据和部分视觉 token。
- 按真实频道搜索结果页和工作台来重建。

### 风险 2：策略层容易做重

处理：

- 第一版采用半透明模式。
- 用户主入口仍是一句自然语言策略指令。
- 系统只展示轻量“理解摘要”，不开放完整策略编辑器。

### 风险 3：继续筛与重新筛容易混淆

处理：

- 默认输入区表达 `继续筛`。
- `重新筛` 放在当前轮次结果头部作为明确次级动作。
- demo 出来后专项回看入口位置、文案和提示强度。

### 风险 4：列表快照与精选结果关系复杂

处理：

- 第一版只做轻量关系说明。
- 主对比对象是本轮直接基底。
- 次级累计信息表达相对原始快照的收敛程度。
- 不做重型 diff 视图。
