# Spec v1 · 智能精选（v6.3.10）

> 业务规格 · 上游输入：`input_v1.md`  
> 状态：v1，可进入 design；后端接口字段与异常分支需在 PRD 前收口。  
> 范围：标准搜索结果桥接、精选策略抽屉、输入快照、批次产出、精选结果审阅、短期 session。

## §零 功能概述与公共约定

### 0.1 版本信息

| 属性 | 内容 |
| --- | --- |
| 版本号 | v6.3.10 |
| 文档阶段 | Spec v1 |
| 上游输入 | `input_v1.md` |
| 前置依赖 | v6.3.9 标准搜索自然语言输入 |
| 涉及端 | WEB，Desktop First |

### 0.2 版本定位

智能精选是频道搜索之后的精筛阶段。

当前主链路为：

```text
经典态搜索及结果
  -> 结果区智能精选入口
  -> 精选策略抽屉
  -> Agent 精选及精选结果
```

本版本不提供“从 0 开始”的全库 AI 搜索主入口。自然语言入口仍属于标准搜索框内部输入形态，主搜索框按钮保持线上搜索心智：先得到经典搜索结果。智能精选作为搜索结果页的外挂入口，只消费当前搜索结果作为候选频道输入。

### 0.3 核心名词

| 名词 | 定义 |
| --- | --- |
| 输入快照 | 开始 Agent 精选时冻结的一份候选频道列表快照或后端可追溯引用。 |
| 候选频道 | 当前搜索结果对应的频道快照。Agent 只能在这份候选频道上做语义细筛。 |
| 精选结果 | Agent 在候选频道上按精选策略和输出设置筛出的结果。 |
| 精选策略抽屉 | 搜索结果页上的临时抽屉，只用于整理进入 Agent 前的精选策略和输出设置，不编辑搜索条件。 |
| 精选策略说明 | 用户对当前搜索结果提出的筛选目标，可在抽屉中反复修改。 |
| 来源搜索条件 | 生成输入快照时标准搜索的生效条件集。用于解释来源，不在智能精选内直接编辑。 |
| 精选策略指令 | 用户对输入列表提出的自然语言精筛目标。它不是搜索 query。 |
| 策略理解摘要 | 系统对精选策略指令的轻量解释，例如优先项、排除项、重点研究项。 |
| 目标名单量 | 用户最终希望得到的精选频道数量。 |
| 批次产出 | 长时间 Agent 精选任务按固定批量逐步产出结果，例如每批 20 个。 |
| 当前批次 | 已展示给用户查看和处理的一批精选结果。 |
| 精选名单 | Agent 默认认定已入选的结果集合。用户无需逐条采纳。 |
| 移出列表 | 用户从精选名单中移出的频道集合，仅在当前 session 内作为补充排除信息。 |
| shortlist | 用户最终可消费的精选名单。 |

### 0.4 全局业务规则

- 经典态搜索只负责按标准字段生成候选频道。
- 自然语言搜索从经典搜索框切换进入，但提交后仍遵循主搜索框行为，先展示经典搜索结果。
- 智能精选只处理已有候选频道，不替代标准搜索。
- 智能精选入口统一出现在搜索结果列表右上方，文案沿用 `对当前结果做智能精选`。
- 点击入口后打开精选策略抽屉，确认后创建新的 Agent 筛选 session。
- session 锚定候选频道快照，不锚定标准搜索页面的动态状态。
- 输入快照默认冻结；后续标准搜索条件变化不影响已创建 session。
- 来源搜索条件可查看，不在智能精选内编辑。
- 大量目标名单量时，Agent 精选可按批次持续产出。批次产出是 session 状态，不是阻塞式弹窗。
- 用户可随时查看已产出的批次；但在 session 完成或被用户显式终止前，不允许保存至收藏夹、进入邀约或导出结果。
- 用户移出精选结果后，系统应询问是否补齐。补齐是基于当前 session 的小型增量任务，不直接改写需求说明。
- 用户追加目标名单量时，在不改变需求的前提下继续使用同一候选频道快照；追加入口归属 `目标名单量` 设置，并且仅在 session 完成或被显式终止后可用。

## §一 M1 · 经典态搜索与自然语言入口

### 1.1 功能目标

经典态搜索负责通过标准搜索条件生成候选频道列表。页面和结果区应尽量保持线上频道搜索心智，不因智能精选而明显变形。

自然语言入口通过经典搜索框内部的 `关键词 / 自然语言` 输入形态切换进入。用户提交自然语言后，仍由搜索页生成经典搜索结果；是否进入智能精选，由结果列表右上方的智能精选入口承接。

### 1.2 与 v6.3.9 的差异

v6.3.9：

```text
自然语言 -> 解析为标准搜索条件 -> 调用标准搜索 API -> 回到标准搜索结果页
```

v6.3.10：

```text
自然语言 -> 经典搜索结果 -> 对当前结果做智能精选 -> 精选策略抽屉 -> Agent 细筛
```

### 1.3 智能精选入口

入口展示规则：

- 统一放在搜索结果列表右上方。
- 关键词模式和自然语言模式都使用同一个入口。
- 主搜索框按钮不承担打开智能精选抽屉的职责，保持线上搜索行为。
- 点击 `对当前结果做智能精选` 时，以当前搜索结果生成候选频道输入快照。

## §二 M2 · 精选策略抽屉

### 2.1 功能目标

精选策略抽屉是标准搜索结果到 Agent 精选之间的临时编排态。它只负责整理“如何在当前搜索结果中继续精选”，不负责生成或修改搜索结果。

它不是结果页，也不是 Agent session 页。

### 2.2 确认对象与边界

精选策略抽屉表达：

1. `精选策略说明`：用户希望 Agent 如何筛选当前搜索结果。
2. `精选策略`：系统从说明中识别出的保留、排除和解释维度。
3. `输出设置`：例如输出数量；后续可扩展为风险偏好、边界候选保留、是否生成排除理由等。

抽屉不表达、不编辑：

- 候选范围。
- 结构化搜索条件。
- 搜索结果预览。
- 候选频道更新。

如果用户想改变候选频道，必须回到外部搜索页调整搜索条件并重新搜索。

### 2.3 迭代与关闭

抽屉内允许用户修改精选策略说明。修改流程：

```text
点击修改精选策略
  -> 展开输入框
  -> 用户修改
  -> 确认
  -> 系统重新识别精选策略
```

- 修改只影响精选策略说明和精选策略，不影响外部搜索条件或搜索结果。
- 取消修改时恢复当前已确认的精选策略说明。
- 用户直接关闭抽屉时，保留当前页面生命周期内已输入或已确认的精选策略说明。
- 页面刷新后，抽屉内临时内容失效，不跨 session 持久化。

### 2.4 开始 Agent 精选所需输入

从精选策略抽屉开始 Agent 精选时，必须携带：

- 当前搜索结果对应的候选频道快照或可追溯引用。
- 精选策略。
- 输出设置。

## §三 M3 · 标准搜索结果桥接

### 3.1 功能目标

让用户在标准搜索已经产出候选列表后，把当前搜索结果送入智能精选继续深筛。

### 3.2 入口位置

入口出现在经典搜索结果列表右上方。关键词搜索和自然语言搜索得到结果后都可展示同一入口。

建议文案：

- `对当前结果做智能精选`
- `进入智能精选`

避免使用：

- `带当前条件去 AI 搜索`
- `AI 搜索`
- `从 0 开始`

### 3.3 桥接行为

点击入口后：

- 打开精选策略抽屉。
- 以当前搜索结果生成候选频道输入快照。
- 记录来源搜索条件。
- 允许用户修改精选策略和输出设置。

不发生：

- 不改写标准搜索状态。
- 不在标准搜索页内直接替换结果。
- 不复用其它 session。
- 不在抽屉内修改结构化搜索条件。

### 3.4 快照范围

快照应代表当前搜索结果对应的整份候选频道，而不是当前页。

第一版可用后端引用表达，不要求前端持有完整列表。

必须记录：

- `snapshot_id` 或等价引用。
- 快照来源：标准搜索。
- 快照规模。
- 快照生成时间。
- 平台范围。
- 来源搜索条件摘要。

## §四 M4 · Agent 精选实体页（结果审阅型）

当前阶段采用结果审阅型 Agent 精选页。该页是一个新的稳定实体，用于承接已完成或可找回的精选任务，并让用户处理 Agent 输出的结果。

### 4.1 页面结构

Agent 精选页应包含：

1. `精选任务` 入口：在经典搜索页以提醒式入口出现，用于找回短期精选 session；进入 Agent 精选页后不常驻任务列表。
2. `任务摘要`：展示任务状态、需求说明、候选频道规模、目标名单量、已产出数量、已移出数量和当前批次。
3. `批次进度`：展示 Agent 是否仍在持续产出下一批结果；该进度不阻塞用户查看已产出结果。
4. `精选结果` 列表：展示 Agent 筛出的频道及处理动作。
5. `结果后动作`：展示保存至收藏夹、进入邀约和导出结果等去向；改需求入口归属精选任务列表。

### 4.2 精选结果列表

精选结果应与经典搜索结果保持频道识别上的一致性，并增加 Agent 特有信息：

- 推荐理由，作为入选的主解释。
- 风险提示，作为推荐理由的辅助信息，视觉层级低于推荐理由。
- 移出精选。

精选结果默认已经进入本次精选名单，不再要求用户逐条采纳。

精选名单是 session 内的当前结果集合。保存至收藏夹是结果后动作，只把当前精选名单写入收藏管理体系，不改变 session 生命周期，也不产生 `已保存` 这类 session 状态。

当前版本不展示匹配分、优先推荐、边界候选、人工复核等结果行标签。排序和筛选判断作为 Agent 内部过程，不在第一版结果审阅页中显性暴露。

`移出精选` 仅表示从当前精选名单中移出，不等于长期黑名单。移出行为应写入当前 session 的移出列表，作为后续补齐或追加精选的补充排除信息，但不直接改写需求说明。

### 4.3 拿到结果后的动作

用户拿到结果后至少需要以下动作：

- `移出精选`：从当前精选名单移出频道，并可选择是否补齐。
- `保存至收藏夹`：把当前精选名单保存到收藏夹，沿用现有收藏管理心智。
- `进入邀约`：把当前精选名单带入邀约准备流程。
- `导出结果`：导出频道基础信息、推荐理由、主要风险和处理摘要。
- `重新精选`：基于原搜索结果快照重新整理精选策略，并创建新的精选 session。
- `继续精选`：在当前 session 内开启下一轮，以当前精选名单作为本轮输入继续收窄结果。

当 Agent session 仍在持续产出批次时，`保存至收藏夹`、`进入邀约`、`导出结果`、`重新精选`、`继续精选` 默认置灰或锁定。用户需要等待完成，或显式终止本次继续产出后再进入下一步。

### 4.4 四类后续执行动作

Agent 精选结果页必须区分以下四类动作：

1. `追加目标`：当前 session 内继续跑，保留已有结果。适用于用户不调整需求，只增加目标名单量的情况。
2. `移出后补齐`：当前 session 内小型增量任务，保留已有结果，并吸收移出反馈。移出反馈进入当前 session 的移出列表，不直接改写需求说明。
3. `重新精选`：新建 session，不覆盖旧 session。适用于用户希望以同一份原搜索结果快照重新定义精选策略或输出设置的情况。旧 session 保留为历史，可从任务列表找回；如果用户要改变候选频道，应先回到外部搜索页重新搜索。
4. `继续精选`：当前 session 内开启下一轮，不新建 session。适用于用户认可当前精选名单，但希望在这份名单上进一步加强策略、继续收窄结果的情况。

`重新精选` 与 `继续精选` 不做树状层级，也不暴露父子任务关系。任务列表仍按独立 session 平铺展示；当前 session 内只展示最新一轮结果，并用 `第 N 轮 / 本轮输入` 说明当前结果来源。

### 4.5 批次产出、补齐和追加目标

大量目标名单量时，Agent 精选默认按批次持续产出：

```text
候选频道快照 A
  -> Agent 按需求和精选策略持续筛选
  -> 每批产出 20 个左右
  -> 用户可查看已产出批次
```

批次产出规则：

- 默认每批 20 个；具体批量可由配置或后端能力决定。
- 批次进度展示为非阻塞状态，例如 `已产出 20 / 100 · 第 2 批生成中`。
- `停止生成` 是批次进度操作，应放在进度区域，不放在任务摘要标题区。
- 用户可以查看已产出的批次，但不能在任务仍运行时直接保存、邀约或导出。
- 用户可以显式终止继续产出，终止后当前已产出的精选名单成为可处理结果。

补齐规则：

- 用户点击 `移出精选` 后，不立即自动补齐。
- 页面应询问是否补齐，让用户对加载和结果变化有预期。
- 用户选择补齐后，系统基于当前需求、候选频道快照 A、精选策略和移出列表即时计算补位。
- 补齐不直接改写需求说明；移出列表仅作为当前 session 的补充排除信息参与补位。
- 若候选频道快照 A 内可用结果不足，应提示 `当前候选频道内可补充结果不足`，并引导调整外部搜索结果或重新精选。

追加目标规则：

- 用户在不调整需求的情况下增加目标名单量时，应在当前 session 内追加目标，而不是新建搜索。
- 追加目标继续复用同一候选频道快照 A、同一需求说明和同一精选策略。
- 追加目标入口应收敛在 `目标名单量` 对应的任务摘要 block 内，不放在精选结果列表或结果后动作附近。
- 追加时不新增独立配置 block；在 `目标名单量` 小 block 内将当前数字原地切换为输入框，用户输入新的目标总数后确认。
- 当 Agent session 仍在持续产出批次时，追加目标不可用，避免用户在未完成的生成任务上继续改变目标量。
- 目标名单量只能增加，不能向下修改；若用户希望减少名单，只能通过移出精选或后续保存时选择范围处理。
- 目标名单量必须明显小于候选频道数量，不能等于、接近或超过候选频道数量。具体安全余量由后端能力和业务策略配置。
- UI 需要明确展示目标量变化，例如 `目标 100 -> 200`，并说明会继续从当前候选频道中筛选。
- 如果候选频道快照 A 内可用结果不足，应在追加前提示风险；若 Agent 完成筛选后仍无法达到目标名单量，应结束本次生成并提示 `当前候选频道无法达到目标名单量`，引导用户调整外部搜索结果或重新精选，而不是无限等待。

### 4.6 精选 session 状态与删除规则

频道搜索场景下，Agent 精选 session 是短期临时任务记录，不承担智能营销计划里的上下游项目状态。当前阶段仅定义以下用户可见状态：

- `运行中`：仍在按批次产出结果。
- `已停止`：用户显式停止继续产出，当前已产出结果可处理。
- `已完成`：本次目标量已完成产出。

频道搜索中不使用 `已保存` 作为 session 状态。保存至收藏夹是结果后动作，不改变精选 session 的生命周期状态。

删除规则：

- 删除入口只出现在精选任务列表或任务抽屉中，不出现在 Agent 精选结果页主操作区。
- 只有 `已停止` 和 `已完成` 的 session 可以删除。
- `运行中` session 不允许删除；用户需要先停止生成，再删除任务记录。
- 删除前需要二次确认，避免误删短期任务。
- 删除只移除频道搜索里的临时精选任务记录，不影响已经保存到收藏夹、已经导出的文件或已经进入邀约流程的数据。
- 删除后的任务从用户侧列表消失；后端可保留必要的操作日志，但不作为可恢复的用户入口。

### 4.7 重新精选与继续精选

当前结果页需要同时承接两种二次筛选意图，但必须避免树状任务心智：

- `重新精选`：基于原搜索结果快照创建新的精选 session，适合策略方向明显变化、输出设置变化，或用户希望保留旧 session 结果作为历史对照的情况。
- `继续精选`：在当前 session 内开启下一轮，以上一轮精选名单作为本轮输入，适合“在已有结果上再收窄”的漏斗式场景。

交互规则：

- 两个入口都使用精选策略抽屉整理新策略，但抽屉需要明确显示本次输入来源。
- `重新精选` 的输入来源是原搜索结果快照；确认后进入新的 session。
- `继续精选` 的输入来源是当前精选名单；确认后仍留在当前 session，生成下一轮结果。
- 当前 session 不提供轮次切换、轮次树或基底选择器；只展示最新一轮结果。
- 运行中的 session 不允许 `重新精选`、`继续精选`、保存、邀约、导出或追加目标，用户需等待完成或停止生成。

### 4.8 后续待定

以下内容暂不在当前 Demo 中最终定稿：

- 精选 session 的更长期留存时长、失败恢复和服务端日志规则。
- 推荐证据详情页。
- 排除原因的结构化记录方式。
- 与邀约、收藏夹、导出中心的真实数据联动边界。

## 附录 A · 旧版 Agent 工作台方案（待重审）

以下内容来自前一版“智能精选工作台”设想。当前阶段只作为后续讨论素材，不视为 v6.3.10 当前主线的定稿，也不要求 Demo 或 PRD 实现。

特别说明：

- 当前主线允许 `继续精选` 在当前 session 内产生下一轮，但不提供轮次切换 UI。
- 当前主线不提供基底选择器。
- 当前主线不提供 `继续筛 / 重新筛` 工作台模式切换；只提供结果页动作 `重新精选` 和 `继续精选`。
- 当前主线中，`重新精选` 创建新 session，`继续精选` 留在当前 session 内生成下一轮；两者不形成树状层级。

### A.1 页面结构

旧工作台主结构：

1. 输入快照卡。
2. 精选策略输入区。
3. session 摘要。
4. 当前轮次结果。

### A.2 输入快照卡

必须展示：

- 来源：标准搜索结果。
- 快照规模。
- 快照生成时间。
- 平台范围。
- 来源搜索条件摘要。

可提供：

- `查看来源条件`。
- `返回标准搜索结果`。

### 2.3 Session 侧栏

支持：

- 最近 session 列表。
- 当前 session 高亮。
- 新建 session。
- 改名。
- 删除已停止或已完成 session。

侧栏允许收起。收起状态是前端 UI 状态，不改变 session durable state。

---

### A.3 精选策略指令

#### 输入形态

策略输入以自然语言为主。

示例：

- `从这批候选里优先保留真实玩具测评频道，排除纯动画儿歌和低质搬运。`
- `继续筛，重点看近期更新稳定、妈妈群体适配度高、合作气质成熟的频道。`

#### 系统理解摘要

提交后，系统展示轻量摘要。

摘要可拆成：

- 优先。
- 排除。
- 重点研究。

第一版默认不可直接编辑摘要。用户修正方向时，优先通过新增自然语言策略完成。

#### 继续筛

默认输入态为继续筛。

规则：

- 基底默认是当前列表。
- 提交后生成下一轮结果。
- 新轮次仍属于当前 session。
- 当前 session 的已采纳 / 已排除继续保留。

#### 重新筛

重新筛是显式次级动作。

规则：

- 入口与当前轮次结果关联。
- 进入重新筛态后，基底自动切到本轮直接基底。
- 主按钮文案需要与继续筛不同。
- 提交后生成新轮次，仍属于当前 session。

---

### A.4 基底选择器

#### 功能目标

基底选择器用于决定“下一条策略将作用于哪份列表”。

它不负责切换当前正在浏览的结果。

#### 第一版选项

只开放：

- 当前列表。
- 原始快照。
- 最近 3 轮结果。

不开放：

- 全量轮次列表。
- 树状分支图。
- 复杂 lineage 管理。

#### 交互规则

- 默认选中当前列表。
- 用户切换基底后，当前结果区不立即变化。
- 提交策略后，系统基于所选基底生成新轮次。
- 新轮次生成后，基底默认回到当前列表。

### A.5 当前轮次结果

> 注意：本节为旧版工作台方案记录，不适用于当前 v6.3.10 结果审阅型主线。当前主线已取消逐条 `采纳 / 排除`，改为默认精选与 `移出精选`。

#### 结果列表

结果区展示当前激活轮次。

第一版以列表为主，不做卡片墙。

结果项应包含：

- 频道基础信息。
- 平台、地区、粉丝量、观看量等核心指标。
- 与策略相关的轻量判断说明。
- `采纳`。
- `排除`。

#### 采纳 / 排除

- `采纳` 进入当前 session 的已采纳集合。
- `排除` 进入当前 session 的已排除集合。
- 两个集合只在当前 session 内生效。
- 采纳 / 排除不是收藏、不是加入营销计划。

#### 轻量关系说明

结果区需要展示：

- 本轮基于哪份列表生成。
- 本轮结果数量。
- 相对本轮基底减少数量。
- 相对原始快照保留比例。

第一版不做重型 diff。

### A.6 Session

#### Session 数据

每个 session 至少包含：

- `session_id`
- `title`
- `snapshot_id`
- `snapshot_source`
- `snapshot_count`
- `snapshot_created_at`
- `source_search_conditions`
- `rounds[]`
- `active_round_id`
- `accepted[]`
- `excluded[]`
- `status`
- `created_at`
- `last_active_at`
- `deleted_at`

#### 轮次数据

每个 round 至少包含：

- `round_id`
- `base_type`
- `base_ref`
- `strategy_instruction`
- `strategy_summary`
- `result_count`
- `created_at`

#### 持久化规则

- 刷新后恢复最近活动的未删除 session。
- session 之间完全隔离。
- 切换 session 时，不带入上一个 session 的临时浮层状态。
- 删除后从主列表移出，不提供用户侧恢复入口。

## §五 当前阶段验收标准

- 经典态搜索页与结果区保持线上标准搜索心智。
- 用户能从同一个经典搜索框切换到自然语言输入形态。
- Demo 中自然语言输入框应可编辑，用于评审不同输入对经典搜索结果的影响；后端语义解析可先模拟。
- v6.3.10 自然语言提交后保持主搜索框心智，先展示经典搜索结果。
- 智能精选入口统一位于搜索结果列表右上方，关键词和自然语言结果共用同一个入口。
- 精选策略抽屉只表达精选策略说明、精选策略和输出设置，不展示候选范围或结构化搜索条件。
- 用户能在精选策略抽屉内修改精选策略说明；修改只影响精选策略，不影响外部搜索结果。
- 用户能理解智能精选不是重新搜索全库。
- Agent 精选页采用结果审阅型实体页，能展示精选任务、任务摘要、结果后动作和精选结果列表。
- Agent 精选页不展示 `已保存` 作为 session 内状态或 KPI；保存至收藏夹只作为结果后动作。
- 结果后动作至少覆盖移出精选、补齐询问、保存至收藏夹、进入邀约、导出结果、重新精选和继续精选。
- 异步 session 运行细节、失败恢复和证据详情页后续定稿。
- `下一批` 不作为产品动作出现。
- 文档主口径应围绕当前搜索结果、候选频道、精选策略和精选结果展开。
