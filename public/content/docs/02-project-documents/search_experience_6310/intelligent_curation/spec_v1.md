# Spec v1 · 智能精选（v6.3.10）

> 业务规格 · 上游输入：`input_v1.md`  
> 状态：v1，可进入 design；后端接口字段与异常分支需在 PRD 前收口。  
> 范围：标准搜索结果桥接、输入快照、精选策略、轮次结果、session。

## §零 功能概述与公共约定

### 0.1 版本信息

| 属性 | 内容 |
| --- | --- |
| 版本号 | v6.3.10 |
| 文档阶段 | Spec v1 |
| 上游输入 | `input_v1.md` |
| 前置依赖 | v6.3.9 标准搜索自然语言输入 |
| 涉及端 | WEB，Desktop First |

### 0.2 版本定位

智能精选是频道列表之后的精筛工作台。

主链路为：

```text
标准搜索结果页
  -> 创建输入快照
  -> 智能精选 session
  -> 精选策略指令
  -> 当前轮次结果
  -> 继续筛 / 重新筛
```

本版本不提供“从 0 开始”的全库 AI 搜索主入口。

### 0.3 核心名词

| 名词 | 定义 |
| --- | --- |
| 输入快照 | 进入智能精选时冻结的一份频道列表快照或后端可追溯引用。 |
| 来源搜索条件 | 生成输入快照时标准搜索的生效条件集。用于解释来源，不在智能精选内直接编辑。 |
| 精选策略指令 | 用户对输入列表提出的自然语言精筛目标。它不是搜索 query。 |
| 系统理解摘要 | 系统对精选策略指令的轻量解释，例如优先项、排除项、重点研究项。 |
| 基底列表 | 下一条精选策略将作用于哪份列表。 |
| 原始快照 | session 创建时的输入快照。 |
| 当前列表 | 当前激活轮次的结果列表。 |
| 轮次 | 一次策略执行产生的一份结果。 |
| 继续筛 | 基于当前列表继续收窄。 |
| 重新筛 | 基于本轮直接基底重新生成一版结果。 |
| shortlist | 用户最终可消费的精选结果集合。 |

### 0.4 全局业务规则

- 智能精选只处理已有列表，不替代标准搜索。
- 标准搜索结果页是本期唯一桥接入口。
- 桥接时创建新的智能精选 session。
- session 锚定输入快照，不锚定标准搜索页面的动态状态。
- 输入快照默认冻结；后续标准搜索条件变化不影响已创建 session。
- 来源搜索条件可查看，不在智能精选内编辑。
- `下一批` 不是产品动作；分页、加载更多或增量展示后续作为结果区交互另行设计。
- `继续筛` 是默认主路径。
- `重新筛` 是显式次级路径。

## §一 M1 · 标准搜索结果桥接

### 1.1 功能目标

让用户在标准搜索已经产出候选列表后，把当前候选范围送入智能精选继续深筛。

### 1.2 入口位置

入口只出现在标准搜索结果页。

建议文案：

- `对当前结果做智能精选`
- `进入智能精选`

避免使用：

- `带当前条件去 AI 搜索`
- `AI 搜索`
- `从 0 开始`

### 1.3 桥接行为

点击入口后：

- 创建输入快照。
- 记录来源搜索条件。
- 创建新的智能精选 session。
- 进入智能精选工作台。

不发生：

- 不改写标准搜索状态。
- 不在标准搜索页内直接替换结果。
- 不复用其它 session。

### 1.4 快照范围

快照应代表当前搜索条件下的整份候选范围，而不是当前页。

第一版可用后端引用表达，不要求前端持有完整列表。

必须记录：

- `snapshot_id` 或等价引用。
- 快照来源：标准搜索。
- 快照规模。
- 快照生成时间。
- 平台范围。
- 来源搜索条件摘要。

## §二 M2 · 智能精选工作台

### 2.1 页面结构

工作台主结构：

1. 输入快照卡。
2. 精选策略输入区。
3. session 摘要。
4. 当前轮次结果。

### 2.2 输入快照卡

必须展示：

- 来源：标准搜索结果。
- 快照规模。
- 快照生成时间。
- 平台范围。
- 来源搜索条件摘要。

可提供：

- `查看来源条件`。
- `返回标准搜索结果`。

### 2.3 Session 侧栏

支持：

- 最近 session 列表。
- 当前 session 高亮。
- 新建 session。
- 改名。
- 归档。
- 恢复归档 session。

侧栏允许收起。收起状态是前端 UI 状态，不改变 session durable state。

## §三 M3 · 精选策略指令

### 3.1 输入形态

策略输入以自然语言为主。

示例：

- `从这批候选里优先保留真实玩具测评频道，排除纯动画儿歌和低质搬运。`
- `继续筛，重点看近期更新稳定、妈妈群体适配度高、合作气质成熟的频道。`

### 3.2 系统理解摘要

提交后，系统展示轻量摘要。

摘要可拆成：

- 优先。
- 排除。
- 重点研究。

第一版默认不可直接编辑摘要。用户修正方向时，优先通过新增自然语言策略完成。

### 3.3 继续筛

默认输入态为继续筛。

规则：

- 基底默认是当前列表。
- 提交后生成下一轮结果。
- 新轮次仍属于当前 session。
- 当前 session 的已采纳 / 已排除继续保留。

### 3.4 重新筛

重新筛是显式次级动作。

规则：

- 入口与当前轮次结果关联。
- 进入重新筛态后，基底自动切到本轮直接基底。
- 主按钮文案需要与继续筛不同。
- 提交后生成新轮次，仍属于当前 session。

## §四 M4 · 基底选择器

### 4.1 功能目标

基底选择器用于决定“下一条策略将作用于哪份列表”。

它不负责切换当前正在浏览的结果。

### 4.2 第一版选项

只开放：

- 当前列表。
- 原始快照。
- 最近 3 轮结果。

不开放：

- 全量轮次列表。
- 树状分支图。
- 复杂 lineage 管理。

### 4.3 交互规则

- 默认选中当前列表。
- 用户切换基底后，当前结果区不立即变化。
- 提交策略后，系统基于所选基底生成新轮次。
- 新轮次生成后，基底默认回到当前列表。

## §五 M5 · 当前轮次结果

### 5.1 结果列表

结果区展示当前激活轮次。

第一版以列表为主，不做卡片墙。

结果项应包含：

- 频道基础信息。
- 平台、地区、粉丝量、观看量等核心指标。
- 与策略相关的轻量判断说明。
- `采纳`。
- `排除`。

### 5.2 采纳 / 排除

- `采纳` 进入当前 session 的已采纳集合。
- `排除` 进入当前 session 的已排除集合。
- 两个集合只在当前 session 内生效。
- 采纳 / 排除不是收藏、不是加入营销计划。

### 5.3 轻量关系说明

结果区需要展示：

- 本轮基于哪份列表生成。
- 本轮结果数量。
- 相对本轮基底减少数量。
- 相对原始快照保留比例。

第一版不做重型 diff。

## §六 M6 · Session

### 6.1 Session 数据

每个 session 至少包含：

- `session_id`
- `title`
- `snapshot_id`
- `snapshot_source`
- `snapshot_count`
- `snapshot_created_at`
- `source_search_conditions`
- `rounds[]`
- `active_round_id`
- `accepted[]`
- `excluded[]`
- `status`
- `created_at`
- `last_active_at`
- `archived_at`

### 6.2 轮次数据

每个 round 至少包含：

- `round_id`
- `base_type`
- `base_ref`
- `strategy_instruction`
- `strategy_summary`
- `result_count`
- `created_at`

### 6.3 持久化规则

- 刷新后恢复最近活动的未归档 session。
- session 之间完全隔离。
- 切换 session 时，不带入上一个 session 的临时浮层状态。
- 归档后从主列表移出，可从归档区恢复。

## §七 验收标准

- 标准搜索结果页能创建智能精选 session。
- 智能精选工作台能展示输入快照和来源条件。
- 用户能理解智能精选不是重新搜索全库。
- 用户能通过自然语言策略继续筛。
- 用户能显式触发重新筛。
- 基底选择器只影响下一条策略，不立即改变当前结果。
- `下一批` 不作为产品动作出现。
- session 可切换、可恢复、可归档。
- 文档不再使用 `总池 / query / 下一批 / 从 0 开始` 作为主口径。
