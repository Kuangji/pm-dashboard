# Design v1 · 智能精选（v6.3.10）

> 交互设计 · 上游规格：`spec_v1.md`  
> 状态：v1 当前固化经典搜索、精选策略抽屉和 Agent 精选结果审阅主线；session 完整生命周期仍待 PRD 前收口。  
> 原则：先让经典态搜索、自然语言输入形态、精选策略抽屉、Agent 精选结果页四者关系自洽，再细化证据详情和真实数据联动。

---

## 1. 当前主线

v6.3.10 当前 Demo 优先表达：

```text
经典态搜索及结果
  -> 同一搜索框切换到自然语言
  -> 经典搜索结果
  -> 结果区「对当前结果做智能精选」
  -> 精选策略抽屉
  -> Agent 精选及精选结果
```

其中：

- 经典态搜索只负责按标准字段生成候选频道。
- 自然语言入口仍属于经典搜索框内部输入形态。
- 主搜索框按钮保持线上心智：先得到经典搜索结果。
- 智能精选入口是结果区上的外挂动作，不影响现有搜索体验。
- 精选策略抽屉只整理 Agent 如何筛当前结果，不修改候选范围或结构化搜索条件。

## 2. 经典态搜索及结果

### 2.1 视觉基线

经典态搜索区应参考线上频道搜索页：

- 平台 tab。
- `频道 / 视频` 切换。
- 主要筛选项：网红分类、地区、粉丝量、筛选。
- 单一搜索框。
- `AI` 输入形态开关。
- 搜索结果列表、结果数量、排序、隐藏特定结果、分页。

这一层不展示 Agent 理由、风险、任务摘要，也不改变结果行结构。

### 2.2 智能精选桥接入口

入口统一放在经典搜索结果工具栏右侧，视觉位置沿用当前传统搜索的 `对当前结果做智能精选`。

推荐文案：

- `对当前结果做智能精选`

行为：

- 不直接开始 Agent 精选页。
- 先打开精选策略抽屉。
- 默认携带当前搜索结果对应的候选频道快照。
- 关键词模式和自然语言模式都使用同一个结果区入口。
- 主搜索框的 `展示结果` 只负责搜索，不负责打开智能精选抽屉。

## 3. 自然语言入口

### 3.1 输入形态切换

自然语言入口通过同一个搜索框内部的 `关键词 / 自然语言` 输入形态切换进入。

不做：

- 不单独展示 `639 自然语言搜索` 独立卡片。
- 不把自然语言塑造成标准搜索之外的另一套产品。

### 3.2 与 v6.3.9 的差异

v6.3.9：

```text
自然语言 -> 标准搜索条件 -> 标准搜索结果页
```

v6.3.10：

```text
自然语言 -> 标准搜索条件 -> 标准搜索结果页 -> 结果区智能精选入口
```

因此，用户点击自然语言模式下的 `展示结果` 时，应保持线上搜索体验：刷新或展示经典搜索结果。智能精选由结果列表右上方入口触发。

原因：

- 用户只想看经典搜索结果时不应被抽屉打断。
- 6310 的智能精选可以作为搜索结果后的增强能力外挂，不改变 639 已建立的搜索框心智。
- 只有用户显式点击结果区智能精选入口时，才进入 Agent 前的策略整理。

## 4. 精选策略抽屉

### 4.1 定位

精选策略抽屉是临时编排态，不是稳定结果页。

它需要让用户清楚看到：

- 当前将使用外部搜索结果作为候选频道。
- 用户希望 Agent 如何进一步筛选这些候选频道。
- 系统识别出的精选策略。
- 进入 Agent 前还需要哪些输出设置。

抽屉不再提及 `候选范围` 或 `结构化条件`。如果用户想改变候选频道，必须回到外部搜索页调整搜索条件并重新搜索。

### 4.2 推荐布局

抽屉采用右侧宽抽屉。

结构：

1. `精选策略说明`：展示当前策略文本和来源 meta，提供 `修改精选策略`。
2. `精选策略`：展示保留、排除、解释三类原子策略摘要；策略标签可点击切换状态。
3. `输出设置`：展示可输入的精选数量，以及轻量输出规则。

层级关系：

```text
当前搜索结果
  -> 精选策略抽屉
      ├─ 精选策略说明
      ├─ 精选策略
      └─ 输出设置
  -> Agent 精选结果页
```

### 4.3 迭代交互

`精选策略说明` 平时只展示文本。用户点击 `修改精选策略` 后，当前 block 原地展开输入框和 `确定 / 取消` 按钮。

修改流程：

```text
修改精选策略
  -> 输入策略说明
  -> 确定
  -> 抽屉主体短暂加载
  -> 更新精选策略说明和策略标签
```

交互边界：

- 修改只影响精选策略，不影响外部搜索条件和当前搜索结果。
- 取消时恢复当前已确认策略说明。
- 直接关闭抽屉时，保留页面生命周期内已确认或已输入的策略说明；刷新页面后失效。
- 不在抽屉底部保留 chatbox，不做多个 block 的输入入口。

### 4.4 精选策略设计方案

当前 Demo 采用方案 A。

#### 方案 A：原子策略集合（推荐用于当前 Demo）

把策略拆成可组合的原子项：

- 优先保留。
- 排除 / 降权。
- 结果解释。
- 用结构化开关承接非标准策略。

策略原子项如果表现为可点击控件，必须有即时反馈，例如 active/inactive 切换；点击不应只触发整页骨架加载。

优点：

- 用户能快速判断系统是否抓住了重点。
- 比整段方案更容易微调。
- 不会因为一个策略不合适就要求用户重写全部需求。

风险：

- 原子项过多时会变成复杂配置器。
- 后续需要控制默认展示数量。

#### 方案 B：完整方案摘要

系统输出一段完整精选方案，用户只能通过自然语言继续修改。

优点：界面简单，符合 Agent 心智。

风险：不够细，容易触发用户反复改写，且难以定位具体不满意点。

#### 方案 C：策略权重面板

将策略拆成若干维度并允许调权重，例如内容垂直度、近期活跃、妈妈群体适配、品牌合作成熟度。

优点：适合专业用户做精细控制。

风险：过早工具化，可能偏离自然语言确认流。

### 4.5 输出设置

第一版输出数量应允许用户自由输入，并做上下限约束：

- 最小值：1。
- 最大值：不超过系统上限，也不能超过当前候选频道数量。
- 输入不合法时应即时修正或提示。

UI 仍可预留轻量配置感：

- 输出数量。
- 是否保留边界候选。
- 是否生成推荐理由。
- 是否标记主要风险。
- 是否输出排除摘要。

这些配置控制精选结果的交付形态，不影响候选频道。

### 4.6 开始 Agent 精选

开始 Agent 精选时，需要带上：

- 当前搜索结果对应的候选频道快照或可追溯引用。
- 精选策略。
- 输出设置。

## 5. Agent 精选实体页（方案 B：结果审阅型）

当前 Demo 先采用方案 B：结果审阅型。该页不再作为占位工作台，而是作为一个稳定实体页，承接“Agent 已完成精选后，用户如何审阅、处理和进入后续动作”。

### 5.1 页面定位

Agent 精选页展示的是基于已确认输入得到的精选结果，不承担重新解释需求的职责。用户在此页主要完成三类动作：

1. 从经典搜索页的提醒式入口找回短期精选任务。
2. 查看 Agent 持续产出的精选批次，并处理少量不合适结果。
3. 在任务完成或显式终止后，将当前精选名单保存、导出、带入邀约，或选择重新精选 / 继续精选。

### 5.2 信息结构

页面采用结果审阅结构：

1. `任务摘要`：展示任务状态、需求说明、候选频道规模、目标名单量、已产出数量、已移出数量和当前批次。
2. `批次进度`：展示后台是否仍在产出下一批；进度不遮挡已产出结果。
3. `精选结果`：展示 Agent 筛出的频道列表。视觉上与经典搜索结果保持频道信息呼应，但只补充推荐理由、风险提示和移出操作。
4. `结果后动作`：保存至收藏夹、进入邀约、导出结果。三者在批次产出未完成前锁定。

短期精选任务列表不常驻在 Agent 精选页内。经典搜索页使用小型提醒入口打开抽屉；Agent 精选结果页在页面头部提供轻量 `精选任务` 按钮打开同一抽屉，用于找回任务或重新精选。该页不保留独立 `返回经典搜索` 按钮，避免页面级操作拥挤。

### 5.3 结果后的动作

拿到结果后，用户至少应能完成以下动作：

- `移出精选`：从本次精选名单中移出频道。移出是当前 session 的补充排除信息，不直接改写需求说明。
- `补齐询问`：移出后询问是否补齐，给用户明确的 loading 预期。用户确认后再即时计算补位。
- `保存至收藏夹`：将当前精选名单保存到收藏夹，沿用现有收藏管理心智。
- `进入邀约`：将当前精选名单带入邀约准备流程。
- `导出结果`：导出频道基础信息、推荐理由、风险提示和处理摘要。
- `重新精选`：基于原搜索结果快照重新整理策略，并创建新的精选任务。
- `继续精选`：在当前任务内开启下一轮，以当前精选名单作为输入继续收窄结果。

精选结果默认已经入选，不再逐条提供 `采纳`。`查看依据` 当前不作为行内按钮出现，推荐理由和风险提示常驻展示；若后续需要证据级详情，再做行详情或侧抽屉。

`已保存` 不作为 Agent 精选页内的任务状态或核心 KPI。保存至收藏夹只作为结果后动作反馈，当前 session 的结果集合仍用 `精选名单 / 已移出` 表达。

当前版本不展示匹配分，也不在结果行展示 `优先推荐`、`边界候选`、`需人工复核` 等标签，避免把尚未定稿的排序解释和处理分层提前产品化。

### 5.4 四类后续执行动作

Agent 精选结果页必须区分以下四类动作：

1. `追加目标`：当前 session 内继续跑，保留已有结果。用于不调整需求、只增加目标名单量。
2. `移出后补齐`：当前 session 内小型增量任务，保留已有结果，并吸收移出反馈。
3. `重新精选`：新建 session，不覆盖旧 session。用于基于同一份原搜索结果快照重新定义精选策略或输出设置；若要改变候选频道，应先回到外部搜索页重新搜索。
4. `继续精选`：当前 session 内开启下一轮，不新建 session。用于用户认可当前精选名单，但希望在这份名单上进一步收窄。

页面文案应避免把以上动作混称为 `重跑`。`重新精选` 是新任务，`继续精选` 是当前任务内下一轮；任务列表不展示父子层级。

### 5.5 Session 状态与删除

频道搜索里的 Agent 精选 session 是临时任务记录，不承载智能营销计划中的上下游状态。因此当前 Demo 只展示 `运行中`、`已停止`、`已完成` 三类状态，不使用 `已保存` 作为 session 状态。

删除入口只放在经典搜索页的精选任务抽屉内：

- `运行中` 任务不可删除，删除按钮禁用，并提示需先停止生成。
- `已停止` 和 `已完成` 任务可以删除。
- 删除前需要轻量二次确认。
- 删除后任务从列表消失；这只影响临时任务记录，不影响已保存到收藏夹、已导出或已进入邀约的数据。
- `重新精选` 可从精选任务抽屉或当前任务摘要区进入；确认后创建新任务，不影响原 session。
- `继续精选` 只在当前任务摘要区进入；确认后仍留在当前 session，生成下一轮结果。

### 5.6 批次产出与追加目标

Agent 精选默认按长时间异步任务处理。若用户要求大量结果，例如 100 个，结果页不等待全部完成后才展示，而是按批次持续产出：

```text
目标名单量 100
  -> 第 1 批产出 20 个
  -> 用户可查看已产出结果
  -> 第 2 批后台生成中
```

设计要求：

- 批次进度不做阻塞弹窗，不影响用户浏览已产出的批次。
- `停止生成` 归属批次进度区域，不放在任务摘要标题区。
- 批次产出完成或被用户显式终止前，不允许保存至收藏夹、进入邀约或导出结果。
- 用户移出结果后，不自动补齐；先询问是否补齐，再基于当前 session 即时计算补位。
- 移出列表作为当前 session 的补充排除条件参与补位和追加精选，但不直接影响需求说明。
- 用户在不调整策略的情况下增加目标名单量时，使用 `追加目标`，继续复用同一候选频道快照 A 和精选策略。
- `追加目标` 入口归属任务摘要里的 `目标名单` 小 block，不放在精选结果列表附近。
- 点击追加后，`目标名单` 的数字原地切换为输入框；用户输入新的目标总数并确认，不新增独立的追加目标 block。
- 目标输入态应前置展示候选频道规模和建议上限，例如 `候选频道 286 · 建议上限 228`，让用户在输入前就理解可用范围。
- 批次产出完成或被用户显式终止前，`追加目标` 与保存、邀约、导出一样不可用。
- 目标名单量只能增加，不能向下修改。
- 目标名单量必须明显小于候选频道数量；如果输入值接近候选频道规模，应在输入态阻断并说明。
- 追加目标前要提示候选频道可能不足，尤其当用户要求再追加 100 个或更多时。
- 如果 Agent 实际筛完仍达不到目标名单量，应以完成态提示 `当前候选频道无法达到目标名单量`，并引导调整外部搜索结果或重新精选。

### 5.7 仍需后续定稿

以下内容暂不在当前 Demo 中最终定稿：

- 精选 session 的留存时长、失败恢复和服务端日志规则。
- 推荐证据详情页。
- 排除原因的结构化记录方式。
- 与邀约、收藏夹、导出中心的真实数据联动边界。

## 6. 当前 Demo 验收

- 第一屏保持经典搜索页形态。
- 自然语言入口在同一个搜索框内切换。
- Demo 中自然语言输入框保持可编辑，以便评审不同输入对经典搜索结果的影响；语义解析结果可先使用模拟内容。
- 自然语言提交后保持搜索框行为，先展示经典搜索结果。
- 结果列表右上方统一展示 `对当前结果做智能精选`，关键词模式和自然语言模式共用同一入口。
- 精选策略抽屉首屏聚焦 `精选策略说明`、`精选策略` 和 `输出设置`。
- 精选策略抽屉不展示候选范围、结构化搜索条件、候选频道预览或返回确认动线。
- 点击 `修改精选策略` 后，输入框在策略说明 block 内原地展开，带确定和取消按钮。
- 直接关闭抽屉时，页面生命周期内保留当前策略说明；刷新后失效。
- 输出设置中的精选数量使用数字输入，限制上下范围。
- Agent 精选页采用结果审阅型实体页，能展示任务摘要、批次进度、精选结果列表和结果后动作。
- Agent 精选页不展示 `已保存` 作为 session 内状态或 KPI。
- 精选结果默认已入选，行内只保留 `移出精选`；推荐理由为主信息，风险提示为辅助信息。
- 移出后询问是否补齐，确认后再即时计算补位；补齐不直接改写需求说明。
- 批次产出完成或被用户显式终止前，保存至收藏夹、进入邀约、导出结果不可直接执行。
- 结果后动作至少覆盖保存至收藏夹、进入邀约、导出结果、追加目标、重新精选和继续精选。
- `重新精选` 创建新的并列 session；`继续精选` 在当前 session 内生成下一轮，只展示最新一轮结果，不展示树状层级。
- 任务抽屉只允许删除已停止或已完成 session；运行中 session 需先停止生成。
