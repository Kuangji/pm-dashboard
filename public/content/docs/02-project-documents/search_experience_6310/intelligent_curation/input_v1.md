# Input v1 · 智能精选（v6.3.10）

> 阶段状态：正式 input，后续进入 `spec -> design -> demo -> prd`  
> 前置依赖：`v6.3.9` 标准搜索自然语言输入、单频道相似网红

---

## 1. 背景与动机

`v6.3.9` 已经把本轮更确定的能力拆出：

- 标准搜索接入自然语言输入。
- 单频道相似网红多模态搜索。

`v6.3.10` 继续处理 `智能精选`。此前讨论中，智能精选曾被理解为一个与标准搜索并列的 AI 搜索入口，但这个定义会带来明显问题：

1. **它容易变成另一个经典搜索**  
   如果智能精选也从全库出发，用自然语言重新召回频道，那么用户会难以理解它和标准搜索自然语言模式的区别。

2. **它很难证明独立价值**  
   “AI 帮我再搜一遍”容易停留在更酷的交互形式，而不是更强的业务结果。

3. **它会和标准搜索建参逻辑纠缠**  
   标准搜索已经负责结构化召回和条件构建，智能精选继续承担这件事会让边界变模糊。

重新定义后，智能精选应成为经典搜索之后的下一阶段：

```text
标准搜索产出候选列表 -> 智能精选对列表做深筛 -> 输出 shortlist
```

它的价值不是“替代搜索”，而是“在已有候选里做更深的研究、比较、排除和压缩”。

## 2. 版本定位

`v6.3.10` 是搜索体验升级的第二阶段，定位为：

> 对一份可追溯的频道列表快照做智能精选，帮助用户从已有候选中进一步收敛出更可信、更适合后续消费的频道 shortlist。

本版本只锁定一条入口：

- `标准搜索结果页 -> 智能精选`

更广义的 `收藏夹 / 相似网红结果 / 营销计划候选池 -> 智能精选` 暂不纳入本期，但设计上应保留未来扩展空间。

## 3. 目标用户与场景

### 3.1 主用户：投放 PM / 项目负责人

他们已经通过标准搜索得到一批候选频道，但仍需要继续判断：

- 哪些频道真的适合当前合作目标？
- 哪些频道看起来相关，但内容质量或合作气质不合适？
- 哪些频道需要优先进入名单或后续沟通？

### 3.2 高频操作者：投放运营

他们需要把较大的候选列表快速压缩成可操作列表。

核心诉求：

- 不想逐页人工看几百个频道。
- 希望系统先按策略做一轮深筛。
- 希望能持续修正方向，而不是每次重新搜索。

### 3.3 结论消费者：团队协作者 / 销售 / 客户成功

他们可能不直接使用智能精选，但会消费 shortlist 或过程结论。

因此智能精选 session 需要可恢复、可解释、可复盘。

## 4. 核心需求目标

### Goal 1：输入必须是可追溯的列表快照

智能精选的直接输入不是搜索条件本身，而是一份冻结的频道列表快照或引用。

同时必须保留生成这份快照时的来源搜索条件，用于解释：

- 这份候选列表从哪里来。
- 它代表什么样的候选范围。
- 后续精选是在什么背景上继续进行。

### Goal 2：用精选策略指令驱动深筛

用户输入的不是搜索 query，而是精选策略指令。

策略指令表达：

- 优先保留什么。
- 排除什么。
- 重点研究什么。
- 最终想得到什么样的 shortlist。

第一版采用半透明模式：

- 用户主入口仍是一句自然语言。
- 系统展示轻量理解摘要。
- 不开放完整策略编辑器。

### Goal 3：显式区分继续筛与重新筛

用户很可能多次输入策略，但多次输入有两种完全不同的意图：

- `继续筛`：认可当前结果，基于当前结果继续收窄。
- `重新筛`：不认可本轮方向，回到本轮基底重新生成。

这两类意图必须在 UI 上显式区分，不能只靠用户修改一句话来隐式判断。

### Goal 4：session 独立且可恢复

每个智能精选 session 都锚定一份来源快照。

session 需要保留：

- 来源快照。
- 来源搜索条件。
- 轮次历史。
- 当前结果。
- 已采纳 / 已排除。
- 当前策略状态。

刷新页面或离开后返回时，应能恢复最近活动的未归档 session。

### Goal 5：保留轻量结果关系说明

第一版不做复杂 diff 或树图，但需要让用户知道：

- 当前结果基于哪份列表生成。
- 相对本轮基底减少了多少。
- 相对原始快照收敛到了什么程度。

## 5. 需求范围

### 5.1 Must

- 从标准搜索结果页创建智能精选 session。
- 生成并展示冻结输入快照。
- 展示来源搜索条件摘要。
- 提供精选策略指令输入区。
- 展示系统理解摘要。
- 默认支持 `继续筛`。
- 显式支持 `重新筛`。
- 提供基底选择器。
- 展示当前轮次结果。
- 支持采纳 / 排除。
- 支持 session 列表、切换、归档和恢复。

### 5.2 Should

- 展示相对本轮基底与原始快照的轻量收敛信息。
- 支持查看最近 3 轮作为基底。
- 支持来源条件展开查看。
- 在 session 标题中体现来源列表和策略目标。

### 5.3 Not In Scope

- 从 0 开始全库 AI 搜索。
- 任意频道列表入口全部接入智能精选。
- 完整策略编辑器。
- 树状历史图。
- 全量轮次选择器。
- 复杂 diff 对照视图。
- 自动写入收藏夹、营销计划或 CRM。
- 低召回 / 失败 / 超时的完整异常分支。

## 6. 成功标准

- 用户能理解智能精选处理的是“这份结果列表”，不是重新搜全库。
- 用户能看懂输入快照来自哪里、规模多大、由什么条件生成。
- 用户能明确区分 `继续筛` 与 `重新筛`。
- 用户能通过少量策略输入把候选列表逐步压缩成 shortlist。
- session 恢复后仍能复盘来源、策略和当前结果。
