# v7.5.4 主子品牌视图化查询｜一期建议方案 v1

> 2026-11-23 · Input 评审建议。用户已确认的范围以 [Input v2](input_v2.md) 为准。

建议把一期做成一条业务流程。用户从主品牌报告创建子品牌，保存池内查询条件，生成可独立打开的子品牌报告。主品牌继续提供线上标准报告，新增同池子品牌对比。对比基准、子品牌分项和明细使用同一批数据。已确认的范围是单主品牌池、子品牌快照、同池只做对比，以及主子报告以线上标准报告为基础。

## 1. 子品牌查询

**保存定义。** 每个子视图保存名称、所属主品牌池、收录平台、纳入条件及排除条件。所属主品牌随创建入口确定。规则条件长期有效，本次统计日期、平台等分析设置另行记录。

| 条件 | 一期建议 |
|---|---|
| 纳入 | 至少设置一项。支持内容文本的名称、别名或型号短语，完整标签，以及按平台和频道 ID 指定的发布账号。多条纳入条件取任一命中。 |
| 排除 | 支持内容文本短语或完整标签。命中任一排除条件后剔除该条内容。 |
| 平台与字段 | 按主池实际覆盖和该平台已验证的字段开放。文本的首批候选为 YouTube 标题、Instagram 和 TikTok 说明，标签使用已验证的对应字段。发布账号按平台和频道 ID 精确匹配。 |

执行顺序为「在主池和保存的平台范围内取数 → 判断是否命中任一纳入条件 → 剔除任一排除命中」。文本建议忽略大小写及首尾空白，连续短语匹配，标签建议按规范化后的完整标签匹配。预览和生成使用同一匹配逻辑。数据可以同时命中多个子品牌，上层关系和原始内容保持可追溯。

平台专用条件在其他平台不参与判断。每个选定平台至少有一项适用的纳入条件。若整个平台无法提供某项已选字段，先识别该条件无法执行，用户调整后再生成。单条内容的字段为空时，该条件对这条内容未命中，仍可按其他条件判断。

**预览和生成共用规则。** 保存前查看命中总数和按平台抽取的明细样本，能看到每条样本的命中条件。预览标明主池日期范围和数据截至时间。生成优先沿用同一批数据，使用更新批次时说明实际范围和截至时间。成功匹配到零条仍可保存。上游范围或查询不可用时提供明确状态。

## 2. 快照与刷新

**建议保存结果快照。** 冻结主池范围、各子品牌实际采用的规则版本、绝对日期范围、平台以及去重后命中的内容身份和计算采用的指标值。也可以引用能重现这些结果的不可变数据版本。数据截至时间用于说明采集时点。新增的子品牌对比一并记录同批主池基准，播放量等累计指标与内容明细能从同一份版本复现。

| 事项 | 一期默认建议 |
|---|---|
| 对比默认窗口 | 截至最近一个完整统计日的 30 个日历日，沿用主品牌统计时区，生成时落成绝对范围。 |
| 子报快照覆盖 | 首份快照同时覆盖对比窗口和本期承接的标准模块所需窗口。市场动态里的 72 小时或 30 天按各自的时段定义，以快照截至为基准。需一年或长期历史的模块按第 4 节的交付边界处理。 |
| 查看与筛选 | 独立打开子报读取最新成功发布的快照。对比入口下钻绑定当前显示的批次及日期、平台，对既有固定窗口的模块仍使用其标明的窗口。在已冻结范围内读取或二次筛选。超出范围的查询需发起新生成；支持的最大区间以全量验证确定。 |
| 触发 | 保存新建或修改后的规则触发生成。用户可从主品牌发起统一刷新，更新同池对比基准及已生效子品牌。推荐手动刷新，读取报告时使用已发布结果。 |
| 发布 | 每个主品牌使用一份当前发布的对比批次。生成前锁定主池、统计窗口、平台、指标截点、应参与的子品牌与各自规则版本。新增或编辑能用当前数据批次时，成功后发布新的对比版本，仍引用同一个数据批次。需要切换数据批次时，将待发布的子品牌及其他已生效分项按新范围一起生成，再整体切换。选择对比行只改变同一发布版本的展示范围。 |

取数成功和范围完整是发布前提。新批次尚未完整时继续使用上次成功结果，首次生成和尚未生效的新增分项有独立状态。常规刷新沿用当前已生效规则；新增或编辑失败的规则保留为待重试版本。当累计观看值缺失导致该指标无法完整统计时，标为该指标不可计算，不能当作零。若首发需缩成仅提及视频数，作为另一个待批准的交付范围。去重按稳定内容身份处理，建议从平台和原始内容 ID 定义。

主品牌标准报告按原有方式更新。比较区域声明本批次的日期范围、平台和截至时间。旧子报 60 条、同批主池 100 条时覆盖率为 60%，即便当前主品牌标准报告后来显示 200 条。

## 3. 主品牌报告增量

保留现有标准报告内容与统计行为，新增一项同池子品牌对比能力。用户可以选择一个或多个子品牌，同时看到主品牌同批基准、每个子品牌的实际值和对主品牌覆盖率，并打开子品牌报告或明细。

| 指标 | 一期建议 |
|---|---|
| **提及视频数及覆盖率** | 主品牌基准为同一批次与日期、平台范围内的主池去重视频数。分项使用该子品牌命中的去重视频数。覆盖率为分项除以主品牌基准。 |
| **观看量及覆盖率** | 同一批次按去重视频统一汇总观看量，覆盖率使用同口径的主品牌观看量作为分母。页首「总曝光量」和内容库「总浏览量」需先对齐字段和采集截点。 |
| **解释总量的指标** | 建议在全部已生效子品牌具备同批完整数据时提供未归入数。按主池减去该批次全部已生效子品牌的唯一内容集合计算，所选对比行的变化只影响对比范围。 |

同一比较范围中，各子品牌共用该日期及平台范围内的主池分母。子品牌保存的平台属于自身收录条件，限制该分项的命中集合，并应随分项说明。平台维度的数据缺失需区分于主动限定平台。一条视频可在多个分项计入，在总量中计一次。分项覆盖率之和可以超过 100%。分母为零或不可用时，覆盖率显示为不可计算；分子真实为零且分母大于零时，覆盖率为 0%。相关网红数、互动量和互动率作为增补对比指标，需先确认频道身份与互动口径。

## 4. 子品牌报告内容

**一期建议沿用标准品牌报告的四个板块和已有指标定义。** 子品牌报告新增所属主品牌、已采用的查询版本、快照覆盖范围和截至时间等来源信息。子品牌报告沿用标准指标，覆盖率在主品牌对比中提供。用户从主品牌对比打开子报时，共享筛选模块沿用同批统计范围，固定窗口的模块按各自口径读取快照。

| 标准板块 | 一期建议必交 | 建议后续补齐的标准内容 |
|---|---|---|
| **品牌概览** | 提及视频数、观看量和对应内容明细。 | 相关网红数和互动指标需对齐频道身份及互动字段。推广占比与花费需子品牌粒度的推广关系及估价。AI 和竞品矩阵需按子品牌集合重建计算输入。 |
| **营销策略** | 在覆盖时间内提供标准发布频率、时段、语言和标签等内容分布。 | 网红画像、受众重合、商品策略依赖频道、受众、竞品和商品关系，请按子品牌集合校准。 |
| **市场动态** | 按快照截至时间计算已有内容发布、标签趋势和榜单。快照中覆盖哪段，就按哪段统计。 | 新合作达人等异动依赖长期合作历史。增量观看类指标需明确对应历史指标版本。 |
| **营销资产** | 内容明细、具有稳定身份的关联频道和内容标签。各项明细与所读快照一致。 | 频道属性、商品库需要可追溯的频道及商品关系，按已收录子品牌内容取得。 |

建议将表中的「一期建议必交」作为子品牌交付基线。表中右列是待确认的范围取舍。发布前逐项确认是否允许延后。若本版要求逐模块完整复现，右列是交付前要补齐的能力。计划延后的模块在版本范围中登记。已纳入模块若在运行时个别数据不可用，记录缺少的依据及其状态。

现有标准报告的日期随监控状态变化，普通默认近一个月，部分场景默认近十二个月。市场动态独立使用 72 小时和 30 天窗口，新达人等判断还依赖更长历史，核心 AI 分析近一年。30 天的建议值只用于新增同池对比。现有内容列表有 10,000 条分页上限，部分权限失败返回空结果。需要在服务端证明全量取数和访问成功后再发布快照，并区分失败空包和真实零条。对应静态路径见 `kol-next` 的 `pages/brand/brand-analysis.vue:147–151,287–288,347–355` 与 `KOLServer` 的 `BrandMonitorV2Service.java:3095–3119`、`BrandMonitorControllerV2.java:796–806`。现网入口及其他依赖线索见 [原讨论稿](子品牌查询与快照讨论_v0.md)。

## 5. 创建、入口与生命周期

建议从主品牌报告的子品牌管理或对比任务创建。流程为「命名与设置规则 → 预览 → 保存并生成 → 打开子报」。用户从对比进入子报，能识别它对应的主品牌和当前快照，也可以按已有访问权限直接打开子报并返回主品牌。管理权限沿用主品牌报告现有配置权限判断，本期入口从主品牌内承接。

| 状态 | 建议规则 |
|---|---|
| **首次生成中** | 保存规则后生成，进度及状态可见。首份成功结果发布后可查看。 |
| **可用** | 读取已发布的快照。成功但零命中时显示为真实零结果。 |
| **更新中** | 继续读取上一次成功快照及它所对应的规则。规则编辑或手动刷新成功后，发布本次结果。 |
| **生成失败** | 初次失败可重试。更新失败时仍可查看旧快照，记录失败的是哪次更新及规则。重试沿用原规则，修改后重新提交形成新版本。 |
| **停用** | 停用后立即从对比、明细及可访问入口移出；旧链接也验证当前状态。未归入数在下一份范围一致的批次发布后再提供。重新启用时按同一访问权限生成或校验可用快照。 |

对比批次按主品牌检查当前有效的发布请求，迟到的旧任务不能覆盖更新批次。停用、主品牌访问权限撤销时立即限制对应读取，包括旧批次和直接链接。已发布对比的下钻按对应快照读取，建议保留当前及上一成功批次用于正常查看和短期回看。超过保留范围时说明旧结果已过期，并给出可以访问的当前入口。失败、零命中、超出范围和数据依赖缺失分别记录。

## 6. 落地顺序与验收

1. **确认全量取数与可比字段。** 用真实主池验证输入、可用平台条件、全量内容身份、观看值及同批主池分母，核对分页上限、数据截至和快照可复现。现有报告列表可用于抽样对照。
2. **完成查询、快照和对比主流程。** 先交付可解释的两项对比指标、同批下钻及错误状态。先让主池和子视图能够逐条对数。
3. **按标准板块接入子报。** 用已获支持的窗口与附属字段逐项验证模块。发布前明确需要补齐哪些依赖、可接受哪些数据不可用场景。确认现有主报告的标准内容仍可用。

| 验收场景 | 预期 |
|---|---|
| 一个主池 100 条，两个子品牌分别命中 60、55 条，重叠 25 条 | 两个覆盖率为 60%、55%，主池总量为 100，未归入两组的内容为 10 条。下钻可以解释每项数字。 |
| 主标准报告已变到 200 条，子报沿用旧批次 | 新对比发布前，旧快照的 60 条继续以同批 100 条作分母。 |
| 主池未收录、池内规则未命中 | 池外视频不进入子报范围。池内视频根据同版条件解释纳入或排除。已收口样本仅用于理解差异。 |
| 平台专用条件、排除规则和单条字段缺失 | 条件只在所适用平台判断。任一排除命中后剔除。整个平台字段不可执行的状态与真实零条区分。 |
| 命中集合超过 10,000 条，或某条观看值缺失 | 完整内容集合由服务端计算。只有展示分页时标记范围不完整。缺失观看值不当作零写入覆盖率。 |
| 查询改版、连续刷新、生成失败 | 旧快照及其规则可继续读取。新批次完整成功才切换，迟到的旧任务不能覆盖同池发布结果。 |
| 成功零条、范围超出、权限返回空结果、停用 | 区分结果状态，权限变化和停用即时限制旧链接、对比和明细。 |
| 一个现有标准模块依赖子品牌缺少的字段 | 标注具体的依赖和状态。若该模块被列为发布必需项，应先补齐并按子品牌口径验收。 |
| 只有多个现有独立报告，缺少可建子视图的主品牌池 | 各独立报告继续按自身范围解释。该场景保留为后续聚合样本，本期的子品牌取数从已存在的主池执行。 |

**交付前要确认的决策。** 一是子品牌标准报告是否要求本版逐模块等价。二是 30 天默认窗口及手动刷新是否适合一期的运营任务。其余推荐做法可据数据核对再进入 Spec。

## 7. 独立 Review 记录

2026-11-23。一次只读独立 review 核对了已确认的版本范围和五项方案，提出三个需修正的问题。已在本稿按以下处理收口。

| Review 发现 | 本稿处理 |
|---|---|
| 30 天对比窗口和标准报告的历史范围混在一起。 | 分开定义对比窗口、子报快照覆盖和固定模块取数窗口。逐板块写明一期建议必交和建议后续补齐项。 |
| 选择分项、旧链接和刷新任务可能读到不同批。 | 固定主品牌发布批次并绑定下钻。新批整批发布，旧任务不能覆盖。停用和失权限时核对旧链接及明细。 |
| 只记录截至时间无法重现内容和指标，分页与缺失数据也会影响分母。 | 冻结命中集合、指标值或可复现版本，明确同池共用分母和数据完整性。补充跨平台条件、10,000 条截断、权限空包与观看缺值验收。 |

发布前仍需用真实主池核验全量读取、可复现的数据版本和观看值口径。四个标准板块的必交与延期划分是本稿的产品建议，等待范围确认。
