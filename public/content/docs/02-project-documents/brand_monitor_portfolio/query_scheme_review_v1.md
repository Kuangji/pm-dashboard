## 1. 建议

**主查询负责入池。子视图在已发布的主品牌池中筛选，并保存同批快照。** 各包含组可以选用主品牌已有的标签、社媒账号、网站、店铺或其他链接；用户也可以手填内容短语和内容标签。两种来源执行同一套池内查询。

这样能复用已维护好的品牌词和专属链接，也能覆盖原本经通用品牌信号入池的内容。比如一条视频经安克通用信号进入 Anker 池，标题另有明确的子系列名称，仍可以由子视图的标题条件选中。

## 2. Anker 表单的只读观察

## 3. 池内规则及执行约束

1. **继承主品牌**。入口确定 `parentBrandId`。后端校验主品牌访问权限，从对应的已发布批次取得完整主池成员。可选平台受主池覆盖范围限制。每次生成均绑定同一主池版本、实际数据窗口、时区及截止时间。
2. **定义子条件**。每个包含组均可从本品牌四类候选中选择主配置，或手填内容文本、内容标签。发布账号从社媒主配置选取，在对应平台按稳定账号 ID 匹配发布者。各组分别保存已选项，组内任一项命中即可。首组之外最多再添加 4 个包含组。独立排除区及组内备选项不占组数。每组内的条件均为备选，每一组都至少命中一项时纳入，各包含组间显示「并且」。组内、组间关系固定。独立排除区移除命中任一排除条件的内容。首版从按平台可验证的内容短语、完整内容标签、发布账号开始。链接或店铺需先具备可验证的内容外链、解析后标识或逐条命中凭据。事件日期、语言和发布账号地区需要独立核对字段。无法验证的字段暂不可执行。
3. **强制取交集**。执行式为 `子视图 = 主池(品牌, 批次) ∩ 平台范围 ∩ 任一条件命中 ∩ 全部附加条件满足 − 任一排除命中`。可先在主池内筛，也可以将池内候选查询结果与该批完整成员集合做交集。每次预览、生成及下钻都受品牌和批次约束。按 `platform + original_content_id` 去重。用户规则和模型结果都无法替换品牌或批次。发布前验证池外条数为零，计算不完整时保留旧快照。
4. **保存与对比**。快照记录规则版本、字段映射版本、主池批次、实际范围和命中内容 ID。引用的主配置值以审批时确认的值或稳定来源标识保存，可追溯到主配置版本。主配置的改动通过新批次生效，已经发布的规则不会静默改写。对比与内容库均读取发布的同批快照。子视图可以重叠，也允许主池内容未归入任何视图。

现有查询代码支持以 `brand_infos.pk_id` 限制归属，可结合内容层的字段过滤。直传 `videoIds` 的分支会提前返回并跳过品牌过滤，不能直接用于子视图入口。另有内容列表的前台分页上限，不能据此导出主池全量。当前代码能核对已有品牌关系和部分内容字段，本轮还无法确认历史全量快照、逐条配置命中凭据或跨平台外链匹配的供给。[新服务品牌过滤](/Users/yukuangji/Work/NoxInfluencer/pm-workspace/kol_server_v2/data.provider/src/main/java/com/nox/kol/data/provider/modules/brand/service/support/BrandVideoQuerySupport.java:60) · [旧服务内容分页](/Users/yukuangji/Work/NoxInfluencer/pm-workspace/KOLServer/ServiceInternal/src/main/java/com/nox/kol/service/brandMonitor/BrandMonitorV2Service.java:3114)

## 4. 人工确认，模型辅助

| 环节 | 一期建议 |
|---|---|
| 用户输入 | 描述当前主品牌下想追踪什么，可填业务范围和多个可验证线索。适用业务范围包括子品牌、产品线、活动和地区。线索包括别名、型号、完整内容标签、账号、专属页面或店铺，以及常见误匹配。明确地区所指的字段，例如「发布账号所在地」。 |
| 人工创建 | 从本品牌配置里选候选，也可直接补充池内条件。每个条件显示实际匹配字段。保存前查看命中分布、代表样本和命中原因。 |
| 模型建议 | 可选入口。把描述和候选表映射为结构化规则草案，标明来自主品牌配置的候选与新提议，给出入选理由。需要补证的别名、链接或账号保持待确认。 |
| 执行与发布 | 用户审阅、调整并确认条件。后台校验允许的字段、操作和平台，再用确定性规则执行预览及快照。首版避免模型逐条分类或直接生成成员 ID。 |

例如用户输入「看 Anker SOLIX 家庭储能，包含 C1000 和 F3800，以明确的 SOLIX 提及或专属入口为准」。模型可以推荐已有的专属标签、账号和店铺信号，以及标题中的系列或型号组合。单独出现 `power station` 或型号短词时先预览误匹配。即便在池外能找到清晰的 SOLIX 视频，它也无法通过本子视图进入报告。缺失内容应单独检查主品牌入池规则。

## 5. 生产前的核对

- 用同一批次构造池内正例、池内误匹配和池外正例。覆盖通用信号入池但命中子视图条件、只匹配共享网站、同一视频多条件同时命中、相同视频 ID 在不同平台、空结果与不完整读取。
- 研发确认主池完整成员的读取与版本能力、能否追溯视频级入池规则，以及各平台标签、说明、账号和外链的覆盖。外链未经验证前可先用短语、标签和发布账号跑通。
- 预览、生成和下钻使用相同批次及有效规则时，核对内容 ID 集一致并且没有池外记录。老独立报告可作为查漏的参考样本，池外命中单列。
