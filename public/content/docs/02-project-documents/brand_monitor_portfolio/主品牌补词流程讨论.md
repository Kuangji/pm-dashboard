# 主品牌补词流程讨论

独立议题，供后续评审。v7.5.4 子视图的池内查询规则见[子视图查询方案](query_scheme_review_v1.md)。

## 什么情况值得提议

以假设的新型号 Anker SOLIX C5000 为例。主配置列表里搜不到 `C5000`，只能说明当前没有这个配置值。若相关视频已经通过 SOLIX 词或专属链接进入主池，在子视图补充纳入条件即可。若用户发现库中有可明确归属 Anker 的视频，在相同平台、日期和已完成的主池批次中确实遗漏，则有理由提议调整主品牌收录规则。新品上市时也可主动提议，注明属于预防性补词，便于与已观察到的漏收区分。

## 建议流程

| 环节 | 谁做什么 | 产出 |
|---|---|---|
| 提议 | 用户说明主品牌、候选词、它指的产品或业务范围。可附代表视频、官方产品页和容易混淆的反例。使用子视图时可带入已填写的词。 | 一条可独立跟踪的建议。 |
| 定位 | 品牌维护者核对样本是否已在视频库、是否落在对应平台和批次的覆盖范围、是否已经入池。已入池但子视图漏选可直接反馈池内条件；视频尚未采集或批次未更新时，分别跟进采集或刷新。 | 明确补词能解决的问题。 |
| 试算 | 在同一视频库范围、同一数据截至时间，分别运行现行和候选主规则。查看新收录的视频、仍遗漏的代表视频，以及是否有意外移出。比较裸型号、品牌限定短语或带上下文的组合，抽查新增内容中的误收。 | 可选择的匹配方式、预计影响及样本依据。试算能力与各平台实际匹配字段待核。 |
| 决定与发布 | 建议由有主品牌配置权限的维护者决定采用、调整或退回，并告知提议人原因。采用后记录配置版本、适用平台及生效时间，生成新主池批次。 | 区分「已采纳」和「已生效」。计算失败时继续提供上一次成功的数据。 |
| 回看结果 | 提议人查看生效批次、代表视频是否入池；品牌维护者可复核误收。已有子视图按原规则在新池刷新，同批对比就绪后切换。 | 新进入主池的视频，只有命中相应子视图规则才进入分项，其余仍计入主品牌。 |

## 下轮要定的两个取舍

1. **谁维护这份主池。** 若主品牌由平台统一维护，可开放用户提议、由平台审核发布。若未来有客户专属主池，再讨论客户管理员的配置权限。先确定影响谁的报告，再决定谁能让建议生效。
2. **是否回算历史。** 从指定日期起收录后续内容，适合持续监控；回算指定历史窗口，适合补齐新品首发分析。发布时标记生效区间并保留旧快照，便于解释前后两版报告的差异。

## 自动发现与维护品牌候选词

建议按主品牌维护一份候选词表。系统负责发现、合并、补充证据和重新评估。主品牌维护者决定哪些匹配规则进入正式配置。这里的「新」指相对于指定版本主配置出现了一个值得评估的词或写法；首次观察日期记明数据覆盖窗口。

### 从哪里发现

| 来源 | 可发现的线索 | 怎么判断 |
|---|---|---|
| 已入主池的视频 | 新出现的标签、型号、系列名和写法变体 | 从已有标签聚合起步，再逐平台验证标题、说明字段。看不同视频、不同发布账号是否重复出现，以及具体上下文。新品上市时一条可核实的品牌官方发布也值得进入观察。 |
| 主池外的独立来源 | 完全未入池的新品或地区叫法 | 有条件时读取已确认的品牌官方账号发布或产品目录，也可从用户提供的漏收视频提取线索。这条输入必须能独立于现行主查询，否则无法发现零入池的新品。 |
| 用户提交的词 | 子视图里有业务意义、主配置尚未维护的型号 | 用户可以显式提议并给出例子。私人视图里的主题、备注和自定义词保持在其授权范围内。 |

现有旧服务的 `BrandVideoRelation.xml`（`selectNewTagList`）已按品牌、平台和视频归属读取标签，在限定历史窗口内统计首次与末次出现、视频数和账号数，可作为池内发现的起点。新服务的 `BrandKeywordResolveService` 做既有品牌名精确解析。以上为代码核对，生产数据覆盖、池外候选检索和独立试算能力仍待验证。

### 如何维护

每个候选保留所属主品牌、原始写法与变体、适用平台、来源、首末观察日期、代表内容、疑似反例、审核决定和关联规则版本。相同写法重复出现时更新证据；词形相近可以归为一组供人查看，执行时仍按已确认的具体字段和写法匹配。相同型号在不同品牌下分别评估。

初次出现进入「观察中」。取得归属证据及可检查的池外样本后进入「待审核」。证据不足可继续观察；驳回记录原因和当时的证据，同一批重复内容不再提报。出现新的官方证据、跨平台歧义或明显不同的用法时再复核。采纳后关联到正式规则和生效批次，持续监测新增命中及误收。季节性词和老型号可能长期低频，低频可触发复核；停用前试算会失去哪些独有内容，保留历史版本。

### 如何证明值得做

以假设的 SOLIX C5000 为例。发现型号后，在固定的视频库时间窗和主配置版本上比较「现行规则」「加入裸型号」「加入带品牌上下文的型号」。对每个方案取新增内容集合，在新增部分抽样判断归属，统计去重视频数、独立账号数及抽检正确率，展示误收例子。某个词即使在主池内高频，若试算没有带回相关池外视频，只保留观察或用于子视图。若词被采纳，后续不能把仅凭该词入池的视频再当作独立的品牌归属证据。

建议先选 Anker 和一个同名词较多的品牌做历史回放。在一个过去的日期冻结当时可见的主配置和数据，只用当时的证据发现候选，再用后续独立核实的新品或已知漏收样本评估。对照人工补词，记录提前发现天数、找回的已知漏收视频、增量抽检正确率及人工审核用时。若缺少历史配置版本，改做前瞻性的只读观察，同步记录人工发现日期。先验证有效增量和审核成本，再确定更新频率、提报门槛及是否需要模型辅助归并。
