# v7.5.4 子视图查询方案

> 非正式评审稿 · 2026-11-23 · 承接 [Input v2](input_v2.md) 与[现行评审 Spec 的 Q01、S01](spec_v0.md)。本稿把 Demo 已有的查询能力、一期建议和数据复用证据写清。实现入口沿用主品牌的「子视图管理」抽屉。

> 历史方案。本文保留前期字段评估，分组关系以[现行 Spec 的 Q02](spec_v0.md)为准，包含组内固定 OR、组间固定 AND。

## 1. 一期建议

创建路径是 **选平台 → 定义纳入与排除 → 预览 → 保存并生成快照**。主品牌由入口确定，每条规则只从该主品牌池筛选。默认先展示一组纳入条件，有需要时添加第二组或更多组，并可添加全局排除。以自然语言显示实际逻辑。

| 配置 | 建议提供 |
|---|---|
| 视图信息 | 名称必填，同主品牌内唯一。自定义视图标签选填，用于查找和识别视图。筛选内容使用查询条件里的内容标签。 |
| 指定平台 | 从主品牌覆盖的平台选择，可多选。平台是全局约束。每个已选平台至少有一组适用且可执行的纳入条件，通用组在各已选平台按各自字段映射执行。 |
| 纳入条件 | 任一组成立即纳入。组内各条件同时成立，同一条件填写多个值时任一值命中。可以从单一关键词开始，再按需要添加账号、语言或地区。 |
| 排除条件 | 任一适用的排除条件命中即移除，优先于所有纳入组。建议一期开放内容短语与内容标签排除。 |
| 当前报告筛选 | 对比日期、平台临时筛选、显示分项只影响本次查看。保存的收录平台和条件定义成员，快照记录本次生成所用的数据窗口。 |

例如，第一组配置 `(内容短语：山野 OR Trail) AND 发布账号：合作频道 A`，第二组配置 `内容标签：#trail-launch`，全局排除 `内容短语：二手转售`。第一组同时核对主题与账号，第二组按活动标签补收。发布账号地区完成核验后，也可以和主题放在同一组，用于区分特定地区的频道与其他频道。

组内 AND、组间 OR 属于同一个子视图的内容查询，依然共用一个主品牌池。嵌套布尔式、正则和脚本，以及通过其他子视图 ID 取数或跨品牌合并均留待后续。平台专属字段完整适用的组可指定平台。对不适用的平台，整组不执行，避免静默丢掉组内一项条件从而扩大结果。

## 2. 字段清单与开放门槛

| 字段 | 用户操作 | 一期取舍和数据边界 |
|---|---|---|
| 内容短语 | 填写可含多个词的短语，支持纳入、排除 | 一期核心。建议按字段精确解释命中原因，YouTube 从标题开始，Instagram 和 TikTok 从说明文字开始。已有内容库一个搜索框可能同时查标签或文本，建议拆成两种显式条件。生产须用多语言样本验证分词、短语、全半角和大小写，确定规则后冻结版本。 |
| 完整内容标签 | 输入完整标签，支持纳入、排除 | 一期核心，按平台开放。索引使用 `tags`、`keywords.keyword` 或 `keywords`。先核对实际采集落的是发布者内容标签还是关键词字段。经验证只能提供关键词时，按「内容关键词」独立标明字段含义。标签仅做完整值匹配。 |
| 平台发布账号 | 选择账号，支持纳入和同项多选 | 一期核心。展示账号名和平台，保存稳定的平台、频道 ID；已有查询支持单一精确频道 ID。多账号规则须由统一查询执行，不凭显示名称并入。 |
| 发布账号国家或地区 | 在已验证的平台选择国家或地区，支持纳入和同项多选 | 一期条件候选。现有内容库已有「频道地区」，相关查询按 `country` 筛选。须验证字段来源、覆盖率以及时间语义后按平台开启。界面明确这表示发布账号地区。受众位置、内容所谈市场和投放地区分别保留为其他需求。 |
| 语言 | 从该平台已验证的分类中选择，支持纳入和同项多选 | 一期条件候选。现有界面字段注释为「频道语言」，新服务过滤视频文档的 `language`。取得生产样本并对齐归属和字典后再决定命名与启用范围，避免将频道语言展示成内容语言。 |
| 内容形式 | 选择该平台可用的内容形式，支持纳入 | 一期条件候选。现有内容库有此筛选，新 provider 在 YouTube 与 Instagram、TikTok 使用不同底层字段。枚举需按平台逐项验收后才在规则中显示。 |
| 固定发布时间 | 指定发帖起止日期 | 候选增强，用于同一活动标签重复使用、按活动档期区分的场景。默认继续把日期用作临时查看范围。若后续开放固定日期为收录条件，需另列时间字段与时区，快照刷新沿用该绝对区间。 |
| 推广关系、提及方式、商品 | 评估使用现有关系及映射 | 留待验证主品牌归属与平台覆盖后再排期。提及方式和推广关系绑定的是此内容与指定品牌的关系，商品须验证关联的是哪个商品、以哪个平台的商品 ID 为准。 |
| 观看量、点赞、评论、互动率阈值 | 先保留既有资产筛选用法 | 数值随采集变化，若写入长期纳入规则，刷新会改变视图成员。后续只有明确要按快照数值筛选并解释成员进出时再开放。 |
| 市场、受众、品类自动识别、正文附加字段、历史受众或账号属性 | 先核验数据来源和版本能力 | 后续。产品线或主题可先由文本、标签及账号组合。商品品类等结构字段要通过关系和数据字典供给。 |

## 3. 预览、保存和可重现性

1. **先看范围。** 在预览结果标明主品牌池、已选平台、预览覆盖日期和数据截至。如果样例只取近 30 天，明确这是预览窗口。子视图报告和对比的日期仍按所用发布批次各自读取。汇报默认窗口和快照最大覆盖期由相应模块的生产数据能力确认。
2. **再看命中。** 在预览展示总命中及按平台命中数。为每个已选平台提供可查样本，显示命中的条件组和实际命中字段或值；条件排除从结果中扣除，并提供汇总提示，便于定位选错条件。平台、条件或时间改变后提示重新预览旧结果。
3. **统一查询。** 预览与生成使用相同规则版本、平台字段映射和权限。可固定预览的主池版本时沿用；取到更新数据时，明确展示生成实际日期和截止。生成时保存规则版本、主池版本、时区、平台、日期、截止及可重现的命中 ID 和指标。保存与首次发布是不同过程，首次生成成功后进入对比候选。
4. **区分异常。** 查询完整且确实无匹配时，可以保存零命中。单条缺字段时该条件视为未命中，提示缺失，保持未命中排除条件的行。如果某平台没有该字段、覆盖情况无法确认或读取失败，暂停该组的预览和发布并说明原因，提供修正规则路径。鉴权失败和取数截断独立处理，现有成功空包不能作为有效空结果。
5. **保留上次结果。** 编辑生成新版本。已有成功快照在失败时继续可读。只有全部有资格发布的同批分项和基准准备完毕后，才切换对比的发布批次。报告只消费已经发布的子视图 ID、快照版本、命中集、平台、日期和指标，不重新解释查询条件。

## 4. 可验收场景

| 场景 | 预期 |
|---|---|
| 主题与地区同时限制 | 同主题但地区不符的记录被排除；同地区不同主题的记录也不入选。增加一个指定平台的独立纳入组，其他平台结果保持原逻辑。 |
| 同一内容命中两组，或同时命中排除 | 命中多组时按平台与原始内容 ID 计一次。只要命中排除条件，该内容就移出结果。 |
| 同名账号、同名字串 | 不同平台同名账号不会串入，内容标签只匹配所选字段上的完整值。 |
| 新旧生产字段覆盖 | 平台整体缺字段可定位条件，单条缺字段可理解，零命中可保存。只读和失权场景不能生成；失权不会通过已有链接恢复访问。 |
| 固定样本版本 | 预览总数、平台合计、同批已发布分项及对应下钻数一致。真正零条、分页截断、权限拒绝和服务错误分别返回。 |
| 更新、失败和旧批次 | 查询改版后失败继续读旧规则及旧批次，迟到任务不能覆盖新版本。旧数据仍按其发布时的规则解释。 |
