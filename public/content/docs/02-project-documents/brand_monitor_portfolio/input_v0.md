# v7.5.4 主子品牌视图化查询｜评审版 Input v0

> 2026-11-23 · 非正式评审草案 · 对应 Demo v0.7。承接 [Input v2 的已确认范围](input_v2.md) 和 [一期建议方案 v1](子品牌视图一期建议方案_v1.md)。

## 要解决的问题

同一个品牌家族的内容分散在不同报告里，用户要分别查找、核对和整理。用户需要先掌握主品牌总体表现，再选择按子品牌、产品线、事业群或主题等维度建立的子视图进行比较，最后回到内容明细核对结果。

## 已确认的版本范围

| 对象 | 本期定义 |
|---|---|
| 主品牌 | 每份主品牌报告直接读取一个主品牌全量数据池。池内包括主品牌自身、各子品牌，以及属于家族的其他内容。主品牌总量由该池直接计算，子视图的创建、编辑和停用均独立于主池取数。 |
| 子视图 | 统一保存名称、可选的自定义视图标签及池内查询条件，按条件生成快照。用户可以用名称或标签标识子品牌、主题、活动等用途。同一条池内内容可以命中多个子视图。 |
| 主品牌报告 | 沿用线上标准品牌报告。子视图对比区展示当前统计范围、同批基准、各分项指标及对应下钻。 |
| 子视图管理 | 从主品牌报告全局入口打开抽屉，管理子视图和对比设置。管理者选择同主品牌下启用且有可用同批快照的对比成员，也可统一刷新。用户可在抽屉内临时调整日期、平台及显示分项。 |
| 子视图报告 | 以标准品牌报告为基础，读取对应视图的快照。优先确认哪些现有内容可以在子视图粒度计算和解释。 |

对比覆盖率共用同批主池分母。未覆盖内容按已配置的子视图命中并集去重。抽屉内的「显示分项」只影响当次阅读。

本期将跨主池聚合、主子混合聚合、同池对比另存聚合，以及随聚合引入的组合运算和二次组合保留到后续。[Input v1](input_v1.md) 记录了此前的组合视图方案。缺少主池、已有多份独立地区报告的 NIKKE 是后续聚合样本。本轮 Demo 使用虚构品牌，历史案例保留在调研材料中。[范围共识](../../03-research/2026-11-13-brand-monitor-hierarchy/brand_monitor_common_context_v1.md)

## 本轮评审问题

| 编号 | 评审问题 | 建议做法 |
|---|---|---|
| Q01 | 能否用名称和标签标识用途，并在预览中发现误收？ | 用户可为同一类子视图自由命名和添加视图标签。平台内按内容短语、内容标签和发布账号收录，同时执行排除。保存前查看命中数、样本及命中依据。 |
| S01 | 对比数字和下钻明细能否对得上？ | 同一主池按同批日期、平台和指标取数，完整生成后整体发布；旧对比继续绑定旧快照。对比窗口默认最近 30 个完整统计日并建议手动刷新。 |
| R01 | 能否在抽屉配置同池对比，并回到报告核对结果？ | 抽屉内的「配置对比」保存成员，并按选择更新分项与未覆盖内容数。「显示分项」控制当次阅读，两者均使用同批主池基准。 |
| R02 | 子报哪些板块可以交付，哪些依赖需要补齐？ | 以品牌概览、营销策略、市场动态、营销资产为基线，按快照及已具备的依赖展示。建议一期沿用标准指标，覆盖率集中在主报对比，其余内容逐项确认。 |
| L01 | 能否独立管理子视图，随时继续查看原报告？ | 多个报告标签共用一个全局入口。抽屉维护已发布与待更新版本。失败保留成功结果，停用和权限撤销即时限制访问。 |
| F01 | Demo 的反馈能否落回条文并回归？ | 按评审编号和操作路径记录差异。确认后更新对应文档和 Demo，再验证受到影响的路径。 |

## 评审样例与收口条件

用虚构主品牌「岩途 TerraPeak」及「山野系列」「居家系列」「新品体验内容」三个子视图验证。首个对比窗为 2026-10-24 至 2026-11-22，主池 100 条，默认选择的山野系列和居家系列分别命中 60 条、55 条，重叠 25 条，未覆盖 10 条。再加入新品体验内容后未覆盖 8 条，分母仍为 100。评审时核对对比配置、临时隐藏分项、视图标签和各类快照状态。

本轮需确定对比默认窗口和刷新方式、可交付的子报模块及指标、配置权限和旧结果保留规则。Demo 可验证业务路径和口径；正式文档收口前还需要验证真实主池的全量读取、可复现的指标及平台字段、标准板块的实际数据依赖，并记录未结事项。[评审版 Spec](spec_v0.md) · [评审版 Design](design_v0.md) · [评审入口](README.md)
