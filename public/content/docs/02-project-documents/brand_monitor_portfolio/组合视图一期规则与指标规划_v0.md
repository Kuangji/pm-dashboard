## 子品牌取数方式的取舍建议

2026-11-23。**建议主品牌下的子品牌只保留池内条件派生。** 主品牌总量由自己的全量池决定。子品牌按该池和保存的条件取数，因此在相同统计条件下，子品牌内容必然属于主品牌总体。子品牌条件变化只会改变分项，主品牌仍按全量池计算。

| 候选 | 主品牌与子品牌如何对数 | 取舍 |
|---|---|---|
| **池内条件派生** | 主池里的命中内容形成子品牌分项。可以比较分项、计算覆盖率并下钻到主品牌里的同一条内容。 | 推荐用于主子品牌关系。子品牌可查范围受主池覆盖限制，现有独立报告如要成为主品牌分项，需另定义池内条件。 |
| **独立子品牌直接取数** | 独立报告按自己的收录范围计算，可能有主池之外的内容。关联关系本身不改变主品牌统计范围。 | 可保留独立报告作为聚合来源。若直接用作主品牌分项，用户需要额外理解两份报告的范围差异，主品牌占比也只能按两边共同纳入的内容计算。 |

- **Anker / Solix。** Anker 下的 Solix 分项通过主池内查询取得。现有 Solix 独立报告可以保留为聚合来源，其中主池之外的内容仍按独立报告范围统计。
- **NIKKE。** 各地区报告继续作为独立来源参与聚合，由聚合视图提供所选地区的总体。这个场景可以直接使用已有地区报告。

两类数据仍可在聚合入口共用取数接口。本轮待确认的取舍是主品牌下的子品牌是否统一使用池内派生。

## 三种业务实体如何取数

沿用**主品牌、子品牌、聚合视图**三种实体。讨论「原子数据源」只用于回答同一个问题：这个实体直接取自己的数据，还是引用其他实体的数据？

| 实体 | 取数方式 |
|---|---|
| **主品牌** | 直接取主品牌全量池的数据。主品牌全量池也是家族总量的计算范围。 |
| **子品牌** | 有独立报告时可直接取自己的数据，例如现有 Anker Solix 和 NIKKE 的区域报告。从主品牌全量池按条件拆出的子品牌分项，则沿用所属主品牌池作为取数范围。 |
| **聚合视图** | 引用所选主品牌或子品牌的数据，形成指定范围的汇总。Input 中也称「组合视图」。 |

用这套实体解释两个场景：

- **Anker** 有主品牌和子品牌。线上 Anker 和 Solix 各有独立报告。若用 Anker 全量池再拆出 Solix 的子视图，这份子视图的取数范围来自主品牌池。
- **NIKKE** 的 SEA、JP 等子品牌各有独立报告，可以直接取数。选择这些报告汇总时，结果属于聚合视图。

可直接取数的来源包括主品牌的全量池，以及已有独立收录范围的子品牌。池内按条件派生的子品牌也可以被聚合视图单独选作来源，实际取数范围仍来自指定主品牌池。[线上样本与静态取数线索](../../03-research/2026-11-13-brand-monitor-hierarchy/decision/自顶向下与自底向上_竞品对应.md)

### 池内子品牌作为聚合来源的前提

2026-11-23 补充。这里「作为原子」指聚合视图可以单独引用一个子品牌的数据，按该子品牌的定义取得其内容集合。

1. **子品牌有稳定的引用和收录规则。** 保存可引用的子品牌标识、对应主品牌池和用于识别子品牌内容的条件。品牌收录条件与本次分析的日期、平台等筛选分别记录，使独立查看与聚合引用使用同一套子品牌定义。
2. **主品牌池覆盖该子品牌声明的范围。** 子品牌取数限于指定池。若池内覆盖的是部分平台或内容范围，引用时也沿用该范围。要覆盖池外内容，需要补足主品牌池或使用子品牌的独立报告数据。
3. **可在统一统计条件下取得完整命中集合。** 聚合需能按该子品牌定义取全部命中的内容身份和相关指标，支持与其他来源对齐统计条件、逐条去重和保留命中归属。只取得报告的汇总数字或当前页记录时，无法据此计算去重总量。
4. **来源变化可追溯。** 聚合视图保存子品牌引用。对子品牌收录条件的修改，需要明确聚合跟随当前定义还是引用已保存的版本。来源不可访问或无法取数时，聚合需区分范围不完整与真实零条。

例如将「Anker 数据池里符合 Solix 收录条件的内容」保存为 Solix 子视图，聚合视图可以把它作为一个来源选入。执行时仍从 Anker 池筛出 Solix 的完整命中集合。如果同一组合也收录了 Anker 主视图，Solix 可以单独列为分项，重复内容在组合总量中只计一次。

### 两种子品牌共用的取数接口

2026-11-23 · 接口建议。调用方提供**来源引用**和**本次统计条件**，得到同一种可计算的**内容集合**。接口可为聚合解析独立报告和池内子视图，能否作为主品牌分项按上方取舍讨论。

`resolve(sourceRef, scope) → { contentSetRef, effectiveScope, definitionVersion, dataCutoff, status }`

| 接口约定 | 含义 |
|---|---|
| `sourceRef` 来源引用 | 唯一指向一份取数定义。独立报告绑定现有品牌 ID，池内子视图绑定主品牌池及保存的子品牌条件。同一子品牌同时存在两种取数定义时，分别使用各自的来源引用。 |
| `scope` 本次统计条件 | 传入本次统计的时间范围、平台等条件。接口在来源定义的范围内应用这些条件。报告间对比时，调用方传入一致的统计条件。 |
| `contentSetRef` 内容集合 | 可按相同范围计算全量指标和读取明细的集合引用。两种取数方式都提供可统一识别的内容身份，如同一平台的发布内容 ID。大量数据可以通过集合引用分页读取或在服务端计算。 |
| `effectiveScope`、`definitionVersion`、`dataCutoff` | 标明实际取数范围、使用的来源定义和数据截至时间，供对数和解释结果变化。 |
| `status` 取数状态 | 区分范围内取数完成、范围部分可用和取数失败。真实零条是取数成功且集合为空。 |

| 同一业务对象的两个来源 | 接口内部怎样取得集合 |
|---|---|
| **Anker Solix 独立报告** | 按现有品牌 ID `3547978` 的收录范围查询，再应用本次统计条件。NIKKE 的独立地区报告也走这条路径。 |
| **从 Anker 池派生的 Solix 子视图** | 定位 Anker 的主品牌池，执行保存的 Solix 收录条件，再应用本次统计条件。 |

**聚合统一处理来源命中和指标计算。** 对各来源的内容集合执行选定的组合规则，保留每条内容命中的来源。同一内容的来源标签可以分别记录，观看量等内容指标按统一内容身份和统计截点取值，再计算总量、分项及占比。例如同一条 YouTube 视频命中 Solix 的两种取数定义，两个来源分项都可追到该视频。若取并集，组合总量中它只计一次，观看量也按一条内容取值。

现有两个 Solix 口径若同时存在，保存聚合时需要记录选中的具体来源，结果可按该口径追溯。按品牌名或子品牌 ID 查到多个来源时，需明确来源引用，再生成聚合结果。来源定义是跟随最新还是固定版本，仍按待确认规则处理。

**存量接口的边界。** 本地旧服务端 `KOLServer` master `706dc8ea0e` 的 `BrandVideoRelation.xml:67–83` 仍按品牌 ID 分组返回批量汇总。`BrandMonitorV2Service.java:3095–3119` 的内容列表分页上限是 10,000 条。新服务端 `kol_server_v2` master `234e9dad` 的 `BrandVideoQuerySupport.java:471–486` 也保留内容列表分页上限。统一取数需要能够在服务端处理完整内容集合，或提供能保证完整性的分段读取。这些边界来自本地静态代码，实际生产覆盖范围和完整取数通道需在实现时核实。

## 一期运算建议

**一期建议支持并集，按内容去重后看总量，同时保留每条内容命中的全部来源。** Anker 的主视图从全量池取数，子视图在池内筛选。NIKKE 的地区报告以独立取数范围参与组合，两种场景都可以用一套规则做汇总与对比。

| 运算或能力 | Anker 场景 | NIKKE 场景 | 一期建议 |
|---|---|---|---|
| **并集** | 组合 Solix 等子视图，得到选中子品牌的汇总。若同时选择 Anker 主视图和池内的 Solix 子视图，总量仍是 Anker 主视图的范围。 | 直接选择全部或部分地区报告汇总，`nikke-global` 与其他地区报告一样按各自取数范围参与组合。 | **支持。** 来源可为主视图、子视图、现有独立报告，支持同类或混合选择。组合总量对内容去重，各来源保留各自的命中关系。 |
| **交集** | 可以回答同一条内容是否同时命中两个子视图。 | 可以找到同一条内容同时被两份地区报告收录。若同一达人分别发两条视频，属于共同达人，两个内容集合可以没有交集。 | **先用于计算重叠内容数。** 开放保存交集视图前，需要明确用户想求的是内容交集还是达人交集。 |
| **排除（差集）** | 主池减去已定义的全部子视图覆盖范围，可解释「未被子视图覆盖」的内容。 | 例如 SEA 减去 JP，只表示「SEA 收录且 JP 未收录」，地区报告的覆盖范围也可能互相重叠。 | **先用于解释主视图的未覆盖内容。** 任意排除运算可等到有明确业务需求再评估。 |
| **二次组合** | 例如先保存「Anker 储能」，再把它与其他主视图放进更大的专题。 | 例如先保存「NIKKE 亚洲」，再与其他运营范围合成一份报告。 | **一期暂缓。** 只做并集且统计条件一致时，可以直接选取底层报告得到相同内容集合。二次组合的收益主要是复用一组来源，后续需明确上游改动、删除或权限变化如何传递。 |

## 并集与二次组合的详细定义

### 并集决定哪些内容进入结果

并集接收多份来源的内容集合。每个来源沿用自己的取数定义，并应用本次统计条件。只要一条内容出现在至少一个所选来源的结果中，就纳入并集。选取顺序和重复选入同一来源都不改变结果。

通过稳定的内容身份合并重复记录。同一条内容即使命中多个来源，在组合总量中仍只计一次，同时保留它命中的所有来源。计算视频数、观看量等指标时使用去重后的内容集合。各来源分项仍可各自包含这条内容。计算过程可以用同一平台和内容 ID 说明，生产去重键仍待数据核对。

例如用虚构的 NIKKE 内容 ID 演示。SEA 收录 `a、b、c`，JP 收录 `b、c、d`。两份报告取并集后有 `a、b、c、d` 共 4 条。内容 `b` 和 `c` 同时出现在两个来源分项中，在组合总量中分别只计一次。如果选择 Anker 主视图及从它派生的 Solix 子视图，同口径下并集范围等于 Anker 主视图的范围。

### 二次组合决定能引用什么来源

二次组合是指创建一个新组合视图时，**至少有一个直接来源是已保存的组合视图**。例如先将 SEA 和 JP 保存为组合视图「NIKKE 亚洲」，再引用「NIKKE 亚洲」和 KR 创建新视图。新视图保存的是「NIKKE 亚洲」这个来源的引用，执行时按适用的规则取得它所定义的内容集合。

| 操作 | 来源关系 |
|---|---|
| 直接选 SEA、JP、KR 创建一份组合视图 | 一次组合，有三个直接来源。 |
| 先保存「NIKKE 亚洲」，随后分别选取 SEA、JP、KR，或把原来的来源清单复制到新视图后加 KR | 新视图仍直接引用三份独立报告，属于一次组合。 |
| 新视图引用「NIKKE 亚洲」本身，再加 KR | 二次组合。有两个直接来源，其中一个是已保存的组合视图。 |

如果内外两层都取并集，且对各底层来源实际生效的条件一致，那么 `(SEA ∪ JP) ∪ KR` 的内容集合与 `SEA ∪ JP ∪ KR` 相同。分项粒度不同，前者的直接来源分项是「NIKKE 亚洲」和 KR，后者是 SEA、JP、KR。若「NIKKE 亚洲」还限定 YouTube，展开时需要保留对 SEA 和 JP 的平台限制。直接以同一宽口径查询三个来源，结果可能变化。

二次组合的额外价值是保留可复用的一组来源、条件和分项。若后续支持，应明确引用的是上游最新定义还是固定版本，以及来源修改、删除或不可访问时如何处理。

## 一期建议的取数规则

1. **总量先确定数据范围。** 主视图直接从主品牌全量池取数，包含未被子视图覆盖的内容。组合视图按所选来源形成自己的范围。总量按内容身份去重，组合全部子视图或全部地区报告仍得到组合视图。
2. **分项按自身来源取数。** 主视图比较所属子视图，组合视图比较所选来源。每条内容可同时计入它命中的多个分项，在当前总量中计一次。查询条件和来源应可追溯到明细。
3. **总量与分项使用同一统计条件。** 日期、平台等本次分析过滤对总量与分项同时生效，各来源继续沿用自身的品牌或查询定义。用对齐的指标字段和数据截点计算。若来源数据缺失或不可访问，组合应表明统计范围不完整；缺失数值与真实零值分开处理。
4. **比较分项时使用同一个分母。** 主视图以其全量池按当前统计条件计算的总量为分母。组合视图以所选来源组合后的去重总量为分母。每个分项覆盖率可以独立解读，分项有重叠时覆盖率加总可超过 100%。分母为 0 或缺失时，占比显示为无可计算值。
5. **来源的更新方式待确认。** 组合须保存所选来源及组合定义。后续明确来源条件修改时，已保存组合跟随最新定义还是固定在保存时的条件。内容采集更新和来源定义变动需要能够区分。

## 指标规划

2026-11-20 核对了 Anker、Anker Solix 和 NIKKE 地区报告的主要指标入口。现有报告页首有相关网红数量、提及视频数量、总曝光量、平均互动率。品牌概览另外有总互动量，内容库有总浏览量、总点赞量、总评论数。观察到 NIKKE 样本的页首有数据，概览部分核心指标显示 `--`，两处数字不能直接换用。[Anker 品牌报告](https://cn.noxinfluencer.com/brand/brand-analysis?pkId=17220&from=brand_search&word=anker) · [Anker YouTube 内容库](https://cn.noxinfluencer.com/brand/brand-analysis?tabId=assets&platform=1&pkId=17220&subTab=content) · [NIKKE SEA 品牌报告](https://cn.noxinfluencer.com/brand/brand-analysis?tabId=overview&platform=1&pkId=28895)

| 优先级 | 指标 | 比较与计算建议 |
|---|---|---|
| **一期核心** | **提及视频数、视频覆盖率** | 总体和每个分项按各自内容集合统计去重视频数。视频覆盖率 = 分项去重视频数 ÷ 当前总量去重视频数。 |
| **一期核心** | **观看量、观看量覆盖率** | 取同一统计截点下的内容观看值，按各自去重集合汇总。观看量覆盖率 = 分项观看量 ÷ 当前总量观看量。沿用现有报告观看相关数据，指标名称与「总曝光量」的衔接待对账。 |
| **一期口径核实后纳入** | **相关网红数、总互动量** | 相关网红数先按可确认的频道身份去重，跨平台同一自然人的合并需要独立映射证据。总互动量以去重内容集合重算，明确所比较平台的互动动作组成；两项先展示绝对量。 |
| **一期口径核实后纳入** | **互动率** | 按统一的互动分子和观看分母重新计算总体及分项。禁止对各分项互动率取算术平均。观看分母为 0 时记录为无可计算值。 |
| **一期解释指标** | **主视图未被子视图覆盖视频数、组合多来源命中视频数** | 前者以当前统计范围内的全部子视图定义判断，调整参与比较的分项无需重算归属。后者对命中两份或更多所选来源的唯一视频计数，每条计一次。两者用于解释总量和分项覆盖率。 |

若业务需要分项合计为 100% 的构成，可单独定义互斥分组，例如「仅命中 A」「仅命中 B」「同时命中 A 和 B」。主视图的构成还要包含「未命中子视图」。多来源归因规则、费用和商品指标留待后续规划。

## 两组演算

例子均为虚构数据，用来核对一期建议。

| 场景 | 去重总量与分项 | 怎么解释占比 |
|---|---|---|
| **Anker 主视图** | 主池 200 条。Solix 子视图 100 条，另一子视图 80 条，重叠 20 条。两份子视图合计覆盖 160 条，主视图还有 40 条未被这两份子视图覆盖。 | 两个分项的视频覆盖率是 50% 和 40%。已覆盖内容的比例为 80%。若分别选择主视图和 Solix 做组合，则其并集仍为 200 条。 |
| **NIKKE 区域组合** | 选择 SEA 75 条和 JP 50 条，其中 15 条重叠。组合总量为 110 条。 | SEA 和 JP 的视频覆盖率分别约为 68.2% 和 45.5%，相加超过 100%。15 条共同收录的视频在组合总量中各计一次。分母只覆盖所选的两个来源。 |

**待确认的一期决策。** 是否采用「仅并集、暂缓二次组合」，以及一期核心指标是否以视频与观看量为主。来源改动后组合如何更新，须在进入详细规则时明确。本稿用于业务规则和指标评审。
