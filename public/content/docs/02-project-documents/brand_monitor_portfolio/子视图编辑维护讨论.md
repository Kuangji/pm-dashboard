# v7.5.4 子视图编辑维护

2026-11-25 · 非正式评审稿。维护口径和主品牌主动检查已确认。Demo v0.18 演示检查发现影响后的通知与处理。生产触发信号与处理时效待研发核验。

## 主品牌变动处理流程

| 时机 | 系统处理 | 用户看到的结果 |
|---|---|---|
| ① 主品牌正式保存配置 | 按配置 ID 找到引用变更项的子视图，核对实际匹配值。仅改展示名称时同步文案。 | 匹配值改变或引用被移除时，在子视图原条件组保留原值和原因。主池尚未换批时提示「下批次需处理」，当前报告仍显示实际数据截至时间。 |
| ② 主池发布新批次 | 检查全部启用的子视图。引用有效的视图按已生效规则重算；有失效引用的视图保留当前结果，停用视图在重新启用时检查。 | 管理抽屉列出受影响的视图。查看者在子报告快照处可见提示；管理者可点「一键处理全部」，也可从单行进入「处理条件」。 |
| ③ 管理者一键处理 | 同一配置 ID 改值时采用当前值；配置被删除时移除该引用。即使新配置同名，也须由管理者明确选择替换。逐个视图校验整份规则，保留每个原包含组。 | 合法的视图分别提交计算。任一组将变空、规则冲突或已有未完成编辑时，整份视图留给人工处理。其他视图继续。 |
| ④ 发布或人工修复 | 发布前复核主池批次、引用、规则版本、权限、启用状态和结果完整性。成功后一次替换该视图的规则和全窗口快照；失败时保留生效规则、快照和提示。 | 按子视图数反馈结果。管理者只需打开剩余视图，在原组补选或替换条件、预览并保存。成功发布后清除对应提示。 |

子报告始终显示所读快照的实际截至时间。主报告对子视图的对比只展示同批且成员齐全的结果；无法提供完整结果时显示更新或待处理状态。只有完整计算得到的零条才可计为 0。

## 已确认的维护口径

| 动作 | 生效与读取 |
|---|---|
| 只改名称、视图标签 | 保存后，管理列表、当前报告和已配置的对比分项按同一子视图 ID 更新展示。数据快照、查询范围、对比成员资格保持原状。同时改了查询时，名称、标签和查询随本次成功发布一起生效。 |
| 已选主配置失效 | 保留在原组，显示保存时的值和具体失效原因，供用户替换或移除。尤其要保留组内唯一一项，自动删掉整组会扩大命中范围。相同稳定账号 ID 只改展示名可以更新文案；替换账号身份或改变匹配路径属于语义变化。 |
| 修改查询规则 | 沿用子视图 ID。以新规则重算本次快照覆盖的完整统计窗口。准备完成前当前发布结果继续服务；成功后整份替换。发布后只保留一个可读结果。此前打开的明细如请求被覆盖的快照，提示「结果已更新」并给出当前入口，不用新明细解释旧数字。 |
| 编辑生成失败 | 继续提供现行有效结果。仅持久维护已生效查询；任务执行期间可保留提交参数用于计算和技术重试。 |

## 两个一致性检查点

### 1. 主品牌变更时，后台主动检查影响

| 已发生的变更 | 检查范围与处理 |
|---|---|
| 主查询配置正式保存，数据池尚未换批 | 核对直接引用变更项的子视图。账号被移除、匹配路径被替换时，在原组保留条件并提示「下批次需处理」。同一账号只改显示名则更新文案。未提交草稿、品牌名称或 Logo 变更、报告临时筛选均不触发数据重算。 |
| 新主池批次发布 | 对全部启用子视图校验引用，在新主池上按已生效规则重算完整窗口；停用视图在恢复启用时追到当前批次。即使子视图没引用新加的品牌词，新入池的视频也可能命中旧规则。 |
| 新批次中存在失效引用 | 对应视图标记「需处理」，列出组和原值，原条件继续保留。其余可执行视图继续计算。独立子报仍读当前有效结果并标明截至时间；新批对比只接纳同批结果。 |

### 2. 子视图新结果生效前，核对本次计算是否仍然有效

手动编辑和后台刷新走同一个发布校验。对照计算时的主池批次、实际引用的匹配值或稳定身份和子视图规则版本，同时确认视图仍启用、操作仍获授权、结果完整。通过后一次替换当前快照。批次变化时，用户提交回到重新预览，后台任务转用最新批次；规则被其他人更新时重新载入。较早完成的任务不能覆盖新结果。只改名称或视图标签仍走普通保存及权限校验。

**打开编辑**直接读取已记录状态，在对应组展示失效项和原因。**主动预览**按目标批次执行本次表单中的条件，包括刚添加的条件；必要字段或引用不可用时原位提示。预览只对本次输入负责，不触发对所有已保存视图的重复巡检，也不改变已发布状态。

主报告标准指标可按自身发布节奏更新。对比区只读同批主池基准和所选子视图；切换期间可保留完整且仍可读取的上一套有效对比并标明截至时间，否则显示更新中或需处理。必要成员长期无效时，修复条件或将其移出对比后再切换；不可将该成员忽略后把未覆盖量当作完整结果。新结果完整发布后覆盖原结果，旧批次不作为可回看的历史版本。

触发可接入主池发布流程或由后台定期核对「主池当前批次／子视图来源批次」补偿漏触发。如上游暂时只能提供批次更新，配置变更到下批前的提前提示能力需单独核实。事件供给、补偿周期和更新时效待研发核验。

## 检查结果在哪里展示

检查结果归属到受影响的子视图。区分「需处理」和「更新中」：引用变化后等待管理者一键处理或逐项调整；规则仍有效且有刷新任务在运行时显示「更新中」。当前快照仍可读的两种情形都展示其实际数据截至时间。其他子视图沿用原有状态，仅展示名称等信息的变动直接更新相应文案。

| 用户所在位置 | 提示与操作 |
|---|---|
| 主品牌的「子视图管理」抽屉 | 在受影响的子视图行内显示「需处理」及简短原因。管理者点「处理条件」进入该视图编辑器；仅查看者可了解状态并打开有权访问的报告。 |
| 子视图报告 | 在报告标题附近的快照信息处，标明主配置的变动对更新的影响，以及当前展示结果的实际截至时间。报告沿用当前已发布快照，主品牌概览和各指标区不重复放置提醒。 |
| 子视图编辑器 | 在每个受影响条件的原组内标出原平台、账号或链接和失效原因。管理者可以调整所属组的规则，替换或移除失效项；组内唯一条件也须得到明确处理。 |

提示随已发布规则及实际检查结果维护。打开提示、取消编辑或仅完成预览后，管理列表和报告仍反映原规则的影响。修复后的规则成功发布、且没有剩余影响项时才清除提示。仅查看者看不到编辑控件。

[主配置变动示例](../../../demos/brand-monitor-portfolio-754/index.html#anker-impact)模拟 Anker 移除了「SOLIX 官号内容」第二组引用的 Instagram 账号；「SOLIX 产品内容」正常显示。v0.18 供评审已检出影响后的提示与处理流程。生产变更通知、真实更新时效和单一快照覆盖机制仍按上述维护口径推进。

## 一键处理当前主品牌的全部变动

管理者可从「子视图管理」抽屉的子视图列表顶部点击「一键处理全部」。单击后处理当前主品牌所有已启用、已有发布结果且受影响的子视图，省去逐项打开编辑器的步骤。个别视图仍可使用行内「处理条件」。

| 主配置变动 | 批量操作 |
|---|---|
| 同一配置 ID 的实际匹配值发生变化 | 采用该配置当前的值，保留所属组。 |
| 引用的配置已移除 | 删除这一引用，保留组内其余备选条件。 |
| 处理后任何原包含组将变空，或整份候选规则校验失败 | 保留该视图完整生效规则和快照，保留提示，由管理者补充或替换条件。同批次中其他可处理视图继续发布。 |

每个视图以整份规则为单位处理。已有未完成编辑的视图保留该次编辑。批量结果按子视图计数，分别告知已处理与待手动处理的数量。只读用户可查看结果并打开有权访问的报告；健康视图、已停用视图及其他主品牌的视图均保持原状。

[一键处理全部示例](../../../demos/brand-monitor-portfolio-754/index.html#anker-bulk)提供三个受影响视图和一个健康视图。首次一键处理可成功发布两份规则，剩余视图因原组缺少有效条件需手动处理。生产侧变更触发与更新时效仍待核验。

## 失败的影响和恢复

| 情况 | 可见影响 | 建议处理 |
|---|---|---|
| 提交前发现失效引用、组为空、平台缺少必要字段 | 阻止本次数据更新；原报告和对比继续可读 | 在原表单定位条件并保留本次输入。成功计算得到 0 条可照常发布。 |
| 预览后批次被替换、另一人先提交、视图被停用或权限撤销 | 本次提交过期或失去资格 | 批次变更重新预览，规则冲突重新载入，停用或撤权按当前访问状态处理。原参数直接重试无法消除冲突。 |
| 单个子视图计算中断、取数不完整或结果写入失败 | 本视图的新结果不能发布。同批对比继续引用当前结果，主品牌池与兄弟视图不被本次编辑改写 | 先在同次任务内重试可恢复的问题。收到重复提交或返回超时时先核实该次提交状态，防止重复发布。 |
| 主池统一刷新时数据不完整，或必需对比分项未就绪 | 依赖同批数据的对比暂缓整体切换；此前已发布的同批结果仍可读 | 修复数据或重跑统一任务，禁止新旧批次混算。该场景可用已生效查询重跑。 |

**一期只持久维护已生效查询。** 异步执行期间任务可以暂存这次提交的参数和批次，用于完成计算、技术重试和确认发布状态。任务最终失败后，记录原因、时间与任务状态；当前编辑框仍打开时保留用户输入，关闭后再次进入默认加载已生效查询。这个建议的代价是：关闭窗口后才收到最终失败，手选的大量配置需要重新选择。试跑时记录这类重填成本。
