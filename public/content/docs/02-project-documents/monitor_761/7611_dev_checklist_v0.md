# 7611 研发需求 Checklist：内容监控上线反馈修正

> 状态：`dev_checklist_draft`
> 上游：`7611_supplement_v0.md`
> Demo：`06_Prototypes/monitor_761_layout_demos/`
> 作用：给研发、测试、设计对齐 7611 补充需求的拆任务清单；不替代 `prd_v1.md`，仅覆盖 761 上线后的补充修正。

## 0. 核心口径

- [ ] 7611 是 761 的小版本补充，不重做内容监控 2.0 整体 IA。
- [ ] 工作台仍使用统一页面承载单项目、多项目、全部项目范围。
- [ ] 项目层字段继续以线上事实为准：只有 `创建人 / 协作者`，不新增项目负责人。
- [ ] 自动追踪新增结果走全站公用系统通知；内容监控页面内不新增通知模块、通知卡片或通知示例 UI。

## 1. URL 与页面入口

- [ ] 工作台继续支持 `projects=<projectId>` 进入单项目范围。
- [ ] 工作台继续支持 `projects=<projectId1>,<projectId2>` 进入多项目范围。
- [ ] 工作台继续支持 `projects=all` 进入全部可见项目范围。
- [ ] 工作台新增或确认支持 `tab=overview|dashboard`。
- [ ] `tab` 缺省值为 `overview`。
- [ ] `overview` 表示 `监控概览`，承载原始数据和监控内容表格。
- [ ] `dashboard` 表示 `数据看板`，承载观察区间分析、趋势、榜单、标签贡献等分析内容。
- [ ] 从项目列表处理型指标进入工作台时，URL 需要带入 `tab=overview`。
- [ ] 从系统通知进入工作台时，URL 需要带入 `tab=overview`、列表筛选参数和通知来源参数。

## 2. 项目列表顶部总览

### 2.1 指标分组

- [ ] 项目列表顶部总览分为 `当前快照` 和 `处理提醒` 两类。
- [ ] `当前快照` 用于说明当前项目集合的总体规模。
- [ ] `处理提醒` 用于说明当前项目集合中需要处理的任务。
- [ ] `当前快照` 指标不受提醒周期影响。
- [ ] `处理提醒` 指标受提醒周期影响。
- [ ] 项目列表卡片区筛选不影响顶部总览数据。

### 2.2 当前快照指标

- [ ] 当前监控内容：当前可见项目范围内有效监控任务总数。
- [ ] 当前总观看量：当前可见项目范围内监控任务的最新观看量累计值。
- [ ] 当前总 Engagement：当前可见项目范围内点赞、评论、分享等互动指标的最新累计值。
- [ ] 当前快照指标默认只展示，不做下钻跳转。
- [ ] 当前快照指标文案不得写成增量、近期变化或受时间区间影响的口径。

### 2.3 处理提醒指标

- [ ] 需关注内容：提醒周期内命中低增长、数据异常、配置缺失等需处理条件的监控任务数。
- [ ] 自动追踪新增：提醒周期内由自动追踪规则新增的监控任务数。
- [ ] 短链待处理：当前项目集合中短链未绑定或无点击数据、需要处理的监控任务数。
- [ ] 处理提醒卡片可以点击。
- [ ] 可点击卡片静态态需要展示明确的跳转意图图标。
- [ ] 非点击型卡片不展示跳转图标。

### 2.4 提醒周期

- [ ] 原项目列表顶部日期筛选改名为 `提醒周期`。
- [ ] 默认值：最近 7 天。
- [ ] 选项至少包含：最近 7 天、最近 30 天、本月、自定义。
- [ ] 提醒周期只影响处理提醒类指标。
- [ ] 提醒周期不影响当前快照指标。
- [ ] 提醒周期不影响项目卡片列表是否展示。

## 3. 项目列表卡片

- [ ] 项目卡片保留整卡点击进入单项目工作台。
- [ ] 整卡点击进入 `projects=<projectId>&tab=overview`。
- [ ] 项目卡片展示当前观看。
- [ ] 项目卡片展示当前互动率。
- [ ] 项目卡片展示需关注数量。
- [ ] 项目卡片展示自动新增数量。
- [ ] 项目卡片展示当前内容数量。
- [ ] `需关注` 为处理入口，点击进入工作台并应用对应列表筛选。
- [ ] `自动新增` 为处理入口，点击进入工作台并应用对应列表筛选。
- [ ] 项目卡片区的项目筛选只决定卡片展示，不影响顶部项目总览。
- [ ] 已归档项目需要与运行中项目有明确状态区分。

## 4. 工作台 TAB 布局

- [ ] 默认进入 `监控概览` TAB。
- [ ] `监控概览` 内展示原始数据块。
- [ ] `监控概览` 内展示监控内容表格。
- [ ] `数据看板` 作为第二 TAB。
- [ ] 切换 TAB 时保留当前 `projects` 范围。
- [ ] 切换 TAB 时保留一级筛选条件。
- [ ] 切换 TAB 时保留列表筛选条件，但列表筛选仅在 `监控概览` 中实际生效。
- [ ] 从项目列表或系统通知带入的列表筛选，需要在 `监控概览` 中可见、可清除。
- [ ] `监控概览` 不受数据看板的数据观察周期影响。

## 5. 筛选分层

- [ ] 一级筛选控制当前内容集合。
- [ ] 一级筛选影响数据看板、原始数据、监控内容表格和任务详情抽屉。
- [ ] 二级筛选只控制监控内容表格。
- [ ] 二级筛选用于快速处理任务，不改写数据看板统计口径。
- [ ] 数据观察周期只在数据看板内生效。
- [ ] 数据观察周期不影响原始数据块。
- [ ] 数据观察周期不影响监控内容表格。
- [ ] 从外部入口带入的 `listFilter` 只落在二级筛选层。
- [ ] 清除二级筛选后，表格回到仅受一级筛选影响的状态。

## 6. 自动追踪系统通知

### 6.1 通知发送

- [ ] 自动追踪规则抓取到新监控任务后，按小时汇总发送全站系统通知。
- [ ] 同一小时内无新增时不发送通知。
- [ ] 通知只发送给对对应项目有可见权限的用户。
- [ ] 多项目汇总通知不得暴露用户无权限项目名称。
- [ ] 通知内容至少包含项目范围、新增任务数、规则名或主要规则名、时间窗口。

### 6.2 通知跳转

- [ ] 点击通知主链接进入内容监控工作台。
- [ ] 跳转后进入 `tab=overview`。
- [ ] 跳转后应用自动追踪新增列表筛选。
- [ ] 跳转后保留 `source=notification` 或等价来源参数，便于埋点和上下文提示。
- [ ] 点击通知中的单条任务链接时，进入对应项目工作台并拉出单内容监控任务详情抽屉。
- [ ] 内容监控项目列表、工作台、数据看板内不新增系统通知示例卡片。

## 7. 项目归档与撤销归档

### 7.1 归档

- [ ] 运行中项目提供归档操作。
- [ ] 归档操作必须二次确认。
- [ ] 归档不删除项目。
- [ ] 归档不删除历史数据。
- [ ] 归档后项目从默认运行中列表退出。
- [ ] 归档后历史数据、内容列表和任务详情仍可查看。
- [ ] 归档后禁用添加监控入口。
- [ ] 归档后暂停自动追踪新增。
- [ ] 归档后已存在监控任务继续更新到原监控结束时间。

### 7.2 撤销归档

- [ ] 已归档项目提供撤销归档入口。
- [ ] 撤销归档后项目回到运行中状态。
- [ ] 撤销归档后项目恢复默认项目列表可见。
- [ ] 撤销归档后添加监控入口恢复。
- [ ] 撤销归档不自动启用已停用的自动追踪规则。
- [ ] 撤销归档后自动追踪是否继续执行，以该项目原有规则状态为准。

## 9. QA Checklist

- [ ] 默认打开工作台时首先看到 `监控概览`。
- [ ] 直接访问 `tab=dashboard` 时能进入数据看板。
- [ ] 项目列表当前快照指标不会因提醒周期变化而改变定义。
- [ ] 项目列表处理提醒指标会随提醒周期变化。
- [ ] 点击项目列表 `需关注内容` 后进入工作台，并只筛选监控内容表格。
- [ ] 点击项目列表 `自动追踪新增` 后进入工作台，并只筛选监控内容表格。
- [ ] 清除列表筛选后，原始数据和数据看板口径没有被改写。
- [ ] 内容监控页面内没有系统通知示例卡片或通知模块。
- [ ] 从系统通知 deep link 进入时，能打开正确项目范围和列表筛选。
- [ ] 从系统通知单条任务链接进入时，能打开单内容监控任务详情抽屉。
- [ ] 运行中项目归档前会弹出确认。
- [ ] 已归档项目可以撤销归档。
- [ ] 撤销归档后项目回到运行中列表。
- [ ] 已停用的自动追踪规则不会因为撤销归档自动启用。
