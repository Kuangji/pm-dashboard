# Dashboard Metric Planning v0 · 内容监控 761

> 状态：pre-input 子 topic，不是正式 design。  
> 目的：回答“现有内容监控指标是否足以撑起独立看板区域”，并规划项目列表速览指标。  
> 证据来源：`current_state_facts_v0.md`、`kol_brain` M04/M08、`kol-next` brandAI/videoMonitor 代码、2026-05-07 品牌分析页只读实勘。

## 1. 参考对象：品牌分析看板

品牌分析页当前能撑起复杂看板，不是因为它有很多纯数字，而是因为它把原始指标加工成多种分析形态：

- KPI 卡：总网红数、总内容数、总互动量、商品数、预估花费、战略浓度、资产沉淀率。
- 分布/矩阵：竞争合作矩阵、付费推广 vs 自然传播、平台分布、商品分类。
- Top 列表：播放量最高、内容最多、互动率最高、评论最多、标签榜。
- 趋势：内容数/观看量趋势、互动趋势、72 小时新增内容/标签趋势。
- 异动通知：付费互动率变动、自然声量探知。
- AI/策略解释：AI 战略评估、机会与风险、行业建议。

对内容监控的启发是：看板不应只堆更多数字，而应把“近期发生了什么、哪些内容贡献了变化、数据是否可信”组织成可扫读的信息结构。

## 2. 内容监控现有指标是否足够

结论：**足够撑起一个轻量但独立的项目看板区域，但不足以撑起品牌分析那种重型策略看板。**

已经在线上确认的内容监控指标包括：

- 项目级规模：内容数、观看量、点赞数、评论数、分享数。
- 质量/效率：互动率、Nox 短链点击数、CPM、CPV、CTR 等。
- 用户手动输入：预算、预计花费、预算消耗等成本类数据，默认未填写。
- 任务级明细：每条内容的观看、点赞、评论、分享、互动率、进度、预估视频价值、预算/成本输入、CPM、CPV、状态、地区、内容类型、标签、负责人、创建人、监控时长、发布日期、来源。
- 趋势：监控内容趋势，当前主要覆盖观看量、点赞数、评论数。
- 详情分析：单条内容数据总览、趋势、短链点击分布、评论情感分析、评论高频词。
- 来源：手动添加 / 自动追踪，以及自动追踪规则名可作为 761 解释字段。

当前不足：

- 缺少成熟的异常检测口径。
- 缺少稳定的评论数据覆盖。
- 缺少项目级评论洞察、风险提示和 AI 解释。
- 缺少明确的内容/频道贡献汇总口径。
- 预算/成本类数据依赖用户手动填写，默认未填写；短链、CTR 等指标也依赖额外配置，不能默认承担主解释。

因此 761 看板应采用“现有指标再组织 + 少量派生指标”的方式，而不是依赖新增大量后端指标。

## 3. 单项目 Dashboard 建议结构

### 3.1 看板定位

单项目 dashboard 默认服务最近 7 天项目状态快照。

它应回答：

- 最近 7 天项目有没有明显变化？
- 哪些内容爆发或下滑？
- 当前整体规模和互动质量如何？
- 哪些内容/频道贡献最大？
- 哪些数据为空、为 0 或需要谨慎解释？

### 3.2 建议模块

#### 模块 A：近期状态摘要

用少量主指标建立项目当前状态：

- 观看量。
- 互动率。
- 内容数。
- 新增/活跃监控内容数。

主指标默认展示观看量和互动率；内容数、新增/活跃内容数用于解释样本规模。

点赞、评论、分享作为副指标，可跟随主指标展开或在卡片内辅助展示。

#### 模块 B：内容级变化榜

这是 761 dashboard 的核心。

用现有任务级数据构造：

- 最近 7 天观看量增量 Top 内容。
- 最近 7 天观看量低增长/下滑内容。
- 互动量增量作为第二参考。
- 数据异常内容：评论/短链/互动率等为空、为 0 或明显不可解释，或预算/成本输入缺失导致成本效率指标不可解释的内容。

当前算法口径先用占位规则：

- 爆发/下滑按最近 7 天观看量增量排序。
- 互动量增量作为辅助。
- 更复杂的环比、同项目均值、频道历史均值另开子 topic。

#### 模块 C：内容贡献 / 频道贡献

默认展示内容贡献，支持切换到频道/创作者贡献。

可用现有数据构造：

- Top 内容：按观看量、互动量、评论数排序。
- Top 频道：聚合该频道在当前项目/时间范围内的观看量、内容数、互动率。
- 平台贡献：按 YouTube/TikTok/Instagram/X 等平台聚合内容数和观看量。

频道贡献不必一开始做复杂矩阵，先用排行和占比即可。

#### 模块 D：趋势

保留并强化当前“监控内容趋势”。

建议支持：

- 观看量趋势。
- 点赞数趋势。
- 评论数趋势。
- 可选：互动率趋势、短链点击趋势。

趋势图与 7 天快照联动，默认展示最近 7 天，也支持日期切片后重算。

#### 模块 E：数据可信度提示

用轻量提示解决“有图但不可解释”的问题：

- 评论数据不足 / 暂无可分析评论。
- 短链点击为 0 / 未关联短链。
- 预算/成本未填写，因此 CPM/CPV 等成本效率指标不可解释。
- 自动追踪来源内容需要展示规则名。

这类提示不应抢第一屏，但应出现在对应指标或内容旁边。

## 4. 可用现有指标构造的新指标

以下不要求新增复杂数据采集，主要是前端/接口聚合与口径定义。

| 新指标 | 构造方式 | 用途 |
| --- | --- | --- |
| 最近 7 天观看增量 | 内容/项目在最近 7 天观看量变化 | 识别爆发/下滑内容 |
| 最近 7 天互动增量 | 点赞 + 评论 + 分享等互动变化 | 作为变化识别第二参考 |
| 活跃内容数 | 最近 7 天有观看/互动增长的监控内容数 | 判断项目近期是否仍有热度 |
| 内容贡献占比 | 单条内容观看量 / 项目观看量 | 识别头部内容依赖 |
| 频道贡献占比 | 频道聚合观看量 / 项目观看量 | 识别头部频道贡献 |
| 自动追踪贡献 | 自动追踪来源内容的内容数/观看量占比 | 解释自动追踪价值 |
| 评论样本状态 | 评论数、评论分析是否为空 | 解释评论洞察可信度 |
| 短链数据状态 | 是否有关联短链、点击数是否为 0 | 解释 CTR/点击类指标 |
| 预算/成本数据状态 | 预算/预计花费是否由用户填写，CPM/CPV 是否可用 | 避免把手动输入缺失误读为采集结果 |

注意：这些是 pre-input 候选指标，正式 input 中需要区分 Must/Should/Backlog。

## 5. 项目列表速览指标规划

项目列表不应变成第二个 dashboard。它的任务是让用户快速判断“哪些项目近期值得进入”。

### 5.1 项目卡片默认速览

建议每个项目卡片保留基础信息，并增加近期快照：

- 最近 7 天观看量。
- 最近 7 天互动率。
- 近期异常内容数：爆发/下滑/数据异常合计。
- 活跃监控内容数：最近 7 天有数据变化的内容数。
- 自动追踪新增内容数。

如果空间有限，默认展示：

1. 最近 7 天观看量。
2. 最近 7 天互动率。
3. 异常内容数。

其余放 hover、展开区或二级信息。

### 5.2 项目列表顶部总览

一级页面可以提供跨项目的轻量总览，但不应抢项目列表心智。

建议总览指标：

- 进行中项目数。
- 最近 7 天总观看量。
- 最近 7 天活跃内容数。
- 需要关注的项目数。

“需要关注的项目数”可由项目内异常内容数、数据异常、自动追踪新增未处理等信号粗略构造。

### 5.3 项目列表排序/筛选

为了让速览指标真正可用，项目列表应支持按近期状态排序或筛选：

- 按最近 7 天观看量排序。
- 按最近 7 天互动率排序。
- 按异常内容数排序。
- 筛选有自动追踪新增内容的项目。
- 筛选有数据异常的项目。

这些排序/筛选比单纯展示数字更能提高一级页面效率。

## 6. 初步范围建议

### Must

- 单项目 dashboard 从纯数字 + 单趋势图升级为“最近 7 天快照看板”。
- 增加内容级变化榜：观看量增量 Top/低增长或下滑内容。
- 项目列表卡片增加最近 7 天观看量、互动率、异常内容数。

### Should

- 频道/创作者贡献切换。
- 自动追踪贡献/新增内容提示。
- 项目列表顶部跨项目轻量总览。
- 项目列表按近期状态排序。

### Backlog

- 完整异常检测算法。
- 项目级 AI 总结。
- 项目级评论舆情汇总。
- 复杂矩阵类图表。
- 独立报告式 dashboard。

## 7. 进入 input 前还需确认

- “异常内容数”的第一版口径是否先按爆发/下滑/数据异常三类粗分。
- 项目列表卡片能承载多少个速览指标，不影响列表扫描。
- 最近 7 天指标是否需要和用户自定义日期记忆联动，还是项目列表永远固定 7 天。
- 自动追踪新增内容数是否已有稳定字段，还是需要由来源 + 创建时间聚合。
- 项目列表顶部总览是否会削弱“项目列表 -> 项目详情”的主层级。
