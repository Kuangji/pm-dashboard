# 7611 补充文档：内容监控 2.0 上线反馈修正

> 状态：`supplement_draft`
> 上游：761 上线后用户反馈与 Demo 复盘
> 作用：作为 761 的单补充文档，不另起版本目录；涉及 Demo 的改动直接回写 `06_Prototypes/monitor_761_layout_demos/`。

## 1. 背景

761 上线后，用户反馈集中在四类问题：

- 项目列表顶部指标语义混乱：当前只强调“增量”，且增量受“可见项目时间范围”影响，导致一个时间筛选同时控制项目可见范围和数据定义。
- 老用户仍高频使用“原始数据 + 监控任务表格”，上下长页面让数据看板占据默认路径，影响既有习惯。
- 从项目列表数据项进入工作台时，尤其是“需关注内容”，用户期望直接看到对应内容集合，而不是只进入一个未带条件的聚合页。
- 归档后需要可逆操作；自动追踪新增结果需要通过系统通知提醒用户。

7611 的定位是小版本修正，不重新定义内容监控 2.0 的整体 IA。

## 2. Scope

### Must

- 项目列表顶部 `项目总览` 改为当前筛选项目集合的当前值聚合，不再提供日期选择，不再展示增量数据。
- 项目列表顶部筛选项收敛为 `项目创建人` 和 `项目状态`，并同时影响项目总览数据和项目列表。
- 工作台改为 TAB 布局：
  - `监控概览`：默认 TAB，承载原始数据和监控内容表格。
  - `数据看板`：第二 TAB，承载观察区间分析、趋势、榜单、标签贡献等分析内容。
- 项目列表处理型数据项点击后进入工作台，并自动带入列表筛选上下文。
- 项目归档支持撤销归档。
- 自动追踪结果通过全站公用系统通知每小时汇总；7611 不在内容监控页面内新增通知 UI，只定义通知触达和跳转承接需求。

### Non-goals

- 不改 760/761 已确认的新建监控流程。
- 不扩展评论抓取能力。
- 不新增报告型导出或 PDF 报告。
- 不引入项目负责人字段；项目层仍以创建人、协作者为事实字段。

## 3. 项目列表指标口径

### 3.1 顶部总览

项目列表顶部 `项目总览` 是项目列表的聚合摘要，不再是独立速览。它只回答“当前筛选结果下，这批项目现在是什么状态”。

| 指标 | 口径 | 7 天对比 | 点击行为 |
| --- | --- | --- | --- |
| 项目数 | 当前筛选结果下的项目数量 | 不展示 | 只展示 |
| 观看量 | 当前筛选结果下所有项目的最新观看量累计值 | 展示 | 只展示 |
| 互动量 | 当前筛选结果下所有项目的最新互动量累计值 | 展示 | 只展示 |
| 活跃监控数 | 当前筛选结果下仍在有效监控中的任务数 | 展示 | 只展示 |
| 需关注内容 | 当前筛选结果下需处理的监控任务数 | 不展示 | 进入工作台 `监控概览` 并应用列表筛选 |
| 自动追踪新增 | 当前筛选结果下自动追踪新增的任务数 | 不展示 | 进入工作台 `监控概览` 并应用列表筛选 |

所有数据均为当前值；`观看量`、`互动量`、`活跃监控数` 额外展示 7 天对比，但不把主值定义为 7 天增量。

### 3.2 筛选项

项目总览区提供两个筛选项：

- `项目创建人`：全部、Yuki Chen、Kuangji、Sophia、Alex 等。
- `项目状态`：全部、进行中、已归档。

筛选项同时影响：

- 项目总览聚合数据。
- 下方项目列表卡片。

因此项目总览必须对当前项目列表内容负责；不再保留只影响总览、不影响列表的独立筛选。

### 3.3 项目卡片

项目卡片指标改为：

- 当前观看。
- 当前互动率。
- 需关注。
- 自动新增。
- 当前内容。

其中“需关注”“自动新增”为可点击处理入口。点击后：

- 进入 `option-a-project-workbench.html?projects=<projectId>&tab=overview`。
- 附带 `listFilter=<filter>`。
- 工作台顶部显示“已从项目列表进入”的上下文提示。
- 仅影响监控内容列表，不改变原始数据和数据看板口径。

## 4. 工作台 TAB 布局

### 4.1 TAB 定义

工作台 URL 支持 `tab=overview|dashboard`。

- 缺省值：`overview`。
- `overview`：监控概览，包含原始数据和监控内容表格，作为老用户默认路径。
- `dashboard`：数据看板，包含观察区间分析和标签贡献等解释型可视化。

### 4.2 筛选关系

- 一级筛选继续控制当前内容集合。
- 列表内处理筛选只控制 `监控概览` 中的监控内容表格。
- 数据观察周期只在 `数据看板` 内生效，不影响监控内容表格。
- 从项目列表或系统通知带入的筛选，统一落在列表内处理筛选层。

## 5. 系统通知

### 5.1 自动追踪新增汇总通知

自动追踪规则抓取到新监控任务后，系统通知每小时汇总一次，避免高频打扰。

该能力走全站公用系统通知功能，不在内容监控项目列表、工作台或数据看板内新增独立通知模块；7611 Demo 不体现系统通知 UI，只保留被通知点击后的页面承接逻辑。

通知内容至少包含：

- 项目范围。
- 新增任务数。
- 规则名列表或主要规则名。
- 时间窗口。

点击通知主链接：

- 跳转到工作台 `tab=overview`。
- 自动应用 `listFilter=auto-track`。
- 保留通知来源参数 `source=notification`。

点击单条任务链接：

- 跳转到对应项目工作台。
- 打开单内容监控任务详情抽屉。

### 5.2 权限与频控

- 仅向对项目可见的用户发送。
- 如果同一小时无新增，不发送通知。
- 多项目汇总通知需要优先展示用户可见项目范围，不暴露无权限项目名称。

## 6. 项目归档与撤销归档

### 6.1 归档

归档仍需二次确认。

归档后：

- 项目从默认运行中列表退出。
- 历史数据、内容列表和任务详情仍可查看。
- 添加监控和自动追踪新增暂停。
- 已存在监控任务继续更新到原监控结束时间。

### 6.2 撤销归档

已归档项目展示“撤销归档”入口。

撤销后：

- 项目回到运行中状态。
- 恢复默认项目列表可见。
- 添加监控入口恢复。
- 自动追踪新增是否恢复执行，需要沿用该项目原有规则状态；如果规则已停用，不因撤销归档自动启用规则。

## 7. Demo 对应改动

Demo 路径：`06_Prototypes/monitor_761_layout_demos/`

已体现：

- 项目列表顶部改为“项目总览”，全部主值按当前值定义，不再做日期选择或增量主值展示。
- `项目创建人 / 项目状态` 筛选同时影响项目总览和项目列表。
- 处理型指标点击进入工作台并带入列表筛选。
- 工作台改为 `监控概览 / 数据看板` TAB。
- 默认进入 `监控概览`。
- 已归档项目支持撤销归档。

未在 Demo 页面内体现：

- 自动追踪系统通知入口。该入口属于全站公用系统通知能力，内容监控页面只负责接收通知点击后的 deep link 和任务详情抽屉承接。

## 8. 验收点

- 默认打开工作台时首先看到 `监控概览`，老用户能直接看到原始数据和监控内容表格。
- 切换到 `数据看板` 后，观察区间分析仍可正常使用。
- 项目列表顶部不再出现日期选择器、提醒周期或平台范围筛选。
- 项目总览数据随 `项目创建人 / 项目状态` 筛选变化，并与下方项目列表保持一致。
- 点击项目列表“需关注内容”进入工作台后，只应用列表筛选，不改变数据看板或原始数据。
- 从全站系统通知点击进入工作台后，只筛选自动追踪新增内容；该通知入口本身不在内容监控页面中呈现。
- 已归档项目可撤销归档；撤销后项目回到运行中表现。
