# Discussion Questions · 内容监控二期（v7.6.1）

> 状态：pre-input 讨论问题清单。

## 1. 版本目标

- 761 的首要目标是“重构体验”，还是“补齐复盘能力”？
- 761 需要对外包装成内容监控 2.0 二期，还是内部体验优化版本？
- 本期成功的判断标准是什么：使用率、创建效率、复盘效率、客户满意度，还是售卖价值？

## 2. 用户与场景

- 主要用户是投放运营、PM、客户成功，还是客户本人？
- 用户查看内容监控的最高频动作是什么？
- 用户是更多从项目详情页进入复盘，还是从全局监控列表进入排查？
- 用户在项目详情里最关注的是项目整体表现、异常内容、创作者贡献，还是单条内容详情？
- 用户抱怨“报告不够详细”时，缺的是数据、解释、图表、导出格式，还是自动结论？

## 3. 评论能力

- “更多评论抓取”具体指什么？
- 当前详情抽屉已有评论情感分析和评论高频词展示位，但线上样本为空态；用户反馈是因为没抓到评论、抓得太少、分析太粗，还是不知道为什么没有数据？
- 哪个平台评论最优先？
- 是抓热门评论、最新评论、全部评论，还是按互动/情感筛选？
- 评论是否需要支持手动刷新？
- 评论空态是否需要解释抓取范围、更新时间、失败原因或套餐限制？
- 评论分析是否需要 AI 总结？

## 4. Dashboard

- dashboard 服务项目复盘还是实时监控？
- 默认指标应该控制在多少个？
- 线上已有观看量、点赞数、评论数、分享数、互动率、Nox 短链点击数、预算消耗、CPM、CTR；哪些是默认主指标，哪些只作为补充指标？
- 当前部分成本/点击类指标经常为 0 时，dashboard 是否仍应默认展示？
- 是否需要平台维度、来源维度、规则维度的分布图？
- 成本和回报类指标是否可以作为默认主指标？

## 5. 列表与详情

- 全局监控列表和项目详情列表是否都要重构？
- 原“总监控列表”是否应从项目列表平级 Tab 降级为“跨项目监控内容视图”？
- 跨项目视图是否允许默认全部项目进入，并同时支持项目多选后带筛选进入？
- 跨项目视图应以二级页面、抽屉，还是项目列表工具区入口呈现？
- 跨项目视图的内容模型是否应贴近单项目详情的内容列表，而不是保留一套独立总表心智？
- 任务详情抽屉是否需要变成独立详情页？
- 线上全局列表已有来源列和监控进度；来源、进度、状态、异常是否需要在项目详情列表中同样显性化？
- 项目详情的卡片视图与全局表格视图，应该统一字段口径，还是分别服务浏览和排查？
- 评论洞察应该出现在列表行、详情抽屉、dashboard，还是报告里？
- 自动追踪规则来源是否需要在每条任务上显性展示？

## 6. 自动追踪与来源解释

- 线上文案显示自动追踪仅生效 7 天；这个规则对用户是否足够清楚？
- 自动追踪失效后，用户应该重新添加规则、续期规则，还是系统提示一键继续追踪？
- 自动追踪规则贡献是否需要在 dashboard、列表、详情和报告里分别解释？
- 自动追踪生成的内容是否需要未读/新发现提示？
- 自动追踪规则与已生成任务之间的关系，需要展示到什么程度？

## 7. 短链、配额与关联计划

- 新建监控抽屉底部已有“关联自动营销计划、剩余配额、本次消耗”；这些信息在创建前是否足够可理解？
- Nox 短链点击数、点击数据分布、CTR 应该进入 dashboard 主指标，还是只在详情/报告中展示？
- 短链为空或无点击数据时，需要怎样解释？
- 配额不足、预计消耗变化、自动追踪持续消耗是否需要在本次讨论中进入范围？

## 8. 报告

- 报告主要给内部复盘还是客户汇报？
