## 1. 阅读口径

- **已确认**：动作主体与基本范围有现行依据；不等于接口、迁移和异常状态已经实现或验收。
- **部分确认**：已有不变量，但字段、目标对象或角色边界仍需确认，不能整行动作视为全开。
- **待确认**：只列问题和建议，不把 Demo 默认值当作产品默认值，也不将文档没有授权解读成已经批准。
- **不提供**：本期明确不建设，或该身份本身不提供该项权力；同一人具备其他有效身份时仍按该独立来源判断。

组织所有者、Admin、组长、组员不是互斥的四种登录身份。同一个 Admin 同时为某组组长时合并其合法能力；“Admin 不获得业务明细”不妨碍其凭本组成员身份读取正式支付单，或凭对象协作权限参与业务。

基础边界统一适用：组织及成员有效资格、目标组状态、对象稳定组归属、套餐权益和具体动作约束。组织管理可操作组织内目标组，不要求管理者加入该组；参与组内业务则必须满足该组有效关系及模块授权。归档、到期冻结和 REMOVING 的例外沿原生命周期规则，不因本矩阵自动恢复权限。

## 4. 逐项讨论顺序与建议

以下全部是建议，确认前不写成正式权限。前四项先收口查看范围，后两项再补全局策略和审计，避免边界互相打架。

### D01 资金汇总可见范围（第一条，待确认）

建议按身份明确，**先不新加一个控制资金汇总可见性的策略开关**：

| 身份 | 建议允许 | 建议不因该身份开放 |
|---|---|---|
| 组织所有者/Admin | 组织及各组的余额、占用、已付等已定义资金汇总，供分配/归还和资金管理 | 跨组支付单正文、草稿、收款账户/银行信息、回执 |
| 有效组长 | 自己管理组的资金汇总；多组逐组判断 | 组织钱包总额/全组织资金结构、其他组资金；不自动获得草稿或支付执行权 |
| 普通组员 | 本人该组的支付上限、承担用量和个人有效可用信息 | 完整组资金汇总及同事个人上限/剩余，组织余额；单笔单据仍按已定模块权限读取 |

两个限定一并确认：默认组组长可看“本组当前共享可用”，但不因此看组织总额和其他专用组；普通成员不看资金汇总，不影响原有合法填写/提交及资金不足提示，其父级数字披露按后续字段规则处理。

**本条只决定汇总，不决定流水、单笔金额是否敏感或回执访问。** 组织管理视角的普通业务/资源汇总不因此被收紧。

### D02 资金流水和业务明细分离（待确认）

建议组织所有者/Admin看组织资金总账及分组账，组长看管理组资金流水，普通成员不开放组流水。流水按账务需要记录类型、时间、组、金额、余额及关联标识；是否显示操作人等字段在评审列清。收款银行/账户和业务附件不因能看流水而开放。

关联支付单的链接仍过单据自身权限；无权可看账务引用，但不能进入正文、拿附件或从导出获得正文。精确字段按D03收口，不新增独立财务角色或跨组业务只读授权。

### D03 支付单基础/敏感字段及审核所需信息（待确认）

正式单同组读取、草稿隔离及敏感信息开关不重开；建议逐字段确认，不再讨论笼统“可看支付明细”：

| 字段组 | 需要确认什么 |
|---|---|
| 单号、状态、组、负责人、频道、时间 | 是否作为正式单同组固定可读的基础字段；不能包含原草稿内容 |
| 单笔金额、币种、手续费 | 哪些基础可读、哪些脱敏；不能用“财务数据”四个字含糊带过，也不能直接照Demo定案 |
| 收款人身份、银行/账户、联系方式及付款附件 | 敏感字段枚举、脱敏程度；不能用组织共享收款模板把来源单权限打通 |
| 回执 | 已确认固定只读者受敏感信息开关；列表、详情、下载链接和导出须一致 |
| 有效协作者/负责人、待审核组长 | 完成填写/执行/审核所需的最小字段；审核资格与隐式协作开关独立，不能出现有审核权但无法完成合法审核的死路 |

建议先把单笔金额/币种列为正式单基础信息，银行账户等和回执列为敏感信息；手续费、收款人身份及附件细项逐项定。此建议未确认，不扩为草稿向全组可见。

### D04 普通成员看组配额到哪一层（待确认）

建议保留本人逐Scope的配置、用量、实际可用和周期；不能把其他账号个人额度明细当成本人的“共享约束”。现有团队/组额度可见性策略作用域建议收为**普通配额的本组汇总**：

| 展示对象 | 建议关闭时 | 建议开启时 |
|---|---|---|
| 本人本组各Scope上限/已用/实际可用、周期 | 可见；可说明受组约束，但不泄露完整父级账 | 仍可见 |
| 本组普通配额上限、已用、实际剩余、周期 | 隐藏组汇总数字 | 显示本组汇总，不开放全组织余额/用量 |
| 同事逐人的上限、已用、剩余及排行 | 不因该开关开放 | 仍不因该开关开放；组长/组织管理视角另按已定资格 |
| 支付组资金与支付个人额度 | 不由此开关控制 | 仍按D01及支付规则，不混入普通Scope |

建议开关仍为组织级统一设置，不新增组级覆盖，产品默认关闭；组织管理者/有效组长的既定管理读取不被该展示开关撤销。**这是待确认建议，不是从Demo默认值得出的既有结论。** 共享默认组也只露本组普通配额汇总，不因此开放全组织资源结构；组织共享资格/固定容量的必要说明按Scope事实处理。

### D05 Admin能修改哪些全局策略（待确认）

两项Admin移除/归档敏感开关仅组织所有者可改已定，不重新讨论。其余逐开关确认，不能一句“Admin能改组织设置”全部带过。

| 全局开关 | 组织所有者 | Admin待决定部分 |
|---|---|---|
| 组长默认协作 | 可，默认关闭已定 | 是否允许Admin开启/关闭，此动作会改变全组织对象授权来源 |
| 组长配置成员配额委派 | 可 | 是否允许Admin改；并补产品默认值，解决梳理/S10歧义 |
| 正式单同组只读敏感信息 | 可，默认关闭已定 | 是否允许Admin改，这是敏感字段披露而非支付执行权 |
| 普通成员本组配额汇总可见性 | 组织策略配置 | 先确认D04字段、默认和范围，再确认Admin修改权 |

组策略三项明确Owner/Admin可改，不借D05重新收回已定权限。此次只列待决，不预先统一成Owner-only或Admin全开。

### D06 最小审计记录由谁看（待确认）

建议按事件域：组织所有者/Admin看组织治理、组配置、配额和资金配置的必要审计；组长看本组业务交接/配额等管理事件；普通成员只看与自己有关的结果通知和必要记录。审计内容不包含无权业务正文或收款敏感原文，事件引用不授对象访问。

查询/导出若本期需要则沿同一范围；不新增全站审计平台、复杂检索和独立审计角色。保存时长、具体通知和字段留Spec/研发评审，不在本矩阵填未经确认的年限。

## 6. 跨页面和验收约束

- 同一读取范围须同时落实于组织资金、支付详情、Dashboard、成员与配额、检索/通知预览、导出和下载接口；前端隐藏不是鉴权。
- 资金配置、普通配额配置、业务统计、资金汇总、账务流水、单据正文是不同动作域，不能把一项允许扩成其他项允许。
- 有汇总权限不代表所有组成明细可钻取；有单据读权不代表可见组余额或其他账号剩余。有执行权不一定要拿到完整资金总账。
- 状态变化实时撤销对应资格；归档历史只按原权限可读，冻结历史读取也不扩大原授权，普通组员不能因看历史成为业务管理员。
- 对外文案用“组织所有者、Admin、组长、组员、对象负责人/协作者”；代码中的T2/T3仅映射，不恢复旧T1天然协作。
- 每条确认记录“编号、角色、数据/动作、范围、条件/默认值、允许与拒绝示例”；确认后再同步Input、梳理、相关故事和Demo，不新增未经讨论的开关或权限包。
