## 2. 必须保留的优势

1. 组织/组/个人统计资格分开，Admin 兼组长合并可用能力，不要求切身份；统计汇总不授正文或业务写权限。
2. 业务整体结果、实际 actor 工作量、合法组长项目统计分离；普通成员选项目只筛本人动作，不复制项目总量。
3. 邮件四位七值、四线趋势与独立对话指标；不恢复重复漏斗，不强造跨模块转化链。
4. 日期状态跨视角/模块保留；期间量与当前值分开，未知/零/延迟/异常分开，同范围导出。
5. 原模块业务和扣量不为新看板统一改写；组织/组/个人配额配置职责与支付资金仍独立。

## 3. 发现与修订建议

### R01 / P1：看板去配置会丢失目标组

定位：Demo `app.js:329`。

实测 Owner 在资源页选品牌组，顶部业务组仍为增长组，点击“前往组配额设置”后进入增长组的“成员与身份”，而非品牌组的组配额。原因是普通 `goto('groups')` 未传统计目标组和 Tab。Admin 兼多组组长在组维度看非顶部当前组时，个人额度入口直接消失。

建议：组织侧跳转携带目标组及 `quota` Tab；全组织汇总先明确选择目标组，不静默使用业务当前组。组长个人配置需再验有效组长及委派资格；目标不同则显式确认切业务组后到“本组管理 → 成员与配额”，不能静默切组或用组织身份代替组长权。

验收：分别在业务组A、统计组B、历史管理目标C的组合中验证跳转B、Tab准确、取消不切组、越权不能配，返回保留看板范围。

### R02 / P1：多人工作量被标成“本人”

定位：`usage-model.js:318–322`。

组织/组选择“实际操作量汇总”可统计多人，但跨模块总览固定写“本人有效发出消息”“本人新增 CRM”“本人手建项目”等。内存与浏览器均复现，数字并非当前操作者本人。

建议：按目标动态使用“本范围 / 所选成员 / 本人”；卡片、表头、口径说明和导出一致。不改变 actor 聚合，也不改回负责人归因。

### R03 / P2：资源已列全，但没有完成类型化表达

定位：`resource-model.js:9–17`；`app.js:319、325、338`。

当前模式统一显示“已用 / 配额上限”。既定口径中，资格参数、当前容量/席位、期间消费和日/月双限制并非同一种度量，差异主要藏在长说明里。catalog 尚未带可供界面统一消费的资源类型/单位/周期元信息。

建议：按已确认类型表达“当前资格”“当前占用 / 容量”“当期已用 / 上限”“今日 / 本月限制”等；准确显示单位、真实发放窗口、是否可分配。证据不足继续待核，不根据名称或虚构值给资源补扣量规则，不统一计算消耗百分比或剩余。7502/7503不相加，席位含待接受邀请且不下分，继承不冒充无限制。

这属于展示及交付契约未分型，不是认定线上真实扣量错误。完整可分配矩阵仍须逐Scope核对，不能用23项展示清单替代。

### R04 / P2：筛选控件的作用域不够清楚

定位：`app.js:186、194、198–202、219–222、243–246、318–325`。

- 当前/累计资源不随任意日期重算，这是正确规则，但页面仍保留可编辑的“统计日期范围”，会承诺一个实际上不生效的筛选。
- 整体/操作量模式会改变上方跨模块总览，控制却放在该总览下方的模块区；组长项目统计又仅作用局部，三个选项不在同一作用域。

建议：全页范围和全页统计口径集中在总览上方；项目整体/本人动作项目筛选留模块内并清楚标注范围。当前/累计时就地显示实际窗口，禁用或明确标记日期不参与该窗口；期间发生量启用同一份日期状态。保留三视角及兼任资格，不新增身份切换。

### R05 / P2：信息密度没有转化成定位效率

定位：`app.js:214–217、265–273、319–329`；`styles.css:43–49`。

资源页先等权展示23块，再展示22列矩阵，没有资源检索或轻量类别定位。手机主内容约3129px，矩阵宽约2850px，冻结账号列后一次仅能看很少的资源列。业务页分组及成员工作量也位于趋势、对话和多个说明区之后，Owner主内容约3362px。没有页面横溢出不代表比较任务已经高效。

建议：保留全量/原名原序核对模式，增加轻量资源检索或分类定位；手机可选单资源纵向对照组/成员。核心指标之后优先承接分组/成员摘要，趋势和完整口径可渐进展开。只对证据充分的有限额度表现耗尽/可用状态，不凭空定义80%告警阈值；成员规模增长需补搜索/分页方案，不要求审阅Demo造完整异步服务。

### R06 / P2：图表与关键辅助信息未达到可读性门槛

定位：`app.js:346`；`styles.css` 的 chart、usage、resource 字号及颜色定义。

10月日趋势同时强制显示末端10/29与10/31。1440实测文字边界相交约9.6px，手机更紧；现有“不横溢出”检查不会发现SVG文字相互遮挡。关键日期、限额和口径还大量采用10–11px及低对比次级色；`#7d849b`与`#f7f8fa`对比约3.50:1，不宜承载普通小字必读信息。

建议：按可用像素生成刻度，保留首尾并剔除冲突刻度，移动端减少刻度但不删数据；提供可用的统一日期点读数及表格替代，不只靠悬停微小圆点。关键状态、单位、上限和必读口径用规范的正文次级色及可读字号，弱色仅留非必要元数据，不另换视觉体系。

### R07 / P2：数据新鲜度和重试状态示意不准确

定位：`app.js:106、205、1030`。

刷新只更新本地读取时间，但主文案用新读取时间替换来源 `asOf` 并称“更新时间”；切延迟状态仍显示新读取时间。新时间为UTC `Z`，原来源为北京时间，展示也未统一。刷新还与可导出条件绑定，来源异常时刷新和导出一起禁用。

建议：明确区分“数据截至/来源更新时间”和“本次读取时间”，统一时区；来源异常允许重试但禁止导出，真实无权限则不重试越权。无需为审阅Demo实现真实刷新任务，但成功、延迟、错误示意不能暗示旧数据已更新。

## 7. 用户批准的修订与实施记录

用户确认按上述顺序修一轮，保留现有优势和已确认权限边界，原邮件抽屉继续保留。当前Input§6.2/§6.6/§6.7、梳理及S31–S33同步以下要求，不新增产品决策卡：

- 正确性：配置跳转绑定统计目标组和组配额Tab；个人配置先验有效组长/委派，非当前组明确确认后切组，取消不切。统计主体按本人/所选成员/本范围命名。来源时间和读取时间分开北京时间表达，异常可重试禁导出，无权不重试越权。

- 视觉与定位：23项/22列全量原名原序保留，增加检索/分类及手机单资源纵向对照。核心指标后优先分组/成员摘要，趋势与完整口径渐进展开；避刻度重叠，保留日期点读数和表格替代，提高关键单位/上限/状态可读性。
- 原能力边界：原邮件抽屉承接旧账号→任务八项/原分页及导出；Dashboard保留11项和合法组长项目统计，不声明全身份完整替代，不给Admin新增项目权限，也不改变个人actor或旧模块业务核算。
