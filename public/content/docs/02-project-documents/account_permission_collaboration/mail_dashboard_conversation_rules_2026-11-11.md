# Dashboard 邮件趋势、漏斗与对话沟通｜已确认规则

> 更新：2026-11-11。承接 [当前 Input §6.7、§6.9](./phase2_input_v0.md) 及 [S31–S33](./use_case_stories_v0.md#S31)。这是新增 Dashboard 表达与指标，不改原邮件、消息业务或配额核算，也不将本地示意写成真实服务已交付。
> 原团队邮件数据抽屉仍只收窄当前业务组账号候选；原 11 项、账号/任务八项和旧导出契约保持，已核事实见 [邮件看板证据](./email_dashboard_evidence_2026-11-11.md)。
> 最新范围覆盖：本稿邮件11项/漏斗/对话效果适用于合法整体统计；个人和管理者选单人改看实际动作，Admin不凭组织身份看项目整体，详见 [实际动作规则](./dashboard_actor_workload_rules_2026-11-11.md)。旧个人项目整体目标不再生效，原线上事实不因此改写。

## 1. 邮件四线趋势与同范围漏斗

- 趋势展示发送、送达、已读、回复四项；“已读”沿用原 `openCount`（原界面“打开数”），不新增另一种状态或计量规则。
- 四条线按原邮件发送日期归集，观察这些邮件截至本次更新时间的送达/已读/回复效果。不是把打开或回复发生日期改成横轴，也不把沟通消息时间混入四线。
- 漏斗使用同一授权范围、日期、项目/账号筛选的四项原始总值；与对应邮件总览、趋势共享数据范围，不另建一套转化计算。
- 四项不承诺逐层严格嵌套。回复可能没有被追踪到打开，回复数可以高于已读数；应保留原值并提示追踪/统计差异，不能裁数、补数或排序数值强行画成递减漏斗，也不能强制相邻阶段比例不超过100%。
- 原送达率、打开率、回复率均按原规则除发送数，不因漏斗新增而改成相邻阶段转化率。零、未知、延迟与来源异常继续区分；形状和样例不证明真实来源可算。

## 2. Dashboard 单列“对话沟通”

| 新指标 | 已确认含义 | 不应计入 |
| --- | --- | --- |
| 新增沟通对话 | 精确对话在所选期间首次收到红人有效回复，由建联进入沟通；每个精确对话去重一次 | 期间内第一条可见消息不一定是全历史首次回复；老沟通对话再次回复不算新增 |
| 期间活跃对话 | 已进入沟通，且所选期间有有效收/发消息的精确对话；老对话也计入，从首次有效回复本身起计算活动 | 未回复的单向邀约、仅首次回复前的发送活动，不因有发信就算沟通活跃 |

两个指标使用消息事件时间，不沿邮件四线的发送日期队列；选择同一日期范围时，两者回答的问题不同，应在界面和导出分别说明。

这里的“活跃”只指精确沟通对话，不是泛活跃成员、登录人数或实际操作者绩效；后几类仍按原候选边界处理。

首次有效回复本身既使对话新增进入沟通，也构成当期活动，不要求之后额外再收/发一条。历史完整且范围一致时，新增是活跃的一部分；历史不足时可以只有新增未知、活跃仍有可靠结果，不强制把两项一起设为零或一起隐藏。

### 2.1 首次回复必须核全历史

`firstReply` 指该精确对话全历史最早的有效红人回复，不能在日期筛选后再取区间第一条回复冒充首次。首次回复在区间外、区间内仍有沟通消息的对话，可计期间活跃但不能计新增。

历史不足以判定首次回复或活动所属沟通阶段时，显示“—／历史未覆盖”等状态；不当作零、不默认全部为新增，也不假定已进入沟通。真实有效消息状态、覆盖起点和可支持消息类型继续研发核验。

### 2.2 精确对话而非组织达人去重

优先采用经核实的真实对话 ID；否则按真实来源任务/项目、达人、平台等足以唯一标识对话的业务键映射。具体字段留研发核验，不把本示例键写成正式数据库设计。

同一达人在不同来源任务或不同组的独立对话分别计数；不得按“组织 + 达人”全局合并，不将来源任务下的多条消息分别计为多个对话。组织/组汇总按精确对话去重，不能把成员明细直接相加造成重复。

已核 [消息中心静态事实§4、§5](./email_message_permission_evidence_2026-11-10.md) 中，`message_center` 达人卡片按 `uid + channelId + platform` 聚合，不含项目/组，`message_center_task` 才包含源业务项目；不能直接把卡片数或达人数当本次精确对话数。Owner交接或对话转交不应仅因换人就把同一对话重新算新增沟通，稳定标识与迁移留 `RQ-CONV-01/03`。

### 2.3 范围与授权沿看板三视角

组织/组汇总可看相应整体结果；个人和管理者选单人只看该账号真实动作，项目只是动作过滤。组长另可看所辖组项目整体，Admin只有组织身份时不具备该入口，兼组长同页合并可用入口、无须换身份；个人范围仍普通成员。统计不授正文或写ACL，来信/整体对话效果不能直接变成某人动作或绩效。

当前组边界、项目/账号筛选、历史迁组及交接归因必须一致。不能从当前负责人或今天所在组回填历史归属；范围不明时说明未覆盖，不向其他组或个人扩大。

## 3. 导出与原功能边界

- 新 Dashboard CSV 为这两项单列“对话沟通汇总”，保留日期、授权/统计范围、筛选、更新时间及数据状态；不混入原 11 项的字段语义。
- 原模块导出仍为 Summary 11 项 + 账号八项，不新增任务导出，也不声称它已经支持这两个新对话指标。新 Dashboard 的扩展导出须单独核真实接口及同范围约束。
- 趋势、漏斗和新增对话指标不改原团队邮件数据抽屉，不改消息中心的建联/沟通列表、对话转交、发件身份、通知或扣量。
- Demo 只用虚构样例示意时间差、老对话活动、未回复排除及未知历史；不真实发信、收信、强刷、导出客户数据或新增生产聚合接口。

## 4. 独立研发核验

| 编号 | 保留事项 |
| --- | --- |
| RQ-CONV-01 | 精确对话真实 ID/来源键、平台/达人关系及去重；全历史首次有效红人回复、建联转沟通时点，不能按区间首条回复推算 |
| RQ-CONV-02 | 有效收/发消息的状态与类型、活动从首次有效回复本身起、时间边界/时区、历史覆盖及两项各自缺失状态；不能把未回复单向邀约算活跃 |

上述为落实已确认规则的技术核验，不新增产品决策卡、不把定义整体恢复待定，也不关闭 `RQ-DASH-01–04` 或其他模块核验。

## 5. 先跨模块总览，再模块分析（2026-11-11 确认）

本轮吸收便于阅读的顺序，不复制竞品功能全集、不新增指标或权限。原三视角、统一日期、指标解释、期间与当前值的区分、未知/无权/延迟、实际观察截止及同范围导出全部保留；不以首屏更紧凑为由弱化这些边界。

### 5.1 四个紧凑分区

业务概览在模块分析页签前先展示以下四区，复用已确认指标，不另造分数或跨模块转化率。

| 分区 | 先读的两项 | 仍按原口径解释 |
| --- | --- | --- |
| 触达 | 发送数、回复率 | 发送日期范围内邮件截至更新时间效果，回复率仍除发送数 |
| 沟通 | 新增沟通对话、期间活跃对话 | 消息事件时间、精确对话及全历史首次回复，不按达人数或每日去重求和 |
| 合作 | 期间新增CRM记录、其中当前合作中 | 创建日期范围内记录的当前状态，不是期间进入合作事件 |
| 内容 | 期间新增监控条目、期间观看增长 | 条目加入日期与daily观察增长分开，增长含旧存量且显示实际截止 |

四个分区不是依次转化阶段；单位、对象、时间语义并不相同，不能串成“发送→沟通→合作→内容”的漏斗。

四区的原效果指标用于合法整体范围；个人/选单人须换为来源支持的实际动作，不把观看增长、Assignee名下全部记录或来信强套为个人量。总览按当前统计模式和日期，下方单邮件项目只筛相应分析；普通账号选项目只过滤本人动作，不能看总量。入模块保留范围/日期并重置项目，不改变业务组或正文权限，Admin兼组长在同页开放其可用统计入口。

### 5.2 邮件趋势：日期范围与分桶粒度分开

- 邮件四线提供日/周/月粒度，切粒度不改变开始/结束日期；沿原发送日期归集看截至更新时间效果，不把粒度当配额重置周期。
- 周按周一开始的自然周；月按自然月。首末桶仅包含选择范围内的日期，不为了凑完整周/月扩大查询范围。
- 四封数按桶聚合原数；原三率按相应总数量除发送数重算，不平均各天/成员比率。原值漏斗仍用整段同范围总值，不被分桶改写或裁数。
- 对话两项按完整所选范围精确去重，不由每日去重数相加；邮件趋势切日/周/月不把它们改成消息条数。
- 轴、图例、提示和未知/延迟状态保持现有语义，低量整数刻度不重复；按 `../kol2.0-design-specification/playbook/components/chart.md` 和 `playbook/semantic-tokens.md` 复用既有图表语言，不新增视觉体系或依赖。

### 5.3 核心四位承载七个值，额外四项可展开

邮件分析只设置发送数、送达数、已读数、回复数四个主指标位。送达、已读、回复位内分别次级展示送达率、已读率（原打开率）、回复率，不再为比率单独占指标位；核心仍是四封数+原三率共七个数据值，不是只留四个字段。已读数/率仍用原 `openCount/openRate`，不另造指标，三率仍以发送数为分母。

邀约红人数、建联红人数、红人消息数、跟进消息数四项折叠后仍可展开查看。

折叠只是阅读顺序：原11项、原Summary11+账号8导出、账号/任务八项、四线/原值漏斗及独立对话两项在合法整体范围保留。个人/选单人不硬套全部来信或效果指标，缺actor来源标未知，不复制项目总量凑齐；自动任务单列。新增对话两项始终独立，不塞回原11项。

业务顶栏仍“导出当前模块”，附统计模式/范围/日期/项目条件；合法整体保留原完整字段，个人/选单人只导实际动作，自动/未知单列，不能靠导出拿到项目整体。跨模块不新增合并报表，资源仍原计量主体与导出语义。

### 5.4 本轮不扩展的内容

时间×账号的周/月明细仅为后续可考虑方案，尚未批准本轮实现；不新增自定义报表、寄样或短链看板，不将趋势分桶解释为已支持这些能力。真实页面任务映射仍后置，现有生产服务和原模块抽屉不在本轮重构。

范围隔离、日/周/月边界、原数与比率对账、精确对话去重、展开/导出无损及真实服务SLA继续列 `RQ-CONV-03` 和原有研发核验，不新增决策卡，也不因Demo示意通过而关闭。
