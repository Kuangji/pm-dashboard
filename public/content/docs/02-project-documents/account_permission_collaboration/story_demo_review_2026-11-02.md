## 一、这次要验证什么

这是帮助团队理解需求的独立示意 Demo，不是准生产系统。读者应能从 [故事审阅稿](./use_case_stories_v0.md) 的 S01–S44、导出子场景 S33a–S33p 找到相应内容，而不必猜在哪个模块、用哪个模拟身份、按什么顺序试。

每个故事的审阅只问五件事：

1. **找得到**：可从故事目录或搜索进入；待定场景和无用户操作的后台场景也有明确入口，不只给一个无上下文的编号。
2. **身份对**：区分组织 Owner/Admin、组 T2/T3、项目 Owner/Collaborator、CRM Assignee，以及当前组与对象归属组。
3. **步骤清楚**：说明或演示谁先做什么、谁随后处理；缺前提时说明阻断原因。可使用步骤卡、状态切换或明确的模拟动作，不必接真实业务。
4. **结果不反向**：显示的权限、数据归属、责任和资金承担等核心后果符合已确认 Input。允许样本和简化，不能让演示结果表达与规则相反的含义。
5. **未定不冒充已定**：候选方案、一期待接收事实、未定义的细节均就地标明；不为补齐可点击性而擅自选定方案。

“有故事/议题链接”仍不自动满足这些要求；应检查入口、身份提示、页面文案与实际可见结果。相反，只有文字或步骤卡也不自动不合格：后台初始化、未批准路径和待定方案只要说明准确，就可用于审阅。

## 二、哪些不再作为 Demo 完成条件

| 不要求完整实现 | 合格示意方式 | 不能借模拟边界掩盖什么 |
| --- | --- | --- |
| 服务器、数据库与跨会话持久化 | 本次页面内状态、固定样本，明确重置后丢失 | 不把本地成功提示写成真实邀请、付款或上线成功 |
| 完整权益/Scope 执行引擎 | 选择有权益/无权益/额度不足场景，展示对应条件与阻断 | 不把“额度充足”说成能绕过套餐或对象权限 |
| 真资金账本、对账和支付回调 | 显示资金承担快照、占用/回补步骤和模拟结果摘要 | 不把钱记给执行人，不暗示可凭数据删除清空资金责任 |
| 真实时钟和完整支付状态机 | 明确选择预约前、按时、逾期场景，显示应有分支 | 不演示成到期后才开始预审核，或迟到审核触发自动转账 |
| 真实异步队列、分页与断点重试 | 固定的等待/进行/失败/完成步骤与摘要 | 不把中途成功表示成全部完成，不省略仍待处理对象 |
| 全量历史迁移、注册和真实套餐购买 | 迁移前后对照、身份变化说明与当前产品边界 | 不把一期规划或模拟样本当成真实交付证据 |
| 尚未确认的功能终稿 | 显示目标、候选项、影响、明确的待确认标记 | 不把可点击候选示例写成正式规则 |

因此，不再要求为“补足故事”搭建真实冻结、注销、支付、退款、导出或跨企业恢复系统。需要的是准确、可定位、能够读懂的示意路径。

## 三、旧 F01–F06 重新分类

以下是按新标准对旧发现的处理决定，不是对主代理新代码的完成验收。定位沿用 10-29 报告的文件快照；修改后的行号、行为与证据需在本轮验证时重新核对。

| 旧项 | 新分类 | 本轮应处理的最小问题 | 不要求补建的实现 |
| --- | --- | --- | --- |
| F01 预约审核过晚/逾期返回预约态；S28 | **需修正表达或可见路径** | 预约前可理解“先预审核，后到时执行”；逾期分支不可表示为迟到审核自动转账。可通过明确的场景开关/步骤卡表达；策略关闭等待定分支继续标假设 | 真实时钟、调度器、支付状态机和完整自动回调 |
| F02 归档后历史入口被封；S38 | **需补准确入口/示意** | 读者能进入“归档历史”或其只读示意，理解历史按原授权可达、普通业务停止；不能仅保留一个归档组名称却把历史描述成全部不可见 | 完整归档查询接口、真实对象权限引擎重构或恢复归档能力 |
| F03 整体接替删除 ACL 而未表达接替；S36 | **需修正可见结果** | “整体接替”故事应说明/展示约定范围的显式协作关系接替，而非统一显示只删除离职者协作。普通退组清理与整体接替须区分；覆盖未定对象继续列明 | 真实跨模块批量写入、新邮箱登录、邀请邮件和完整移交任务系统 |
| F04 退出后原承担人的内部模拟账务未回补；S30/S36 | **模拟边界/技术记录，不单独阻塞审阅** | 核心说明保持 fundingUid/fundingGroupId 不改写、取消/失败等按原承担关系处理；结果区标明账务为示意、不验证真实对账。若页面仍直接展示相反的资金归属或把残留样本说成正确结算，才修正该可见表达 | 为通过审阅而修齐历史关系索引、真实余额守恒、会计冲正和对账系统 |
| F05 已分配 CRM 记录没有组长改派入口；S20 | **需补准确入口** | T2 能找到已有/未分配记录的最小分工清单或改派示意，且不因此取得完整记录明细或一般编辑权 | 真实 CRM 接口、旧四项范围完整迁移和所有记录查询实现 |
| F06 监控共享标签被表述为创建组隔离；S21 | **需修正规则表达/示例条件** | 创建来源不等于治理隔离；表达满足资格的 Owner/Admin、有效 T2 可治理组织共享定义，项目内应用另按项目权限。不能一边说明组织共享、一边以创建组关系给出反向拒绝结果 | 真实共享标签库、全量项目应用接口、CRM/消息治理规则统一改造 |

F01/F02/F03/F05/F06 的本轮重点是消除误导和入口缺失；最小修正可落在页面、故事步骤或轻量本地交互，不强制把演示引擎做成生产模型。F04 保留到技术记录，不借此新增本版产品讨论；如果未来进入真实研发，再按正式 Spec 处理账务完整性。

| 故事 | 本轮足够的审阅形式 | 保持的边界 |
| --- | --- | --- |

| S09–S14 配额、委派、消耗、批量和周期 | 上下级数值样本、授权与额度双条件、成功/阻断示例 | Scope 未定矩阵、特殊值和月度规则不假装已定；不要求所有计量引擎 |

| S20 CRM 分工 | 必要信息清单与指派/改派步骤或交互 | 不以方便演示为由给组长全量记录权限，旧范围迁移仍待定 |
| S21–S24 标签、消息、搜索、会话/旧任务 | 共享定义/项目应用分开说明，筛选样本与待定目标可定位 | F06 修正；会话与旧任务不为补齐演示擅自定稿 |
| S25–S30 资金与支付 | 部门配置、草稿协作、提交/预约/审核和异常结果的样本步骤 | F01/F04 按新分类处理；真支付、回执、治理和账本不作完成条件 |
| S31–S33 看板、历史及导出 | 筛选和数据状态示例，导出 16 子场景可找到其目标/状态 | 不要求生产指标、去重、全量导出实现；未知不当零 |
| S34–S37 迁移、退出、整体接替、任务反馈 | 前后状态、资格、ACL 禁用恢复/接替、等待/失败/完成摘要 | F03 修正；不要求真实分页原子性和队列，未覆盖模块须标明 |
| S38–S39 组归档与合并 | 归档历史示意、停止业务的后果；合并的待定选择点 | F02 修正；不擅自加入恢复归档或完整组合并 |
| S40–S41 到期冻结及激活 | 能选取或读到到期/冻结/激活前后身份与结果的完整步骤 | 不自动全员解冻，不支持主动冻结，不新增降级流程；无须真实到期回调 |
| S42–S43 所有权及注销 | 身份交接、三次确认、资金阻塞、不可恢复的步骤示意 | 原 Owner 转让后身份等额外假设注明；不执行真实注销或退款 |
| S44 跨企业路径 | 明确标记未批准，说明目标、冲突与待确认条件 | 不为了“故事全覆盖”实现企业暂停/恢复 |

### 原 Demo 多出的假设如何处理

- 原 Owner 转让后固定变 Admin、默认组禁止归档、关闭审核自动解除待审闸门、批量增加整批失败，均须标为演示假设或边界，不回写为新产品结论。
- D15 到期冻结/激活主流程已确认；不能在聚合文案中继续诱导重新讨论。D 列表可以保留编号用于追溯，但应区分“已确认规则”和“待定选择”。
- 体验账号切换、探针、模拟数据状态、模拟接受、重置和审阅记录导出是评审工具，不必为其增造生产用户故事。

## 五、本轮处理计划与验收方式

1. 增加可直接定位 S01–S44 及导出子场景的故事审阅入口，保留组织管理与业务模块分区，不要求重建生产页面导航。
2. 每个故事展示身份/前提、步骤、结果、规则状态和相应页面入口。能够操作的继续复用现有操作；暂不操作的用准确步骤示意，不用孤立的“待讨论”按钮代替全部上下文。
3. 对 F01/F02/F03/F05/F06 纠正相反表达或缺失入口；F04 明示模拟账务边界。不得为修 Demo 更改已定 Input、代替产品确认或扩展真实业务范围。
4. 完成后逐故事核对入口、身份和可见结果，抽查未定分支；以浏览器实际展示和交互为证据。相关单测只证明本地既有/新增演示预期，不等于产品安全认证。
5. 按现有 Demo 发布合同跑测试、浏览器验收与 publish 一致性检查；主代理取得结果后再报告完成。未验证的代码不得在本报告中预先标为已修复。

可接受的验证包括静态故事卡、一步步场景切换和本地模拟交互；不要求每个故事都产生真实状态变化，也不要求后台故事伪装成人工操作。可查覆盖数只能说明入口齐全，不能独自证明内容准确。
