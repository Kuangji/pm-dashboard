# 聚星账号权限统一版本｜研发评审大纲与讲解路径

> 日期：2026-11-12。对象：前端、服务端、测试及相关模块研发。
> 用途：下午评审的主持提纲与 Demo 导览，不是新 Spec、会议纪要或新增需求。以当前 [Input](./phase2_input_v0.md)、[功能梳理](./账号和权限功能设计梳理.md)及 [43 个业务故事](./use_case_stories_v0.md)为依据，包含 11-12 最新收口。
> 版本：一期之后的一个统一版本，工作区索引为 v6.5.2；不是另拆二期、三期。以一期底层替换生效为规划前提，实际交付仍需研发提供验收证据。

## 1. 主持人速读

**一句话主线：** 一个组织从默认组开始，分部门、安排成员与资源，在原有业务模块内协作；人员变化后业务仍可交接，历史责任与统计不被改写。

开场可以直接这样讲：

> 今天不是把各业务模块重做一遍，也不是逐页确定 UI。我们要把一期的组织底座变成完整的用户流程。先对齐组织身份、组身份和对象权限的区别，再看配额、资金、清退和看板怎样使用这套事实。请研发重点指出三类问题：一期还没提供的基础、与现有业务逻辑的冲突、需要新增记录或状态才能完成的闭环。已确认规则不默认重开，有成本或兼容冲突就明确记录影响和备选。

今天必须带走的结果：

- 一期接收清单与本版净新增的分界，不能用“已有字段”代替“已有可用能力”。
- 模块适配和全对象清退的认领清单，包含后台、导出、聚合和回调，不只是页面。
- 管理动作矩阵与三组留评审问题的结论，或明确的补证人、材料和回收时间。
- Dashboard 能提供哪些指标、历史从何时起、缺什么事件，以及支付与移交的高风险实现边界。

**不要以 Demo 能点通作为生产可行性证据。** Demo 是独立示意，不能证明接口已接通、真实账本正确或一期已上线。

## 3. 先讲清楚六个概念

这一段先不点业务按钮，用下面一张表建立共同语言。

| 概念 | 已确认含义 | 最容易讲错的地方 |
|---|---|---|
| 登录账号 | 可独立于企业存在；加入企业前须符合干净账号条件 | 注销企业不等于删除登录账号；注销中不能加入另一组织 |
| 组织身份 | 唯一组织 Owner、多个 Admin、Member；Admin 全组织管理 | 管理身份不天然成为所有项目协作者，不按 Admin 配管理组范围 |
| 组身份 | 同一人可在多个组分别为组长或组员；每组 0..N 个组长 | 组长不能邀请或主动移出成员；可以处理组织侧产生的本组交接任务 |
| 业务对象 | 项目/支付单固定归组；CRM 是组内记录，不强造项目容器 | 入组不搬业务；本期没有项目迁组或组合并 |
| 对象负责人/协作者 | 对象负责人不是组织 Owner；显式协作是普通业务读写 | 不设只读协作者；读写不等于可管理名单、可执行付款或可删整项目 |
| 资源与统计主体 | 授权、扣量账号、资金承担人、真实操作人各有语义 | 不能从当前 Owner、兼容 Creator 或配额 UID 反推历史贡献 |

讲解授权时用一句话：**先过组织/组有效资格和对象归属边界，再合并该模块允许的授权来源，再检查具体动作、权益及额度。** 这是解释顺序，不规定研发必须采用某一种代码结构。

组长默认协作是组织全局开关，默认关闭；开启后在接入对象上形成动态隐式来源、名单锁定展示，不落显式 ACL。关闭只撤销这一来源，独立显式授权仍有效。CRM 不接入；组长来源不附带名单管理或支付执行能力。

转场：**“身份解释完了，接下来分别看组织管理员配置工作条件，和组内人员实际做业务，入口为什么分开。”**

## 4. 按闭环走 Demo

每段只证明一两个关键点。可选分支留到有人提问再演，不追求现场覆盖所有按钮。

### 4.1 组织配置：让新人进入一个能工作的组织

**讲什么：** 组织管理管成员、组和策略，不等于管理员直接包办组内工作。

1. 林知夏 → **组织成员**。先看有效成员、待接受邀请和剩余名额；预置陆遥邀请可以模拟接受或撤销，二选一后刷新即可看另一分支。待接受邀请占席位，不等同有效成员；Demo 的总席位样例不是实际套餐子账号换算契约。
2. 打开 **邀请成员**表单：仅组织 Owner/Admin 可邀，首组可选、默认默认组；不在这里给个人配额。待接受邀请不改组/身份，需要撤销重邀。
3. **业务组**：展示同页目标组及“成员与身份 / 组配额 / 组策略”。说明正在管理的组不必是自己的业务当前组，也不会偷偷切换业务身份。可以先建空组，不能把建组当成搬项目。
4. **全局策略**：指出组长默认协作、组长配置成员额度委派，以及仅组织 Owner 可设置、默认关闭的“Admin 可移除成员 / Admin 可归档组”。
5. 回 **业务组 → 组策略**：达人标签限制、监控标签限制、支付前组长审核是三个独立组策略，均默认关闭，由 Owner/Admin 配；组长在“本组管理 → 本组策略”只读查看。

**讲透一句：** “策略作用于某个组，不代表组长有权修改策略；组织管理者配置目标组，也不因此获得组内所有业务正文。”

**请研发确认：** 邀请接受时席位/组资格并发检查；所有请求携带何种组织/组上下文；前端缓存与后台任务怎样防串组。不是只验前端下拉框。

### 4.2 业务适配：邮件作样板，其余只讲差异

**主演示：** 许念 → 邮件项目 → “秋季新品达人邀约”卡片铅笔“编辑项目”，给方禾勾选显式协作但不授名单管理并保存；再切孙可、方禾打开同一项目设置。分别看到“负责人可改名称和名单 / 孙可仅改名单及管理能力 / 方禾设置只读”。设置只读不等于邮件内容只读。

要演组长来源时，由林知夏在全局策略开启“组长默认成为组内协作对象的协作者”，再切周明查看锁定来源。组织身份不直接获得项目；可看设置不代表可改治理字段。

**邮件保持的例外必须说：** 有效名单管理员可以继续授予名单管理能力；不新增不可传递限制。邮件没有日常主动负责人转交，只有账号级交接。原“团队邮件数据”抽屉保留，唯一产品变化是账号范围限当前组，汇总、展开和导出也必须一致限组。

其余模块用表讲，不逐页完整重演：

| 模块 | 保留什么 | 本版适配与不能套用的通用规则 |
|---|---|---|
| 智能营销计划 | 已有内部流程及邮件核算 | 作为典型项目协作对象适配组可见性/授权边界；不是借本版重做内部流程，Demo 不提供完整计划模拟 |
| 消息中心 | 来源邮件项目权限、精确对话转交、发件身份及提醒 | 转交候选限同组；不改项目 Owner/ACL，不新增单会话 ACL。聚合、未读、附件、检索和后台发送也要隔离 |
| 收藏夹 | 私有 / 团队公开 / 指定成员三模式及既有配额 | 团队公开变本组公开；私有也接受已开启的组长隐式协作。夹治理 Owner 专属，协作者仅内容读写 |
| 内容监控 | 计量、时长、追踪、内容负责人及原设置权限 | 加组边界和组长普通协作；名单/项目治理仍负责人专属，不新增名单管理委派。内容负责人不是项目 Owner |
| CRM | 原四项写配置、对接人/未分配兼容与原改派规则 | 同达人各组独立记录，基础资料共享；读写先受记录组硬边界。没有记录协作者，不改成全组默认可写，不把所有新 Admin 等同原解析管理员 |
| 标签 | 达人、监控两套字典语境 | 两域均组隔离；达人标签在同组 CRM/消息/资料抽屉复用。定义增删改受各自组策略，打标仍需对象写权；本人置顶/偏好/展示不受定义开关限制，也不授业务权 |
| 数据导出与通用查询 | 各功能现有访问与当前用户既有扣量 | 16 条原始导出需求在版内，样例 CSV 不代表真实导出已实现；搜索/榜单/详情不是项目，不套项目 ACL。旧任务列表日常功能不改、默认全组织可用 |

**请研发确认：** 按模块认领适配入口和后台旁路；CRM 历史记录组键、旧权限来源映射及未分配记录可编辑性；标签原共享字段能否按本人隔离。旧任务“日常不改”不等于清退可不接入。

### 4.3 普通配额：先分清配置层级，再讲扣量

**演示路径：** 林知夏 → 业务组 → 增长团队 → 组配额；在全局策略开启“允许组长管理本组成员配额”后，切周明 → 增长团队 → 本组管理 → 成员与配额。

1. 组配额同时展示多种 Scope 的原上限、已用、组织约束、新值和保存后实际可用，不能只演一项笼统“配额”。
2. 演一次普通 capped 下调低于已用的影响预览：允许保存、历史不回滚、实际可用为 0；不为演示而清空所有额度，取消即可继续。
3. 对比组长逐成员设置 inherit/capped 及批量增加。组织身份不能越级改个人；有组长身份也需满足全局委派开关。组长可以设置自己，但不能越过组约束。

**讲透三点：** 普通配额可以同级超配、实际逐层拦截；inherit 不是无限；个人配置属于“账号 + 组 + Scope”，没有跨组个人总上限。父级缩小不自动替组长重写成员配置。

**不要把扣量统一：** 邮件发送/邮箱解锁、收藏夹解锁、监控时长/追踪席位各沿既有规则。实际操作者统计与核算 UID 分开；自动邮件多轮跟进不能笼统说免费，消息已有对话回复也不能等同所有入口免扣。

**留评审：** Scope 能否下分、单位、周期、特殊无限值与剩余展示、共享解锁是否新增记录。收藏夹单夹容量等已定例外不因矩阵待补而重开；年度父额度另设月度预算本期不做。

### 4.4 支付：把“能填单、能花钱、钱算谁、谁审核”分开

先讲资金来源，再演支付单，避免把个人上限误讲成一笔预拨款。

1. 林知夏 → **组织资金**：组织钱包总额、待分配可用和专用组余额不是三份可相加的钱。普通新组支付默认关闭，开通后只能用组专用余额；存量有支付权益组织的默认组是已确认共享例外，只用未分配可用部分，不能动其他组专用款。
2. 展示**组支付余额 → 分配**及未承诺余额归还；每笔有流水、不改历史。充值依旧线下；“有新充值到账”只是页内可关闭提示和分配快捷入口，不是线上充值产品，也不是唯一分配入口。
3. 许念 → **跨境支付 → Mia · 首批合作款 → 协作者**，给孙可勾选“执行支付”；切孙可展示“填写草稿”。普通同组非协作者不可见草稿，正式单同组可读；协作者能填，正式/预约提交和支付者放行仍需负责人或 can_execute_payment。
4. 先由林知夏回 **业务组 → 组策略**打开“支付前需要组长审核放行”，再由孙可正式提交；切周明，在支付页“待组长审核”筛选中点“审核放行”。资金承担仍是许念。用非组长提交人才能看到闸门；若提交人本来就是有效组长，会豁免，不能误判流程失效。

| 要讲的责任 | 已定口径 |
|---|---|
| 提交与预约 | 提交即占用；支付 Owner 的资金承担快照固定，执行人/审批人另记 |
| 审核时机 | 立即：系统审后；手动：支付者放行后；定时：预约点之前预审，逾期不因补审突然执行 |
| 策略与组长变化 | 实时判断未执行闸门；任一有效组长即可，提交人是有效组长豁免，无有效组长只跳本闸门 |
| 退款与关闭 | 退款恢复原承担关系个人可用，不抬上限或转给接替人；资金按原来源/周期回补，关闭后不丢后续账务 |
| 收款信息 | 全组织共享频道快捷模板，所有有效业务成员可维护；支付单独立保存快照，不因此共享来源订单 |

**现场问研发：** 原子占用、分配与回补的账本契约；旧单来源/周期、关闭后退款、提交人和承担人字段；审核与预约并发。异常冲正沿原人工、币种手续费沿原账务，不顺手新增自助金融配置。

**演示边界：** Demo 省略真实系统审核、调度和转账；资金读取权限矩阵仍待讨论，当前演示谁能看到什么不能反向成为正式裁决。

### 4.5 人变动：先失权，再完成业务处理

先刷新，使用原始预置沈岚，不需现场新造一套清退状态。

1. 林知夏 → **使用情况实时待办 → 组织移交任务**：沈岚涉及增长、品牌两组，组织管理者只跟踪进度。REMOVING 已失去业务资格，但还没最终结束关系。
2. 周明 → 增长团队 → **本组管理 → 业务交接**：选择同组合法接收人完成增长团队任务。CRM 接收人可另选或留未分配；不要因示例只有收藏夹而认为移交只覆盖项目。
3. 回林知夏看 **1/2 组已处理**；未处理组仍等待。组长不能主动清退或撤销，操作的是业务交接，不是批准人员离开。
4. 解释品牌组可继续交接，或在资金条件允许时由组织侧永久归档。可选实操：林知夏 → 业务组 → 品牌团队 → 组操作齿轮 → 冻结归档组，核对影响后继续并确认不可逆；组织移交任务看到“归档免交接”、2/2组已处理。原责任和历史不改，不能称全部资产已移交。人工资金事项未处理阻塞归档，纯后台承诺不一概阻塞。

资金阻塞只作备演，先刷新：林知夏开启增长组支付审核策略，再尝试归档增长组，可看到已有付款的人工审核阻塞。不要接在刚刚审核完付款的现场状态后演这一分支。

再展示一次组织成员“移出组织”的三路径选择，**不必逐条重新执行**：

| 路径 | 执行与继承规则 |
|---|---|
| 邀请新账号整体接替 | 有权 Owner/Admin 提交；新账号接受邀请后系统执行，无额外审批；继承有效组关系，不继承组织/组长角色 |
| 指定现有账号增量接替 | 提交即系统执行；缺失组关系补组员，已有身份/配置保留，不覆盖为离职者身份 |
| 各组长分别处理 | 分组待办，当前有效组长决定本组业务接收人；无组长且有业务项时等组织任命，不静默落给 Admin |

共同边界：全部未永久归档组业务对象都须接入，含精选任务/TikTok Shop 私信；不以冻结保留替代。个人上限不继承、不相加，旧消费/占用不返还，历史 actor 与资金责任不改。永久业务组归档豁免不能套到模块内部归档对象。

用最后一分钟区分生命周期：

- **退某组**只影响该组，可在最终完成前由组织侧撤销；最后有效组结束前须安排另一有效组或改走组织清退。
- **移出组织**影响所有组、不可撤销；全部必要组已处理才最终完成。
- **会员到期**不解绑、不销毁；仅组织 Owner 活跃，其他人冻结但按原权限读历史，续费后 Owner 按名额选择激活，不提供主动冻结或线上降级。
- **组织注销**仅组织 Owner，付费期走人工、资金事项阻塞，允许全员一起解除而不逐个移交；非资金业务停止/放弃、不可恢复、三次确认。注销中不是干净账号，不支持暂停组织/离开外企后恢复。

**不可现场走通的部分：** S38 归档历史可读是规则说明，没有历史对象查看器；S40–S41 激活与 S43 注销不演完整状态机。不要为证明规则而寻找不存在的按钮。

### 4.6 Dashboard：工作量、业务结果、资源使用不是同一张账

建议刷新，避免人员变更影响体验资格；保持默认有样例数据的日期，不切真实当天。

1. 林知夏 → **使用情况 → 组织 → 业务概览**：全组织、分组及选单人。先看总览，再入邮件/CRM/内容监控；日期作用于对应期间口径。
2. 周明 → **组**：看组整合、组员动作和“查看本组项目整体结果”；再切**个人**，只看本人动作。普通成员按项目筛选也只过滤本人的动作。
3. 陈予安：组织管理兼组长，同页合并可用范围，不要求另切角色；不能用 Admin 身份开放其他组项目统计或正文。

**请研发回答：** RQ-DASH/TIME/CONV/ACTOR 对应来源、真实事件、历史起算、组归因、去重及 SLA。新沟通指标不能由旧卡片数量凑出；缺数据不补 0，刷新时间不冒充来源更新时间。原邮件抽屉继续保留，不要求 Dashboard 全身份替代。
