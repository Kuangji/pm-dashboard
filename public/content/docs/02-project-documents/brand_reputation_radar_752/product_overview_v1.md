# v7.5.2 品牌舆情雷达 · 产品说明

面向设计与研发｜2026-09-09｜依据 Input、Spec v1、Design v1 及当前 Demo 整理

## 1. 这项产品解决什么问题

品牌团队需要同时看清两件事：创作者发布的内容怎样谈论品牌，以及用户在这些内容下怎样回应。品牌舆情雷达把内容、采样评论、主题和情感放到同一个品牌视角下，帮助用户发现值得关注的反馈，再查看具体内容和评论判断原因。

例如，用户先看到近期“尺码”相关讨论较多，再分别查看内容与评论的情感，最后打开对应证据，判断讨论具体在说什么。图表负责呈现事实，结论需要有证据支撑；一期不提供自动危机判定或舆情处理工作流。

产品从品牌页面进入，采用独立页面、独立付费的定位。基础舆情证据不要求先解锁 Assets。页面只有“舆情全景”和“舆情动态”两个 Tab，默认进入全景。

## 2. 看数据前，先区分内容和评论

**内容统计针对已采集内容集合；评论统计只针对头部内容下已取得的评论样本。** 这是整项产品最重要的口径，标题、图表、筛选和明细必须始终一致。

| 页面中的信息 | 应当怎样理解 |
| --- | --- |
| 已采集内容数 | 当前品牌、观察时间和内容条件下纳入的内容数量，不代表全网所有提及 |
| 采样评论数 | 关联头部内容的评论样本数量，不是这些内容的公开评论总数 |
| 已观测曝光 | 当前 Demo 对内容累计观看量求和，不是观察期新增曝光或去重触达人数 |
| 内容趋势 | 已采集内容的发布时间分布 |
| 评论趋势 | 评论样本的取得时间分布；评论明细仍显示原始发表时间 |
| 正负情感比例 | 以情感已知的对应样本为分母，包含中性，排除未知；无有效样本不显示为0% |

一条内容可能属于多个主题，所以主题数量相加可能超过内容总量。“典型评论”当前是组内示例，不表示算法已选出最有代表性的一条。没有数据、没有采样和已知数量为零，也必须分别表达。

## 3. 用户如何使用两个页面

### 舆情全景：理解整个观察期

用户从总量进入主题和情感，再通过明细查看证据。页面按以下顺序连续阅读，保留一级标题，不提供锚点导航。

| 分组 | 包含什么 | 用户获得什么 |
| --- | --- | --- |
| 核心概览 | 品牌声量趋势、内容指标、采样评论指标 | 观察期内讨论量和正负反馈的基本情况 |
| 内容舆情 | 内容趋势、主题与标签、内容情感、已观测来源/地区、内容明细 | 创作者谈论什么，内容呈现怎样的态度，来自哪些已观测渠道 |
| 评论舆情 | 采样评论趋势、主题分析、评论情感、评论明细与主题抽屉 | 已取得的用户反馈集中在哪里，有哪些具体表达 |
| 影响情感 | 创作者影响情感双指标图 | 不同创作者分组的内容情感，以及带评论内容的综合表现 |

内容情感和评论情感独立展示，不能只用一个切换组件代替两者。主题表保留同主题的不同情感行，支持主题多选、分页和证据查看；标签列表可切换数量或已观测曝光，点选后查看对应趋势。来源摘要只描述已观测渠道，不宣称平台份额。

全景保留一个统一的高级筛选抽屉。受众画像、发布时间分析、发布频率及“其它”分组不进入主页面。

### 舆情动态：浏览近期变化与证据

顶部保持原 VOC 的整体看板：世界地图作为主要区域，摘要和72小时趋势与地图放在同一结构中。地图及地区排行只统计近期新发布内容数量；72小时新增评论明确标为“头部内容评论采样”。

看板下先是内容动态：主题/标签、负向内容主题、新发布内容地区、来源/平台和热门内容表；再是评论动态：主题词云、主题排行、负向评论语言和评论样本表。内容总趋势不重复放第二次，主题自己的小趋势仍保留。

点击地图地区，会在当前页筛选内容表并显示可关闭的地区条件，不滚动、不跳转、不改变评论样本。点击负向内容主题同样筛内容表，且与地区条件互斥。评论词云、主题和语言入口打开相应评论证据。来源榜保持只读。

动态页没有高级筛选。所谓“热门”仅是当前内容集合或评论采样范围内的排序，不提供“全网评论最多内容”排行榜。近期窗口以数据快照截至时间为准，不承诺实时采集。

## 4. 操作会影响哪些数据

全景高级筛选分为两组：内容条件包括关键词、平台、时间、内容情感、创作者规模/类型；评论条件包括正文关键词、主题、评论情感和所属热门内容。打开后先编辑草稿，点击“应用”才更新页面；取消不生效，“清除”恢复默认范围。

| 操作 | 生效范围 |
| --- | --- |
| 全景高级筛选中的内容条件 | 更新内容集合，以及这些内容关联的评论样本和各模块统计 |
| 全景高级筛选中的评论条件 | 只更新评论及依赖评论的结果，不减少内容总量，不改变内容情感基线 |
| 内容表的搜索、平台、情感、排序 | 只改变该内容表，不改变头部总量或评论域 |
| 评论表的搜索、平台、排序 | 只改变该评论表；从表内主题打开的证据遵循当前表的过滤条件 |
| 主题表的主题选择 | 只筛当前主题表，不改变全局趋势或另一数据域 |

内容表按标题搜索，去除首尾空格后按 Enter 提交；评论表按正文即时搜索。内容表支持观看量排序，评论表仅按发布时间排序，不展示未经确认采集的评论点赞数。两表默认每页5条，可选10或20条；搜索、平台、排序或每页条数变化后回第一页，翻页不自动滚动。

应用全景高级筛选后，局部搜索、情感、主题、排序和页码一起重置，避免表头已复位而数据仍按旧条件排列。切到动态时不携带隐藏的全景高级条件，当前再回全景恢复默认范围。

所有浏览、筛选和重试都只是读取与展示，不触发采集、扣费或服务端写入。没有可靠观看历史时，不显示曝光增长曲线。

## 5. 创作者影响情感如何理解

这张图按创作者规模或类型分组，每组显示同一正负尺度上的两条水平条形：

- **内容情感基线**：只看有效内容情感，使用更粗、对比更强的实心条。
- **带评论内容情感**：在具备有效评论的内容子集上结合内容与评论反馈，使用更细、更浅的条。

两条指标的内容样本范围可能不同，差距不能直接解释为“评论造成了情感变化”。主条末的 n 是实际参与基线计算的有效内容数；次条 n 是参与次指标的带有效评论内容数，均不是评论条数。

缺少评论不能补成中性或零分。评论不足时，次指标显示“评论样本不足”，仍可查看内容证据。点击分组后复用同一抽屉，分别列出内容证据与采样评论，各自计数；不在图中突出覆盖率，不展示情感偏移量。

双指标图已经存在。正式情感判定、权重、混合比例、最低样本量和内部覆盖门槛仍需产品与数据团队确定，不能直接把 Demo 参数作为生产算法。

## 6. 设计和研发应沿用什么

当前 kol-next Demo 已经具备上述页面与主要交互，是本版设计和实现的起点。继续复用原 VOC 的卡片、图表、词云、表格、分页和抽屉；优先调整父层分组、数据映射与组件状态，不重新搭建一套视觉体系，也不改动旧 VOC 页面。

视觉保持浅灰页面、白底卡片和现有标题样式。适合配对的模块继续半屏并排，创作者图与其他卡片的背景、标题和间距一致；地图、摘要和趋势保持整体。具体尺寸和组件规则见 [Design v1](design_v1.md)，沿用 kol2.0 设计规范。本期只做桌面端。

设计需覆盖有数据、加载、空结果、失败重试、评论不足、部分覆盖、地区缺失及延迟/过期状态。提示保持简短：缺地区时地图给出空态但保留摘要；缺评论不影响内容展示；过期数据保留原观察时间；无结果仍能清除条件。不能用零值或空白卡片掩盖不可用。

研发接入真实数据时，应让指标、图表和表格来自同一范围的快照，并保留内容ID、评论ID、父内容关系和数据时间。全局聚合计算完整筛选后的集合，不能只统计当前一页。品牌身份、权限与范围由服务端确认，不能把已有 Brand 参数直接当作旧 VOC 查询身份。

## 7. 接下来需要定案的内容

页面和交互可以基于现有 Demo 继续评审与拆分任务。进入真实数据及上线开发前，以下规则需要形成明确结论：

| 议题 | 需要共同确认的重点 |
| --- | --- |
| 品牌范围、入口和权益 | 品牌身份映射；市场与语言含义；允许的数据范围；正式入口、返回和无权限/到期状态 |
| 评论采样与更新 | 头部内容选取规则、每条内容采样量、去重与回补；各图表的样本资格和不足降级；刷新及延迟/过期规则 |
| 情感与创作者算法 | 情感是否针对品牌、未知判定、模型版本；权重、混合比例、有效样本及覆盖门槛 |
| 时间与曝光 | 统一时区和窗口；是否纳入旧内容近期取得的评论；跨平台观看字段可比性和真实历史曲线 |

后续品牌化增量单独推进：**提及类型**区分自然提及、疑似推广和未知，但不能据此认定真实合作；**主题关联**用稳定主题键连接内容与采样评论；**近期观察**最多呈现三项有证据、可比较的事实，样本不足时省略。这三项尚未开发，需要先确定判定和计算规则。

竞品对比、达人发现、收件箱、工单、通知、真实导出和移动端不纳入当前范围。
