# 爆款视频识别：数据组交接说明

更新：2026-10-27。面向算法、数仓，可独立阅读。

页面方案已与设计、前后端和测试完成评审。**数仓按当前规则接入计算与更新；算法审查当前方法，后续迭代定义、参数及其与聚星数据的适配。** 本期预计不大改公式，后续优化不作为本期接入前置。

## 一、双方共同使用的当前规则

本期“爆款”只表示：**一条视频的播放量明显突破该作者以往同类作品的常态。** 不判断全平台热门，不预测未来表现。

```text
V = 目标视频有效公共快照中的累计播放量
B = 同平台、同作者、此前同内容形态作品的有效累计播放量中位数

当数据充分、B > 0，且 V ≥ 10 × B 时，判为爆款。
```

例如，B为10,000，V为100,000即命中；99,999不命中。按原始值计算，不用显示时的四舍五入值。点赞、评论、分享、收藏及粉丝数不参与公式或补算。

**历史样本：** 发布时间早于目标视频，同作者、同形态；剔除自身、重复及不合格数据，再由近到远取最多L条，不足N条不判定。B须按这批样本计算，不能直接使用全频道现成的平均值或中位数字段。历史样本不受90天计算期限或页面30/90天窗口限制，也不要求自身是爆款。

| 参数 | 当前取值与状态 |
| --- | --- |
| 突破倍数K | 暂按10倍执行，等于10倍也命中；后续可校准 |
| 历史数量L、N | 最多20、至少10条**仍为候选，尚未定稿**；接入前由产品与数据组确认 |
| YouTube普通长视频 | 所选快照须采于发布满7天（168小时）后，暂定 |
| YouTube Shorts、TikTok视频、Instagram Reels | 所选快照须采于发布满3天（72小时）后，暂定；四类内容分别比较，不混算 |

最低时长同时约束目标及历史样本，按**实际采集时间减发布时间**计算。今天已满7天，但唯一快照采于第2天，仍不满足。直播、非视频不参与；未知形态不能默认归入普通视频。

每条作品选一条评估截止时点前的合格公共快照。**不要求同日采集或相同发布年龄，不推算“发布后第3/7天播放量”。** 快照不因采集较早自动失效，仍须验证形态、时间、播放口径和来源。

## 二、数仓：本期如何计算、更新和交付

### 计算与更新

1. **目标限发布后90天（90×24小时）内。** 入队和执行前均检查；恰好90天可算，超过则停止自动首次计算、重算及重试。缺失、非法或未来发布时间不入队，不能用首次发现时间重置期限。
2. **合格公共数据更新后增量计算，日更为产品目标。** 相同输入/规则的成功结果复用；基准变化只处理期限内关联目标。新快照首次跨过3/7天门槛，即使播放未变也需检查资格。
3. **无新数据保留原结果与真实时间。** 不要求每日全量重算，不承诺每条视频每日采集。监控私有修正和连续增长曲线不参与公共判定，页面查询不触发计算。
4. **超龄停算，保留全部已发布判定与依据。** 不自动改成未达标、过期或撤销；旧作品仍可用已有合格快照作历史参考，不因此补采或重算。期限内开跑的任务可完成，不派生超龄重试；迟到数据、基准变化或规则升级也不重开超龄任务。

### 判定结果与异常

| 情况 | 结果 |
| --- | --- |
| 数据充分、B为有限正数，且达到10倍 | 命中 `qualified` |
| 数据充分，但未达到10倍 | 未达标 `not_qualified`；真实播放量0不是缺失 |
| 目标快照采集时未满最低发布时长 | 待观察 `pending` |
| 历史不足、B为0/异常，或关键播放、时间、形态不可信 | 数据不足 `insufficient_data`；不加平滑值、不用其他指标补出命中 |
| 已确认直播、非视频等排除形态 | 不适用 `not_applicable` |
| 尚未纳入结果服务 | 未覆盖 `not_covered`，不伪造一条判定 |

受限、显式停用或撤销不计当前命中；服务失败单独报错。超龄后无结果或仍为待观察/不足时，保留真实原因并注明已停算，不再暗示继续观察。

### 需要交付给业务服务的数据

按“平台＋原生视频ID”去重，内部继续保留类型 `account_breakout`。每次结果至少能追溯：

- 视频、作者、形态、发布时间；V、B、倍数、历史样本数；各样本ID、发布时间、播放量及采集时间。
- 实际采集、评估和计算时间；计算截止时间及是否结束。
- 规则参数与版本、快照选择政策、结果批次/版本；判定状态、有效性及不可用原因。

**各页面读取同一套公共结果，前端不算标签、基准或倍数。** 翻页固定结果版本；发布失败保留上次成功结果和实际时间。权限裁剪、查询及分页由后端与数仓对齐，不能只交一个爆款布尔值。

| 数据消费场景 | 与计算有关的约束 |
| --- | --- |
| 新榜单 | 仅近90天发布的当前有效命中；按发布时间筛选近30/90天，默认30天。按判定快照V降序，再按发布时间降序、原生视频ID固定字典序升序；倍数不参与排序 |
| 视频搜索、频道内容、监控、品牌资产 | 保留原业务范围和排序；页面筛选不改变历史基线 |
| 频道搜索“近期有爆款视频” | 默认不限即不加条件；选近30/90天时，作者在该发布时间窗口至少有一条可访问的有效命中。作品无需匹配频道搜索关键词，不改变原关联视频展示 |

30/90天按固定截止时点回推连续小时，含起止边界；新查询/发布时推进窗口，不依赖视频重算。先过滤、统计与排序，再分页；覆盖率按完整业务范围计算，未检出不等于已评估且无爆款。

## 三、算法：审查当前方法，后续如何迭代

**本期审查公式与数据是否适配，核对10倍、3/7天及L/N配置。** 发现影响正确性的缺陷时，与产品、数仓对齐修订；无需先完成新模型才开始接入。

已知局限：目标与历史的发布年龄、采集时点不同；低基数易出现大倍数；历史不足降低覆盖。因此命中不能证明内容质量、自然流量或作者持续能力。

后续以三平台真实样本评估误报、漏检、有效发现及覆盖，再优化定义与方法。**新规则另建版本，保存配置、样本及旧判定，不覆盖历史依据。** 新类型/业务含义与产品另行对齐，历史回算另定范围与成本。广泛热门、监控曲线增长爆发和预测均不纳入本期。

## 四、接入前待确认

- **产品＋算法＋数仓：** 确认L/N最终值；10倍与3/7天作为本期暂定参数记录版本。
- **数仓＋算法：** 确认来源字段、历史覆盖、快照质量与选取政策，字段同名不等于口径相同。
- **数仓＋后端：** 确认更新/发布链路、延迟、重试与交付字段；联调10倍边界、零基线、样本不足、早期快照、90天停算及重复更新。

本文摘述当前交接规则，不代表生产链路或算法效果已验收。详细边界与结果契约统一维护在[计算规则SPEC](计算规则_SPEC.md)；页面与模块需求见[README](README.md)。
