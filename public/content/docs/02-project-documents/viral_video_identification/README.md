# 爆款视频识别

帮助品牌从视频表现中发现值得进一步了解的作品和作者：可以直接找视频，也可以筛选“近期有爆款视频”的作者；没有明确关键词时，从榜单浏览。

**这是爆款内容方向的第一版，以“榜单 + 筛选与标记”建立发现入口。榜单页面方向与本期改造原则已确认；真实识别数据尚未接入，计算参数、近期监控规则及正式排序仍需评审。**

## 为什么做这一版

品牌寻找合作作者时，除了按频道条件筛选，还需要从具体作品判断哪些作者值得进一步了解。作品的一次突出表现，可以成为发现新候选、补充了解已有候选的线索。本版希望把这条线索放进聚星现有的发现与分析流程，让用户能够从“找到一条表现突出的作品”继续了解作者和相关内容。

现有的播放量、互动量、粉丝数和监控增长等指标，分别描述作品规模、互动或变化情况。要判断一条作品是否突出，还需要知道它与谁比较、在什么时间条件下比较。直接按播放量排序，不能完整回答“同类中是否突出”和“是否突破作者常态”这两个问题。因此，本版增加一套可解释的视频识别结果，并让不同页面使用同一口径。

这条产品线先完成榜单和既有页面的筛选、标记及依据展示。自定义爆款规则、进一步的爆款内容分析属于后续方向，尚不构成本期承诺。本期也不把作品入选直接解释为作者持续创作能力、合作效果或转化保证。

## 用户会在什么情况下使用

| 用户当前的任务 | 本版提供的帮助 | 用户接下来做什么 |
| --- | --- | --- |
| 还没有明确关键词，希望先浏览某个平台或领域 | 从爆款榜单查看已识别的突出作品，按范围逐步收窄 | 看作品与识别依据，再了解作者 |
| 已有主题或作者条件，希望提高候选的针对性 | 视频搜索增加爆款条件；频道搜索增加“近期有爆款视频” | 保留原搜索条件，检查命中作品是否符合合作需求 |
| 已有候选作者或正在分析品牌内容 | 在频道内容、品牌资产中直接看到作品标记与依据 | 在原分析流程中进一步比较，不另开一套工作台 |
| 正在持续观察一批内容，希望发现近期突出表现 | 在内容监控原有列表中并列展示识别结果与监控指标 | 区分近期表现、累计表现与数据不足，再决定是否继续跟进 |

这些场景都以发现和理解作品为起点。标签提供进一步查看的理由，合作判断仍需结合内容相关性、作者情况和品牌需求。频道搜索的“近期有爆款”默认描述作者近期作品，不保证导致入选的作品与搜索词相关；这层区别在命中作品中说明。

## 为什么采用两个判断、两种用途

### 两个判断分别回答什么

| 判断 | 用户要知道的事 | 为什么要单独保留 |
| --- | --- | --- |
| 广泛热门 | 这条作品是否在可比的同类视频中表现突出？ | 帮助用户从同类内容中找到值得关注的作品 |
| 账号突破 | 这条作品是否明显超过该作者的日常表现？ | 帮助用户看到单看绝对播放规模容易忽略的异常突出作品 |

例如，大号的一条高播放作品可能处于自己的日常水平；小号的一条作品可能明显超出自身常态，但传播规模仍有限。这两种线索对发现作者都有价值，应分别表达，允许同时命中，不合成一个“爆款总分”或作者评级。数据不足、尚待观察与未达标也分别说明，避免把不能判断当成表现不佳。

“广泛热门”是当前 UI 名称。同体量、同分类中的高位是否足以使用这个名称、是否还需要最低传播规模，是规则评审的待定项；不能仅从名称推断已具备全平台热度。

### 两种用途为什么不能直接套同一公式

| 用途 | 面向的内容 | 设计重点 |
| --- | --- | --- |
| 搜索、榜单等公共存量内容 | 大规模公共视频库 | 在可比观察条件下识别，按批次提供稳定、可追溯结果 |
| 内容监控的近期识别 | 用户正在监控、可连续观察的内容 | 识别已经发生的近期突出表现；具体比较指标与窗口待定 |

存量发现更关注作品在可比条件下的表现，监控还需要回答“最近是否出现了突出表现”。发布两天作品的累计播放、成熟作品的终身累计播放，以及最近一天的新增播放，不能直接放在同一门槛下比较；能取得哪些真实观测，也决定了可以回答什么问题。因此，两种用途共享结果结构，分别确定观察条件和规则，不要求所有视频统一等满七天。

“近期监控”不等于预测，“近 30 天有爆款”也不等于实时发现。采集时间、算法观察窗口、页面的发布时间筛选与结果更新时间各有用途，需要分别说明。

## 本版已经作出的关键取舍

1. **优先补齐发现链路。** 新增榜单承接没有明确关键词时的浏览；视频与频道搜索承接有条件的查找；频道、监控和品牌页面承接后续查看。除榜单外，沿用原页面，只增加必要的筛选、标签、简短统计与依据入口，以保持用户原有工作方式。

2. **主判断保持简单，解释能够复述。** 以原始播放表现和可比对象为核心，互动指标作为补充观察。避免未经验证的固定权重、综合分或“爆款原因”推断，让用户能理解入选依据，也便于研发校准规则和定位误报。具体倍数、分位与最低样本量仍是候选参数。

3. **先统一结果，再由各页面消费。** 同一视频在相同用途、观察范围、批次和权限下，应有一致的结果与依据。服务端负责计算、发布结果及授权范围内的证据，前端负责查询和展示；用户切换页面筛选，不应临时改变参考群体、重算门槛或生成另一套标签。不同用途的结论可以不同，但必须说明上下文。

4. **保留已有指标的业务含义。** 旧视频分数、监控增长与品牌“爆款制造率”各有比较对象和历史用途，不能直接换名成为新视频标签。新识别与它们并列展示，避免用户在不知情时读到已经改变口径的历史指标。具体差异与代码证据保留在[结论汇总](保留结论汇总.md)中。

5. **先确认呈现方式，再用真实数据冻结规则。** 榜单 Demo 用确定性样例讨论页面组织、状态和依据表达，不证明算法有效或生产数据可用。其它模块通过 SPEC 交付，不继续制作 Demo。当前候选参数还需要按平台、内容形态验证覆盖、有效发现、误报和稳定性；缺少必要数据时明确返回不足，不补造结论。

6. **相关内容搜索按现有 AI 能力设计，允许本期不交付。** 从单条视频提取准确的主题与限定词，复用“AI推荐关键词”能力，用户确认或修改词后进入同平台视频搜索。它提供搜索线索，不保证找到相同创意或同类爆款。研发评估排期、输入数据与推荐效果后决定是否启用；情况不允许则隐藏整个入口，不阻塞榜单、筛选与标记交付。详见[榜单 SPEC 第 7 节](榜单页_SPEC.md#7-跨页承接与可选-ai-推荐关键词)。

因此，研发可以依据本文和三个 SPEC 讨论页面范围、公共结果协议与接入分工，但不能把 Demo 中的数值、排序键或候选公式直接作为生产定案。**已确认的是产品方向和约束；仍待确认的是可用数据、具体规则参数、正式排序及刷新能力。** 下方 checklist 标记交付与验收状态，待定项集中列在后文。

## 本期边界

榜单保留 Demo 作为参考，其余功能在真实页面中小幅修改，不再做独立 Demo，不重做原页面 UI。

单视频“AI推荐关键词”是本期可选增强，按复用已有能力设计；不单独建设相似视频引擎，不把全榜单筛选直接跳转搜索当作它的替代实现。研发来不及、数据不足以支撑或推荐效果不满足要求时，整项隐藏；用户在已启用能力中遇到个别视频无有效文本，则不生成推荐，不伪造关键词。

频道推广视频、品牌合作/商品抽屉、监控任务详情和相关推荐有复用价值，已列为建议补齐项；TT 带货视频、收藏作者、相似网红、营销项目找作者及品牌/项目聚合继续按接口条件评审，不能因共享组件就默认全部接入。

本期不包含：预测、自动预警、AI 原因分析、复制建议、用户编辑算法权重、作者综合评分、跨平台总榜、交易爆款或独立视频收藏库。已有 `video_score`、监控增长和品牌“爆款制造率”保留各自含义，不替换成新标签。
