# 爆款视频识别：计算规则 SPEC

更新：2026-10-27。适用平台：YouTube、TikTok、Instagram。

**已确定账号突破判定、数据边界和结果消费方式；突破倍数当前暂定为10×，后续可校准调整。** 最低发布时长暂定为YouTube长视频7天、Shorts/TikTok视频/Instagram Reels 3天；排序已确定为判定快照累计播放量降序、同播放量优先较新发布时间、再以稳定ID确定顺序。本期快照不设按时间自动过期的门槛，目标视频发布超过90天后停止自动计算，保留历史判定；日更为产品目标，允许由公共视频数据更新触发增量计算；历史样本量、快照来源/质量、触发与发布延迟的实现仍待确认。10×是当前方案口径，不代表完整算法或真实效果已通过生产验收。

## 1. 计算目标与命名

| 判断 | 协议键 | 要回答的问题 |
| --- | --- | --- |
| 账号突破 | `account_breakout` | 相对该作者此前同形态作品的累计播放常态，是否明显突破？ |

本期只保留“账号突破”一个判断：作品是否突破作者常态；不将命中解释为大范围传播，不合成综合分或作者评级。用户界面隐藏类型名，普通列表统一显示“爆款”、依据显示当前结论；`assessments.account_breakout` 及相关查询/存储类型标记继续保留，不将评估字段拍平为无类型布尔值。未来新增类型需另外明确界面组织。

一期识别已经发生的表现，不预测未来、不自动预警、不生成因果解释或复制建议。算法使用原始播放；点赞、评论、分享、收藏只作补充观察和解释，不参与本版主标签，不因可选互动字段缺失自动否决。

## 2. 本期统一计算范围

本期仅交付公共识别服务的“账号突破”结果。榜单、搜索、频道、品牌资产和内容监控均消费同一公共结果契约，不为内容监控另建近期增量公式或其他判定。

- 服务端按公共数据的可比观察条件和版本化配置计算、发布批次；各页面只查询已有结果，不临时重算或更换作者历史基线。
- 内容监控沿用独立采集和原增长指标，但连续曲线不作为本期新增爆款判定的输入；项目私有修正不回写公共结果。
- 监控列表当前指标与公共结果快照不同时，依据分别标明实际判定指标和时点，不能按最新监控值补算标签。加入监控不保证立即有公共结果，也不自动加速公共采集或触发判定。
- 本期不承诺公共数据对新发布视频前 48 小时的高覆盖及时识别。没有结果时按事实返回未覆盖、数据不足、待处理或受限；服务失败单独处理，不把缺结果都补成待观察。

**2026-10-26 已确认采用累计快照比较，不再要求严格同发布年龄。** 目标视频须达到按平台/内容形态确定的最低发布时长后再评估；2026-10-27 已暂定YouTube长视频7天、Shorts/TikTok视频/Instagram Reels 3天，后续可校准调整。这个条件用于减少过早比较，不代表公共采集能在该时点及时更新。

## 3. 公共存量内容的简明计算规则

### 3.1 账号突破

```text
V = 目标视频所选有效快照中的原始累计播放量
B = 同作者此前同形态历史作品所选有效快照的累计播放中位数
暂定命中条件：V >= B × K，当前 K = 10
```

历史作品须满足同平台、同作者、同内容形态、同累计播放口径，且发布时间早于目标视频；剔除目标视频自身及重复视频。目标和历史作品的所选快照均须符合最低发布时长及快照有效性政策。按发布时间倒序取最近符合条件的历史，最多取 L 条；不足 N 条不能计算。

- 最低发布时长按“指标实际采集时点 − 作品发布时间”判断，不能按今天的年龄代替。视频虽已发布很久，但可用快照采于发布早期，不能据此声称达到条件。最低时长按第3.2节的暂定配置执行，等于门槛即满足；时间条件满足后仍须通过播放与样本等其他判定。
- 在评估截止时间之前，为各视频选择一条符合配置的有效公开累计快照；不要求它们同一天采集或处于同一发布年龄，但必须保存真实观测时点及快照选择政策。缺失关键时间/形态等无法验证时返回数据不足。
- 已知所选目标观测尚未达到已配置的最低发布时长时，可返回 pending 并说明“待观察”；历史样本不合要求则剔除，剔除后不足返回 insufficient_data。结果尚未覆盖、受限或请求失败仍按各自状态处理，不都改成待观察。

- 2026-10-26 已确认当前倍数先按 K=10 执行，等于10倍也命中；后续根据真实样本校准再调整，不在本轮继续讨论倍数。
- 历史数量 L=20、N=10 仍是候选，尚未确认；10×及最低发布时长的暂定不代表历史数量或完整算法同时定稿。
- B 必须是有限正数。B=0、缺失或异常时返回数据不足，不靠除零、平滑项或粉丝数补出命中。
- 服务端保存 B、样本数、最低发布时长/快照选择政策、观测时点、V 和原始倍数，页面只展示已授权证据；倍数不是榜单排序公式。基准 B 对应 `evidence.baseline.medianViews`（原始播放中位数），配套样本数、作者/形态、累计快照比较口径及已计算的 `multiplier`。如保留 `observationAge`，只记录实际发布年龄或说明，不再表示已做同龄匹配；服务端应可追溯各历史样本的身份、发布时间、快照值与采集时点。列表与抽屉同源读取，不从当前指标反推基准/倍数，也不回退成全频道当前平均播放。

### 3.2 参数与观察前提

| 参数 | 当前口径 | 待确认或后续校准 |
| --- | --- | --- |
| 账号历史数量 | 最多 20，至少 10 | 三平台同形态、符合最低发布时长的历史快照覆盖 |
| 账号突破倍数 | 暂定10倍（本轮已确认，后续可调） | 后续根据人工有效发现率、低基数误报与规模偏差校准 |
| 最低发布时长 | YouTube长视频7天；Shorts/TikTok视频/Instagram Reels 3天（2026-10-27暂定，后续可调） | 真实样本校准及按形态配置落地 |
| 快照有效性 | 不因距今较久自动失效；仍需满足采集时最低发布时长、字段与口径要求 | 真实来源、质量与取点实现；采集较早不代表实时表现 |
| 目标计算期限 | 发布后90天内，超过后停止自动首次判定及重算，保留已有结果 | 服务端任务筛选、执行检查与历史归档落地，详见第3.4节 |
| 结果更新 | 日更为产品目标；允许视频公共数据更新后触发增量计算，不要求每天固定全量重算 | 事件/队列接入、合并去重、处理及发布延迟、失败提示与成本；不承诺每条视频每日采集，快照不设时间TTL |

最低发布时长按连续经过时间计算，不按自然日取整；配置须随规则版本保存，统一作用于目标视频和历史参考样本。

| 平台／形态 | 暂定最低时长 | 实施参数 |
| --- | --- | --- |
| YouTube 普通长视频（`youtube_video`） | 满7天 | 168小时 |
| YouTube Shorts（`youtube_short`） | 满3天 | 72小时 |
| TikTok 视频（`tiktok_video`） | 满3天 | 72小时 |
| Instagram Reels（`instagram_reel`） | 满3天 | 72小时 |

这些是参与评估的最低门槛，不是固定取点；达到门槛且仍处于第3.4节90天计算期限内时，才可使用符合政策的新快照继续判定。目标在门槛前即使已达到10倍也先待观察；达到门槛不会自动命中或承诺立刻采集。直播/非视频仍按原排除规则处理；未知或未配置的形态不擅自套用其他形态的值，需按形态确认与配置就绪情况处理。

本期明确比较累计播放快照，不声称是同龄、等时长增长或生命周期最终播放比较。目标与历史的发布年龄和采集时点仍可能不同；最低发布时长只能减少过早比较，不能消除年龄及采集延迟偏差。不倒推“发布后第7天播放”，不按天数线性折算，不预测最终播放量，也不据此承诺早期增长识别。

### 3.3 榜单视频的发布时间范围（2026-10-27 已确认）

本节限定新榜单的候选与查询范围，不改公共账号突破的10倍判定，也不作为快照采集有效期。

| 项目 | 口径 |
| --- | --- |
| 榜单候选最大范围 | 在当前榜单批次截止时间evaluationAsOf之前90天内发布的目标视频，同时满足既定资格、3天/7天最低发布时长和排序数据要求 |
| 用户时间筛选 | 按视频发布时间，只支持近30天（30d）或近90天（90d） |
| 未选、缺省与清空 | 均为近30天；控件明确显示该默认值，不提供“不限”或近7天 |
| 时间边界 | 连续30×24/90×24小时，包含下界与截止时刻；未来、缺失或无效发布时间不可入榜。批次截止时刻固定，翻页不改按浏览器当前时间回推 |
| 作者历史参考作品 | 不受榜单90天或用户30天窗口限制，继续按此前同作者、同形态、最低发布时长及快照有效性政策选样本；用户改时间筛选不重算基线 |

90天外的视频不进入本榜候选，但不因此改写其公共识别状态为未达标或过期；其他模块仍按其原业务范围消费保留结果。榜单候选上限、用户发布时间筛选、3天/7天采集时年龄门槛与计算期限是不同条件：本期快照不按时间自动过期，成本由第3.4节的目标计算期限控制。

服务端先按固定批次、90天上限和用户选定的30/90天范围筛选，再排序、计数及分页；缺省参数按30d处理，生产接口非法值按参数错误处理。Demo旧7d、any等时间值会改为30d并提示，保留其他有效条件，不能以“兼容”为名恢复不限范围。API及生产范围过滤尚未接入，Demo只在完整固定样例中模拟这些范围。

### 3.4 计算生命周期与历史保留（2026-10-27）

为防止待计算对象随存量无限累积，本期将公共账号突破的目标计算期限统一设为发布后90天。它作用于所有模块共用的服务端计算，不仅是榜单查询条件；其他页面的发布时间筛选不因此收窄。

| 场景 | 规则 |
| --- | --- |
| 正常计算 | 任务运行时刻T减发布时间不超过90×24小时，且满足第3.2节采集时最低发布时长及其他数据条件；恰好90天仍在期限内 |
| 发布时间不可验证 | 缺失、非法或未来发布时间不能进入本功能的自动计算、重试或补采队列；保留数据不足原因。既有业务链路修复可信发布时间后，再按实际年龄检查准入，不能用首次发现时间或更新时间替代 |
| 超过90天 | 停止自动首次判定、定时重算、数据更新触发重算和失败重试；即使此前未产生结果，也不补开首次计算 |
| 入队与执行 | 服务端在生成候选任务和实际执行前均检查期限；排队期间已超龄则跳过，不执行后再丢弃结果。不能用旧批次evaluationAsOf重新打开已超龄视频的计算资格 |
| 迟到数据与规则换版 | 超龄后收到新快照、作者基线变化或规则升级，不自动重算该目标。若未来需要历史回算，单独定义有界任务范围和成本，不作为本期常规链路 |
| 历史基线 | 超龄作品仍可作为新目标的历史参考，使用已有符合条件的快照；不要求参考作品自身有爆款结果，不因此给它新建判定、周期刷新或强制补采任务 |
| 其他模块与采集 | 搜索、频道、监控、品牌及详情读取已有结果，不通过查看、筛选、加入监控重开资格。该规则只关闭本功能的计算/补采需求，不停止其他业务原有采集 |

入队与执行按固定服务端时刻检查；期限内已开始的单次任务允许完成，保存实际计算时间，但超龄后不得派生后续重算或重试。期限内对相同有效输入和规则的成功结果直接复用，重复消息或单纯时间流逝不重复计算；新数据、首次判定或配置变化仍须通过期限检查。

快照本身不因采集已久自动失效；仍需验证形态、发布时间、采集时年龄、指标及来源口径。数据修正、无效来源、权限和规则不兼容等限制按原契约处理，不能把“不设TTL”解释为任何快照均可用。

结束计算不改变assessment.status，也不自动把freshness改为stale或validity改为invalidated。保留最后一次判定及全部已发布历史版本，包括所用V、B、倍数、样本身份/快照、实际评估时点和规则版本；不能把新目录/批次的发布时间冒充该视频重新计算时间。

其他模块可在权限及版本兼容条件下继续读取保留的命中，并在依据中说明实际判定时间和已停止更新；超龄本身不是新爆款类型，不增加一套筛选或标记。最后结果是pending/数据不足，或此前从未有结果时，说明“已超过识别期”及实际原因，不暗示还会继续自动观察，不伪造未达标。服务端需提供可追溯的计算截止时间、是否已结束和最近实际计算时间（字段名接口评审对齐），前端不以当前播放量重算。

普通刷新不会改写既有历史判定。来源纠错或明确撤销另存修订/撤销记录；冻结保留不阻碍纠错，但不得借此恢复无限期例行计算。

### 3.5 日更目标与数据更新触发（2026-10-27）

产品目标是爆款结果日更；实现允许在公共视频数据更新后触发该视频的增量计算，不强制每天固定时刻全量扫描、重算或等待每日一次统一计算。日更不等于承诺每条视频每天取得新快照，也不保证某次采集请求同步返回新判定；实际处理及发布延迟由研发确认。

- 公共新快照通过质量校验且目标仍在90天计算期限内时，可触发计算；同输入/规则的重复更新复用已有成功结果。仅修改任务更新时间、重复写入同一次观测或无关可选互动字段变化，不因此重复计算相同判定输入。新可信观测即使播放量不变，但采集时年龄首次达到3/7天门槛，仍属于可改变资格的有效输入。
- 没有新有效数据时保留原快照与结果，不为凑日更刷新采集/评估时间。仅视频今天满3/7天，但已有快照采集时尚未满门槛，仍不能改成可判定。
- 作者历史样本补齐或基准变化时，只在仍可计算的关联目标内处理依赖；触发、合并及重试策略由研发落实，不能因此全量回算超龄目标。新结果必须保存本次实际使用的基准与快照。
- 内容监控私有数据更新不触发公共重算；页面查看、筛选或刷新也不触发。超过90天、时间不可验证及失败重试边界仍遵守第3.4节。

计算触发与对外结果发布分开。结果批次/版本用于一致读取，不要求每条更新都重发全量，也不要求必须日末发布；可采用增量结果与稳定读取上下文或合并发布，具体实现由研发评审。榜单、搜索、频道聚合及依据必须在同一上下文读取一致的已发布结果，翻页期间不混入新版本；实际采集时间、实际评估时间与结果发布/榜单更新时间分别记录，不以一个时间冒充全部数据已刷新。

即使没有新判定，榜单和频道筛选的30/90天范围也要随新查询/新发布上下文的截止时点推进，不能依赖某条视频下一次更新才移出超出窗口的作品；本次翻页仍固定原上下文。日期范围维护不重算旧视频的爆款判定。上述均为SPEC要求，事件链路、发布时延及生产验收尚未完成。

| 输入/情况 | 要求 |
| --- | --- |
| 身份 | 平台+原生视频 ID 为视频去重键；作者关系、内容形态和源字段可追溯 |
| 榜单频道国家 | 沿用频道榜的频道记录国家归属；频道国家可空，需与视频作者可靠关联。不用视频市场、受众、语言或IP补值；全球不加国家限制，具体国家只匹配该归属。国家只限定查询范围，不改变作者历史基线或阈值 |
| 内容形态 | YouTube 普通视频/Shorts 分开，直播暂不参与；TikTok 确认为视频；Instagram 确认为视频/Reel。已确认非视频或排除形态返回 `not_applicable`；形态缺失/不可靠返回 `insufficient_data` 并说明无法确认，不默认归为普通视频 |
| 核心播放 | 保留原值与口径版本；缺失/非有限/负值不可计算，真实 0 不当缺失 |
| 时间 | 分开保存发布时间、指标观测时点、评估截止时点、计算完成时点；时区统一，异常未来时间不可用 |
| 多任务同视频 | 同批次只取一条稳定、完整且满足最低发布时长和快照政策的观测；保存取点规则，不按任务重复加权 |
| 可选互动 | 缺失保留未知，不填 0；不回退为点赞算法或固定互动率否决 |
| 历史数据 | 不用未知形态、混合帖子均值、当前粉丝数补造历史快照或累计播放基准 |
| 结果修正 | 指标/来源修正后可重新发布结果；保留旧上下文和撤销记录，不改写历史报告 |

前端不计算中位数、倍数、判定门槛或排名。旧 `video_score`、监控 `hotLevel` 和品牌 `topVideoRate` 保持原义，均不能直接映射为新标签。

## 6. 统一结果与可用状态

### 6.1 上下文与结果字段

| 层级 | 必须保存的语义（字段名可在接口评审中对齐） |
| --- | --- |
| 结果上下文 | `contextId`、计算用途/配置、观察范围、最低发布时长及快照选择政策版本、`batchId`、`resultVersion`、`evaluationAsOf` |
| 视频身份 | `videoId`、`platform`、`contentType`、作者关系、发布时间、`metricObservedAt`、计算完成时间 |
| 计算生命周期 | 目标计算截止时间、是否已结束、最近实际评估时间；与assessment判定及榜单批次时间分开，见第3.4节 |
| 读取边界 | `accessStatus`、允许读取时的 `coverageStatus`；指标及证据按权限裁剪 |
| 唯一识别结果 | 只有 `assessments.account_breakout`；未纳入结果服务时缺省 |
| 账号突破 | `status`、`freshness`、`validity`、`algorithmVersion`、`rankingPolicyVersion`、可空的 `rankKey`、证据与可公开原因 |
| 证据 | 当前值、比较对象/定义版本、样本量、基线/阈值、观察时点和数据限制；未知与 0 分开 |

同一视频、计算配置、观察范围、批次、版本和权限上下文中，搜索、榜单、频道、品牌及内容监控读取一致的公共结果。上下文字段保留用于配置与追溯，本期不据此新增监控近期模式或额外判定。

### 权限继承原则（2026-10-27 已确认）

新增榜单沿用现有榜单的权限设定，包括既有游客/登录、套餐及可见范围限制；具体值读取现有配置，不为本功能重新制定一套。其他模块的爆款筛选、标签、基准及依据随原模块提供，不新增独立权限、套餐门槛或爆款次数额度，也不在可访问模块中单独锁定爆款功能。

原模块/项目/数据的可见范围与既有操作配额继续生效。`accessStatus=restricted`表达这些既有访问限制，不表示新设爆款权益；服务端授权、字段裁剪与聚合去泄漏要求保持。搜索、导出、加入监控和主动AI调用的既有权限/额度不因接入爆款改写；只读爆款展示与依据不增加独立扣量。

### 6.2 正交状态

| 字段 | 取值与含义 |
| --- | --- |
| `status` | `qualified` 命中；`not_qualified` 数据充分但未达标；`pending` 等待所需观测/处理；`insufficient_data` 缺少可信核心数据/样本；`not_applicable` 不适用形态 |
| `freshness` | 保留`fresh` / `stale`兼容与扩展；本期不因快照/判定年龄或计算期限结束自动转stale。服务端明确停用的旧结果仍按stale处理，不能由页面猜测 |
| `validity` | `valid` / `invalidated`，撤销不改写成未达标 |
| `accessStatus` | `allowed` / `restricted`，优先于内容/证据展示 |
| `coverageStatus` | `full` 账号突破已纳入结果服务；`none` 账号突破未纳入结果服务。它只描述该视频是否纳入唯一判定的结果服务，不代表已经完成评估、数据充分或作者聚合范围完整 |

“待观察”是 `pending` 的可读原因，不新增另一套命中枚举。`not_covered` 是缺省账号突破结果的不可用原因，不冒充 `pending`；缺失结果不补成未达标。受限时覆盖信息若不可公开应省略，不能推断为未覆盖。

当前可消费命中 = 适用视频、允许读取，且账号突破 `qualified + fresh + valid`。本文“当前有效”指结果仍可使用，不代表最近重算；超90天结束计算不自动撤销命中。显式stale/撤销不计当前命中，历史结果保留原时点；榜单还需另满足90天范围。

### 6.3 合法读取响应示例

以下为简化契约示例；`contextId` 必须可解析到 6.1 的完整固定上下文。未覆盖不返回伪造 assessment，请求失败不返回成功的“暂未覆盖”。

```json
{"ok":true,"contextId":"ctx-a","videoId":"v1","platform":"youtube","accessStatus":"allowed","coverageStatus":"none","assessments":{},"unavailableViews":{"account_breakout":"not_covered"}}
```

```json
{"ok":true,"contextId":"ctx-a","videoId":"v1","platform":"youtube","accessStatus":"restricted","assessments":{}}
```

受限响应仅保留允许公开的身份与状态，不下发隐藏指标、样本、基线、队列成员、排名键或内部原因码；前端折叠不是权限裁剪。

```json
{"ok":true,"contextId":"ctx-a","videoId":"v1","platform":"youtube","accessStatus":"allowed","coverageStatus":"full","assessments":{"account_breakout":{"status":"insufficient_data","freshness":"fresh","validity":"valid","algorithmVersion":"a1","rankingPolicyVersion":"r1","rankKey":null}}}
```

```json
{"ok":false,"error":{"code":"RESULT_SERVICE_UNAVAILABLE","retryable":true}}
```

服务端返回 HTTP/错误语义需评审；失败时页面保留原列表和原已取得状态，依据区提供重试。`full` 响应只含账号突破 assessment；上例即使纳入服务仍可数据不足。`none` 响应不返回该 assessment，并明确 `not_covered`；无权字段始终不下发。

## 7. 账号突破展示、筛选与统计

| 账号突破结果 | 当前展示 | 只看爆款 |
| --- | --- | --- |
| `qualified + fresh + valid + allowed` 且形态适用 | “爆款”标签与依据（不显示类型名） | 匹配 |
| 有效新鲜的 `not_qualified` | 可说明未达标，无命中标签 | 不匹配 |
| 待观察/数据不足/不适用/未覆盖 | 说明实际原因，不汇总为未达标 | 不匹配 |
| 过期/撤销 | 显示历史时点或失效说明，不贴当前命中标签 | 不匹配 |
| 受限 | 权限提示，隐藏未授权信息 | 不匹配 |

“已评估”表示账号突破数据充分且结果仍可消费（含结束计算后保留的结果，排除显式stale/撤销），包含命中与未达标；“已入选/命中”仅表示当前有效的 `qualified`，两者不混称“已识别”，也不把fresh解释为最近重算。

- 原筛选中的“只看爆款”唯一匹配当前有效账号突破；状态筛选也只查询账号突破，无类型切换或其他判断控件。与不足/待观察等冲突的状态组合不开放，服务端拒绝冲突参数。
- 原业务条件与结果条件在服务端组合后分页；页面条件不影响账号历史基线。不从当前页反算覆盖率、命中数或作者聚合。
- 原有导出按同条件、固定上下文及既有权限/数量规则输出筛选后的原对象，不退回未过滤全集；本期保持原模板，不新增爆款字段或额外榜单导出功能。
- 服务端返回同权限、同业务范围下的适用数、已评估数、有效命中数及未知分母原因。覆盖分母不被“只看爆款”缩成命中集合；按平台+视频去重，不适用对象排除，待观察/不足/未覆盖/过期/撤销留在适用分母。
- 评估覆盖率=已评估数/适用数；分母未知或 0 显示“—”。命中数独立展示；范围不完整时不能把已知命中数当完整总数。此聚合统计与单记录 `coverageStatus` 分开，`full` 不证明全范围数据充分。

## 8. 发布、排名与历史

计算服务发布完整且原子切换的结果批次；失败保留上次成功批次，显示实际更新时间和延迟，不因单条快照年龄自动失效。服务端明确声明批次不可用时提供不可用状态，不冒充新榜；日更目标、数据更新触发及一致发布遵循第3.5节，触发至可见延迟与异常服务策略仍需落实。翻页/下钻使用相同上下文，权限或上下文变化须显式重新查询。新批次可关联保留的兼容结果，但不覆盖记录的原评估时点，不为更新批次时间重算超龄目标。

入选与排名分开：只有账号突破当前有效命中且具备兼容排序键的记录可入榜。2026-10-27 已确认排序顺序：

1. 按本条判定快照的原始累计播放量 V 降序，不用更晚更新的监控值或当前页面指标重排。
2. 播放量相同，按视频发布时间降序，较新发布的视频优先；不是按采集时间或评估时间判断新旧。
3. 播放量和发布时间均相同，按平台原生视频ID的固定字典序升序，保证顺序稳定；服务端明确编码/比较方式，不能依赖数据库默认顺序。

同一筛选范围内使用连续名次，跨页延续，不展示并列同名次。服务端基于固定上下文和完整筛选范围排序后分页，返回名次、`rankKey`/游标及排序策略版本；前端只读取顺序，不能按当前页的指标拼接排序键或自行重排。排序键的编码与接口分页实现仍需研发落地，不因业务顺序确定就视为真实服务已接通。缺键或版本不兼容不由前端补位。解释倍数、点赞、评论不参与本榜排名，突破倍数仅服务入选判断与说明。

上述为新增榜单的顺序；视频搜索、频道内容、内容监控等继续保留原业务排序，旧HOT榜的 `video_score` 含义和顺序也不因此改变。

每次已发布判定及历史报告均保留生成时上下文和依据；当前查询使用最新成功上下文关联可消费结果，原记录不因新批次覆盖删除。超龄退出榜单、停止计算与数据删除分别处理。发布时间、首次命中时间、首次入榜时间不同，未有历史记录就不显示“首次爆款/新上榜”。

1. 公共识别的累计播放口径、暂定最低发布时长的配置落地及快照取点，以及监控消费公共结果的项目权限与时间说明；后续增长爆发不纳入本期冻结项。
