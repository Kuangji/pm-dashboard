# 爆款视频识别：计算规则 SPEC

更新：2026-10-22。适用平台：YouTube、TikTok、Instagram。

**已确定的是判定维度、数据边界和结果消费方式；具体阈值、观察窗口、刷新频率与排序策略尚未冻结。** 本文把确定要求与待校准候选分开，不能把候选数字直接作为上线参数。

## 1. 计算目标与命名

| 用户视角 | 协议键 | 要回答的问题 |
| --- | --- | --- |
| 广泛热门 | `broad_popular` | 在同平台、同形态及可比条件下，这条视频的播放表现是否突出？ |
| 账号突破 | `account_breakout` | 相对该作者同形态、同观察年龄的历史作品，是否明显超出常态？ |

两个视角独立评估，可以同时命中；不合成综合分或作者评级。“广泛热门”是现有 UI 名称，同体量队列中的高位不自动代表绝对大范围传播，最终名称及是否增加绝对规模门槛待评审。

一期识别已经发生的表现，不预测未来、不自动预警、不生成因果解释或复制建议。算法使用原始播放；点赞、评论、分享、收藏只作补充观察和解释，不参与本版主标签，不因可选互动字段缺失自动否决。

## 2. 两种使用策略

| 项目 | 公共存量内容：榜单、搜索、频道、品牌资产 | 内容监控的近期识别 |
| --- | --- | --- |
| 用户任务 | 找到在可比观察条件下已经表现突出的作品 | 发现近期已发生的突出表现或起量 |
| 观察方式 | 比较固定观察年龄/窗口的播放；批量发布可追溯结果 | 使用项目可取得的近期观测；比较指标与窗口尚待定稿 |
| 参考数据 | 公共视频库及可信的同龄历史 | 同权限、同观察条件下的近期数据；不能默认具备公共参考队列 |
| 刷新 | 非实时；频率依据采集能力、成本和结果有效期确定 | 可比存量更频繁，但必须先确认实际观测点和延迟 |
| 当前边界 | 两条简明计算候选见第 3 节 | 近期规则见第 4 节；确认前不发布伪造的新模式结果 |

两种用途共享协议结构，各自保存计算配置、范围、窗口、版本与结果。正式模式名称由研发确认，不把历史示例中的模式名或 2h/24h/72h 等时长视为定案。

**不要求所有视频统一等满 7 天。** 视频是否可评估由所选用途和实际可比观测决定；7 日只能是某一配置的候选校准点，不能成为所有用途的资格门槛。

## 3. 公共存量内容的简明计算候选

### 3.1 账号突破

```text
V = 目标视频在指定观察年龄/窗口的原始播放量
B = 同作者可比历史作品在相同观察年龄/窗口的播放中位数
候选命中条件：V >= B × K
```

历史作品必须满足同平台、同作者、同内容形态、同播放口径、同龄或可验证的相同观察窗口；剔除目标视频自身及重复视频。按发布时间倒序取最近可比历史，最多取 L 条；不足 N 条不能计算。

- 候选起点：L=20、N=10、K=10；三者均待公共样本校准，不是生产默认。
- B 必须是有限正数。B=0、缺失或异常时返回数据不足，不靠除零、平滑项或粉丝数补出命中。
- 服务端保存 B、样本数、窗口、V 和原始倍数，页面只展示已授权证据；倍数不是榜单排序公式。

### 3.2 广泛热门

```text
C = 同平台、同形态、同内容分类、同作者体量及可比观察条件的参考集合
Q = 集合 C 的播放分位阈值
候选命中条件：V >= Q，且有效样本数 >= M
```

- 候选起点：Q=P95、M=200；均待校准。平台、形态、观察年龄/窗口和播放口径必须相容。
- 分类、作者体量边界、参考数据时间范围及稀疏集合的处理顺序需配置并版本化。没有已批准的放宽规则时，样本不足就返回数据不足，不自动改为全平台集合。
- 同一视频在参考集合只贡献一条观测；剔除目标视频自身，防止目标参与定义自己的门槛。
- 地区/语言只有在参考集合定义明确且有数据时才能成为计算维度；用户页面筛选不能临时改变参考集合或重算分位。
- 是否增加绝对播放下限尚未定稿。历史实验中的下限不能与本候选混为已生效规则。

### 3.3 参数与观察前提

| 参数 | 候选起点 | 冻结前必须确认 |
| --- | --- | --- |
| 账号历史数量 | 最多 20，至少 10 | 三平台同形态、同龄历史的实际覆盖 |
| 账号突破倍数 | 10 倍 | 人工有效发现率、低基数误报与规模偏差 |
| 同类分位/样本量 | P95 / 200 | 公共集合代表性、稀疏分组和稳定性 |
| 存量观察窗口 | 按平台、形态确定 | 历史快照、取点容差及不可比较时的状态 |
| 规模门槛、刷新/有效期、排名 | 未定 | 业务名称、成本、时效和用户可解释性 |

不能用今天的累计播放反推出“发布后第 7 天播放”。没有可信同龄历史时，不用“当前累计对当前累计”冒充严格的同龄账号比较。

## 4. 内容监控近期规则：待定稿的计算边界

近期识别需要先确定比较的是“截至当前年龄的累计播放”，还是“同长度近期窗口的播放增量”。两者不能混用同一阈值或同一结果名称；这一选择尚未获批。

| 视角 | 若选择近期增量方案的候选形式 | 必需条件 |
| --- | --- | --- |
| 账号突破 | 目标窗口 ΔV 与同作者可比窗口的历史 ΔV 中位数比较 | 两端真实观测、相同窗口长度/年龄阶段、足够历史、正基线 |
| 广泛热门 | 目标窗口 ΔV 与同平台同形态可比窗口的 ΔV 阈值比较 | 有代表性的参考集合、同观测条件、足够有效样本 |

该表只是待确认候选，不沿用公共存量的 10 倍/P95/200 作为监控默认。若改选累计播放，则必须使用与目标当前年龄可比的累计参考值，仍不与成熟作品终身累计播放比较。

- ΔV 只由两个真实、同口径观测值计算；记录起止时点、实际间隔和观测来源。缺任一点、采集间隔不符或字段口径变化时不补造。
- ΔV<0 可能是平台修正或观测异常：标明数据不足/修正原因，不钳为 0 后继续认定增长，也不自动认定未达标。
- 所需观测尚未到达且采集计划可信时为待观察；没有足够数据来源则为数据不足，不伪造时间倒计时。
- 项目私有补录/修正仅能在明确授权的结果范围中使用，不覆盖公共存量结果；跨项目去重、权限和结果归属需接口评审。
- 近期配置未确认或不可用时，可明确展示公共存量结果及其用途；不能把它改名为近期识别结果。

## 5. 输入、时间与异常处理

| 输入/情况 | 要求 |
| --- | --- |
| 身份 | 平台+原生视频 ID 为视频去重键；作者关系、内容形态和源字段可追溯 |
| 内容形态 | YouTube 普通视频/Shorts 分开，直播暂不参与；TikTok 确认为视频；Instagram 确认为视频/Reel。已确认非视频或排除形态返回 `not_applicable`；形态缺失/不可靠返回 `insufficient_data` 并说明无法确认，不默认归为普通视频 |
| 核心播放 | 保留原值与口径版本；缺失/非有限/负值不可计算，真实 0 不当缺失 |
| 时间 | 分开保存发布时间、指标观测时点、评估截止时点、计算完成时点；时区统一，异常未来时间不可用 |
| 多任务同视频 | 同批次只取一条稳定、完整且满足窗口的观测；保存取点规则，不按任务重复加权 |
| 可选互动 | 缺失保留未知，不填 0；不回退为点赞算法或固定互动率否决 |
| 历史与分类 | 不用未知形态、混合帖子均值、当前粉丝数补造历史状态或同龄参考 |
| 结果修正 | 指标/来源修正后可重新发布结果；保留旧上下文和撤销记录，不改写历史报告 |

前端不计算中位数、分位、倍数、判定门槛或排名。旧 `video_score`、监控 `hotLevel` 和品牌 `topVideoRate` 保持原义，均不能直接映射为新标签。

## 6. 统一结果与可用状态

### 6.1 上下文与结果字段

| 层级 | 必须保存的语义（字段名可在接口评审中对齐） |
| --- | --- |
| 结果上下文 | `contextId`、计算用途/配置、观察范围、窗口及取点政策版本、`batchId`、`resultVersion`、`evaluationAsOf` |
| 视频身份 | `videoId`、`platform`、`contentType`、作者关系、发布时间、`metricObservedAt`、计算完成时间 |
| 读取边界 | `accessStatus`、允许读取时的 `coverageStatus`；指标及证据按权限裁剪 |
| 两个独立结果 | `assessments.broad_popular`、`assessments.account_breakout`；允许未覆盖视角缺省 |
| 每个视角 | `status`、`freshness`、`validity`、`algorithmVersion`、`rankingPolicyVersion`、可空的 `rankKey`、证据与可公开原因 |
| 证据 | 当前值、比较对象/定义版本、样本量、基线/阈值、观察时点和数据限制；未知与 0 分开 |

同一视频、用途、观察范围、批次、版本和权限上下文中，搜索、榜单、频道及品牌读取一致结果。不同用途可有不同结论，必须标明用途/窗口，不能互相覆盖。

### 6.2 正交状态

| 字段 | 取值与含义 |
| --- | --- |
| `status` | `qualified` 命中；`not_qualified` 数据充分但未达标；`pending` 等待所需观测/处理；`insufficient_data` 缺少可信核心数据/样本；`not_applicable` 不适用形态 |
| `freshness` | `fresh` / `stale`，由服务端配置的有效期判断 |
| `validity` | `valid` / `invalidated`，撤销不改写成未达标 |
| `accessStatus` | `allowed` / `restricted`，优先于内容/证据展示 |
| `coverageStatus` | `full` 两视角均纳入结果服务；`partial` 一个视角有结果、另一个未覆盖；`none` 两视角均未覆盖。它不代表两个视角都已完成评估或源数据完整 |

“待观察”是 `pending` 的可读原因，不新增另一套命中枚举。`not_covered` 是缺省视角的不可用原因，不冒充 `pending`；缺失视角不补成未达标。受限时覆盖信息若不可公开应省略，不能推断为未覆盖。

当前有效命中 = 适用视频、允许读取，且该视角 `qualified + fresh + valid`。过期/撤销不计当前命中，历史结果保留原时点。

### 6.3 合法读取响应示例

以下为简化契约示例；`contextId` 必须可解析到 6.1 的完整固定上下文。未覆盖不返回伪造 assessment，请求失败不返回成功的“暂未覆盖”。

```json
{"ok":true,"contextId":"ctx-a","videoId":"v1","platform":"youtube","accessStatus":"allowed","coverageStatus":"none","assessments":{},"unavailableViews":{"broad_popular":"not_covered","account_breakout":"not_covered"}}
```

```json
{"ok":true,"contextId":"ctx-a","videoId":"v1","platform":"youtube","accessStatus":"restricted","assessments":{}}
```

受限响应仅保留允许公开的身份与状态，不下发隐藏指标、样本、基线、队列成员、排名键或内部原因码；前端折叠不是权限裁剪。

```json
{"ok":true,"contextId":"ctx-a","videoId":"v1","platform":"youtube","accessStatus":"allowed","coverageStatus":"partial","assessments":{"broad_popular":{"status":"insufficient_data","freshness":"fresh","validity":"valid","algorithmVersion":"a1","rankingPolicyVersion":"r1","rankKey":null}},"unavailableViews":{"account_breakout":"not_covered"}}
```

```json
{"ok":false,"error":{"code":"RESULT_SERVICE_UNAVAILABLE","retryable":true}}
```

服务端返回 HTTP/错误语义需评审；失败时页面保留原列表和原已取得状态，依据区提供重试。正常完整响应则有两个 assessment，且字段规则与部分响应相同；无权字段始终不下发。

## 7. 双视角展示、筛选与统计

| 广泛热门 | 账号突破 | 当前有效标签 | 全部爆款 | 双重命中 |
| --- | --- | --- | --- | --- |
| 命中 | 命中 | 两个独立标签 | 是 | 是 |
| 命中 | 未达标/不足/待观察/未覆盖 | 广泛热门；另一视角按需说明 | 是 | 否 |
| 未达标/不足/待观察/未覆盖 | 命中 | 账号突破；另一视角按需说明 | 是 | 否 |
| 未达标 | 未达标 | 无命中标签；可说明未达标 | 否 | 否 |
| 无有效命中，且有缺失/失效 | 任意非命中 | 分别说明缺失/失效，不汇总为未达标 | 否 | 否 |
| 受限 | 受限 | 权限提示 | 否 | 否 |

“已评估”表示该视角数据充分且结果有效、新鲜，包含命中与未达标；“已入选/命中”仅表示 `qualified`，两者不混称“已识别”。

- 单视角评估状态仅匹配该视角；不限视角时，按任一视角匹配并显示状态归属，例如“账号突破：数据不足”。状态查询必须显式带状态归属视角（任一/广泛热门/账号突破）；没有单独视角控件时可在原状态下拉中分组表达，默认任一。不能借正向爆款类型字段表达“账号突破数据不足”。
- 爆款类型是正向命中过滤：全部爆款为任一命中，双重命中为两个都命中，指定类型只认对应视角。与不足/待识别等冲突的状态组合不开放；服务端拒绝冲突参数，禁止类型匹配一个视角而不足匹配另一个视角。
- 原业务条件与结果条件在服务端组合后分页；页面条件不影响判定参考群。不从当前页反算覆盖率、命中数或作者聚合。
- 每个视角返回同权限、同业务范围下的适用数、已评估数、有效命中数及未知分母原因。覆盖分母不被“只看爆款”缩成命中集合；按平台+视频去重，不适用对象排除，待观察/不足留在适用分母。
- 覆盖率=已评估数/适用数；分母未知或 0 显示“—”。命中数独立展示，不把部分覆盖的已知命中数当完整总数。跨视角合并比率本期不默认提供。

## 8. 发布、排名与历史

计算服务发布完整且原子切换的结果批次；失败保留上次成功批次，显示实际更新时间和延迟，超过有效期按过期处理。翻页/下钻使用相同上下文，权限或上下文变化须显式重新查询。

入选与排名分开：只有当前视角有效命中且具备兼容排序键的记录可入榜。服务端返回 `rankKey` 与排序策略版本，固定同平台/用途/观察范围比较；缺键或版本不兼容不由前端补位。具体排名公式及平分规则待定，不用解释倍数或原播放量临时替代。

历史报告保留生成时上下文；当前查询使用最新成功上下文。发布时间、首次命中时间、首次入榜时间不同，未有历史记录就不显示“首次爆款/新上榜”。

## 9. 验收与上线前待确认

必须覆盖：双命中、单命中+不足、双未达标、待观察、未知形态、缺播放与真实 0、零基线、目标剔除、重复任务、同龄数据缺失、负增量、部分/未覆盖、受限字段、过期/撤销、请求失败、原子换批次及跨页一致性。相关页面验收见[榜单页 SPEC](榜单页_SPEC.md)、[其余功能模块修改 SPEC](其余功能模块修改_SPEC.md)。

上线前仍需产品与研发共同确定：

1. 公共存量与监控分别使用的指标/窗口/可比取点、正式用途名称和项目权限范围。
2. 三平台形态与历史观测来源、参考集合及稀疏处理、候选阈值的公共样本校准。
3. “广泛热门”名称是否匹配队列含义，以及绝对规模门槛是否必要。
4. 结果服务归属、接口/存储/索引、成本/刷新/有效期、权限、算法换版和排名策略。
5. 分平台人工标注下的有效发现、误报、覆盖和规模偏差；Demo 测试与历史监控样本不能代替生产效果验收。

已知数据证据与旧指标兼容结论见[保留结论汇总](保留结论汇总.md)。上述未决项没有定稿前，可实施协议/页面骨架与离线验证，不能宣称算法已冻结或三平台已具备生产覆盖。
