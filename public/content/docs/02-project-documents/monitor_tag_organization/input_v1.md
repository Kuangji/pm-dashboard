## 问题与目标

内容监控的项目筛选、单条编辑、批量打标和手动新增都使用视频标签。标签增加后，运营人员难以在平铺列表中定位常用标签。不同入口的搜索和快捷能力也不一致。共享标签定义、内容关联和个人偏好需要各自独立。

本次让运营人员在同一目录中分组浏览、搜索和快速选择，让字典维护者在独立页面整理标签，并让用户在原有项目工具栏中保留自己常用的组入口。

## 范围

| 工作 | 已确认内容 |
|---|---|
| 标签目录 | 内容监控统一使用视频标签目录。原「额外标签 1／2」合入一个「额外标签」组，保留存量标签 ID、关联及原有访问资格 |
| 标签选用 | 主下拉和各打标入口支持折叠分组、搜索、个人标签置顶。页面筛选用组内和组间两项关系，默认组内 OR、组间 AND |
| 个人分组置顶 | 在主下拉的组标题行点图钉，最多把 3 个组设为快捷下拉。该组随之移出主下拉，取消后回到主下拉。所有入口共用一个筛选，「无标签」作用于整个有效目录 |
| 共享配置 | 支持组排序、组内标签排序、标签拖动换组、组头新建标签和标签原行改名改色。换组需要二次确认，并在权限允许时展示受影响内容数 |
| 兼容检查 | 验证旧筛选回放、导入导出、现有看板和列表、自动追踪使用的标签，以及账号和字典权限 |

历史常用标签已从本轮范围裁剪。CRM、达人收藏及其他模块标签在内容监控验收后另行评估。分组快捷是按账号及有效标签字典隔离的个人设置，是否随首版提供服务端存储和跨设备恢复留待研发评审。

## 现状依据与沿用约束

- 频道搜索的地区选择器提供分组浏览、搜索和独立滚动，作为标签选择器组织内容的参考。现有内容监控筛选、标签编辑和导入路径的逐项依据收录在评审入口。 [现状和证据](README.md#3-现状和证据)
- 内容监控项目与任务的对象边界沿用项目定义。标签筛选是工作台条件，日报仍按自身的项目、日期与可见范围冻结。自动追踪沿用现有规则生命周期。 [内容监控项目上下文](../monitor_760/monitor_common_context_v1.md) · [监控日报发布资料](../monitor_762/README.md) · [自动追踪上下文](../monitor_763/monitor_common_context_v1.md)
- 账号权限及共享字典范围以既有部署与业务组验收为准。对生产版本、实际发布阶段和新增效果指标保留验证。 [账号权限统一版本](../account_permission_collaboration/phase2_input_v0.md)

## 完成标准

- 运营可在配置好的主下拉和快捷下拉之间完成一次筛选，在单条、批量和手动新增中继续使用完整授权目录。
- 共享定义维护与个人快捷、个人标签置顶各自生效。两账号操作同一目录时，个人入口和置顶保持隔离。
- 迁移前后对照存量标签 ID、内容关联、原有资格和可执行的旧筛选结果。交互、权限、兼容和回退使用同一验收矩阵。 [验收矩阵](spec_v1.md#61-验收矩阵)
