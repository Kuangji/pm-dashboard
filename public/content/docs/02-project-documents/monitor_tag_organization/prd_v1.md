## 1. 目标与验收

项目运营需要更快找到视频标签，并在项目筛选、单条编辑、批量操作和手动新增之间使用同一目录。字典维护者需要有单独的管理入口。高频分组可以作为个人快捷下拉使用。

| 检查项 | 验收目标 |
|---|---|
| 项目筛选一致 | 主下拉与快捷下拉共用一次应用，同一条件在看板、列表、结果全选和导出下得到一致的范围 |
| 人员与字典隔离 | 两个账号使用同一共享字典时，个人置顶和分组快捷各自生效。切换字典或失去权限时重新校验 |
| 存量完整 | 迁移前后存量标签 ID 与内容关系对照零非预期差异，授权范围内的历史查询按原语义回放 |
| 关键路径 | 实施规格 A01–A10 在预发走通。标签目录首次打开、搜索响应的性能目标按真实分布复核 |

历史常用标签已裁剪。本期覆盖内容监控视频标签。CRM、达人收藏等其他标签另行评估。看板、导入导出和自动追踪按兼容范围验收。 [需求边界](input_v1.md#范围) · [验收矩阵](spec_v1.md#61-验收矩阵)

## 2. 用户流程

### 2.1 项目筛选与个人快捷

1. 打开「视频标签」，顶部搜索匹配可见分组名或标签名，搜索结果自动展开。清空搜索恢复折叠状态，勾选在搜索或折叠时保留。紧凑头部的「管理标签」与搜索同行。
2. 普通组名旁带描边底座的空心图钉可把分组设为独立下拉，最多 3 个。主按钮以品牌浅底突出，快捷按钮用中性描边，组名前的标签图标与主按钮一致。设置后，组候选、置顶和已选项移出主下拉。独立下拉的实心图钉取消快捷，回到主下拉并定位该组。
3. 主下拉和快捷下拉共同维护一份筛选草稿。各入口的「清空」只处理本入口的选项，页面的「清除标签筛选」清除全部标签条件。切换入口保留草稿，存在当前下拉未展示的变更时提示一并应用。取消关闭本次草稿。
4. 仅在主下拉设置组内关系和组间关系。默认组内 OR、组间 AND。应用时记录所选标签 ID 的分组快照，变更目录排序、组名或标签归属不会自动重算已应用条件。具体重组行为见实施规格。
5. 「无标签」在主下拉单独展示，并标明未打标的可见监控内容条数。按整个有效授权目录判断是否已打标签。应用后清除所有下拉的普通标签条件，并在各入口和筛选摘要回显条数。任一入口选普通标签并应用可替换该条件。
6. 个人标签置顶在选用时操作，图钉位于标签行最右侧。已置顶图钉常驻，未置顶时在悬停、键盘聚焦或触屏显示。顶部「我的置顶」用紧凑标签，勾选位等宽，解除入口在悬停或聚焦时显示为右上角「×」。选中标签与保存个人置顶是两个独立动作。

选择器、置顶区、已选区、管理页和手动新增表单在标签名旁统一显示「N 条」。监控内容列表的标签只显示名称。按当前账号在有效字典下可见的监控内容 ID 去重，同一标签共享计数。打标或移除关联后刷新。

### 2.2 单条、批量与手动新增

| 入口 | 提交规则 |
|---|---|
| 编辑已监控内容 | 回显当前绑定的可读标签，只替换有权编辑的关系。隐藏和不可编辑的关联继续保留 |
| 批量添加 | 从空草稿开始，显示目标数量。只新增可写且尚未存在的关联 |
| 批量移除 | 从空草稿开始，只移除目标已有且可写的所选关联。部分失败返回可安全展示的结果 |
| 手动新增 | 在内层保存标签草稿，外层创建监控成功后建立关联 |
| 管理往返 | 回到选择器时复核草稿标签和选择目标。结果变化时取消选中退出当前范围的内容，再提交批量写入 |

各打标入口保留完整授权目录，包括已经设为快捷的组。 [操作与提交规则](spec_v1.md#4-选用入口与提交规则--u01u06)

### 2.3 共享标签管理

具有字典维护权限的用户可新建、改名、排序、删除分组。组头「＋」以原行方式创建标签，标签行「更多」打开原行改名与改色。名称、颜色、取消、保存紧贴排列。有未提交修改时先保存或取消，再离开管理、切换身份或打开分组编辑。

分组和标签的拖动手柄位于最左，呈现时名称起点保持固定。拖动组时临时收起组内容，松手后恢复原展开态。「未分组」固定在末尾。组内标签排序即时保存。标签跨组时二次确认，说明来源、目标，以及权限内当前使用该标签的内容数量。手柄提供键盘位置表单。

删除组时将其中标签移回「未分组」，保留 ID 与内容关联。删除标签时展示影响范围。如果当前筛选正在使用该标签，确认框还要说明结果变化，删除唯一条件时说明会清除当前视频标签筛选。

## 3. 数据、权限与存量迁移

| 对象 | 接入约束 |
|---|---|
| 共享目录 | 按有效字典维护一层目录，标签保持稳定 ID。迁移时将原额外标签 1 和 2 归到同一个「额外标签」组。历史同名不合并，用来源及必要的 ID 识别 |
| 访问权限 | 统一入口不改变原额外标签的读取、筛选及写入资格。字典可读、定义维护和内容关系写入分别校验。上线前核实授权来源及实际部署的字典范围 |
| 个人偏好 | 标签置顶和分组快捷均以账号及有效字典隔离。旧实际存在的个人记录按 ID 迁移，旧共享置顶留给兼容路径。分组快捷优先评估服务端持久化，首版可采用隔离的浏览器存储 |
| 保存条件 | 新旧条件均保存语义版本。旧平铺、旧维度、旧 AND／OR 和旧无标签条件走原版本回放。新版归组变化与当前授权发生冲突时提示用户处理，避免静默扩大结果 |
| 兼容写入 | 验证旧重名定义路径、整旧维度替换详情关系及旧导入创建权限。新旧界面并行和回退期间，采用能保留标签 ID 与隐藏关系的写入策略 |
| 导入导出 | 旧 Excel 模板和字段可继续读取。名称按旧来源与权限解析，无法唯一识别时按冲突处理。看板、列表和导出解析同一版本的筛选条件 |

## 4. 实施顺序与发布门槛

1. **研发确认。** 核实线上部署、扩展标签资格、旧筛选存储、旧接口实际写入路径以及可复用的个人偏好服务。确认字典内同名映射、数据迁移和回退顺序。
2. **预发接入。** 先准备目录、版本化筛选和兼容接口，再接工作台和配置管理，随后联调单条、批量、手动新增、看板、导入导出及自动追踪回归。
3. **灰度验收。** 按有效字典分批开放。通过 A01–A10，核对迁移差异、ACL、请求失败、部分批量回执和回退。不同权限范围的两类账号，以及两种筛选版本，均应覆盖。
4. **效果观察。** 对比灰度前后从打开选择器到应用的耗时和成功完成比例，跟踪搜索无结果和写入失败。指标按入口统计，事件避免携带标签名、分组名或搜索原文。

正式文档以当前产品决策和独立 Demo 评审为基线。生产数据迁移、实际鉴权、旧筛选执行器、联调回执和回退继续走研发及 QA 验收。 [研发评审待核](spec_v1.md#7-研发评审待核)
