# v7.6.3 内容监控自动追踪 QoL 计划 v1

> 阶段：`phase_2_design_review_pass`
> 模式：`strict`
> 版本：`v7.6.3`
> 上游：`input_v1.md`
> 下游：`spec -> design -> prd`

## 1. 目标

将自动追踪从单一手动创建和固定生命周期，推进为支持多来源频道选择、另存为新规则、暂停/恢复、显式时长和可选历史补扫的规则能力。

## 2. 模块拆分

| 模块 | 范围 | 依赖 |
| --- | --- | --- |
| M1 频道来源选择 | 手动/Excel、收藏夹、当前项目其他规则的频道选择与统一去重；来源选择不自动保存规则，不带关键词/短链 | 收藏夹频道接口、规则 list/detail、项目权限 |
| M2 规则保存与另存 | 新建、更新、另存为新规则；原规则隔离；另存保存成功后的立即生效确认 | 规则名唯一、规则保存接口、权限 |
| M3 生命周期与时长 | 暂停/恢复、计费暂停、恢复重算起点/到期时间；7 天/30 天/长期，统一沿用 7 天计费 | 规则状态、账本/席位、durationMode |
| M4 历史补扫与多来源 | 新建/另存保存时可选 3/7/30 天全平台补扫；复用未来追踪异步、重试、失败、通知和去重；一个内容可有多个规则来源 | 内容唯一键、未来追踪执行链路、任务/来源关系 |
| M5 一致性与迁移 | 关键词上限统一为 10；旧规则兼容；状态、时间和来源展示兼容 | 旧字段、旧状态、旧内容来源 |

## 3. 阶段顺序

1. Phase 0：冻结本计划和共同上下文，确认产品语义、边界和 Spec 前置依赖。
2. Phase 1：按 M1-M5 编写 `spec_v1.md`，覆盖规则、状态、时间、配额、任务、去重、权限和异常。
3. Phase 1 Gate：完成 Spec Review 和 Red Team，确认未把研发存储方案误写成产品约束。
4. Phase 2：基于真实 `kol-next` 页面和 `kol2.0-design-specification` 编写 `design_v1.md`，锁定真实组件落点、视觉约束和 Demo 合同。
5. Phase 2 Gate：完成 Design Review 后，再进入真实页面 Demo 实施；不在 Design 阶段修改生产代码。当前已完成，下一步进入 Demo 实施计划。

## 4. Gate 0 退出条件

- [x] `input_v1.md` 已完成代码事实核对并写入产品决策。
- [x] 历史补扫定义已确认：全平台、3/7/30 天、无独立配额、已有内容去重、只在新建/另存保存触发。
- [x] 收藏夹和其他规则仅作为频道选择器，不自动保存，不带关键词/短链；其他规则不跨项目。
- [x] 另存、暂停/恢复、时长计费、多来源和关键词上限口径已确认。
- [x] `monitor_common_context_v1.md` 与本计划完成 Gate 评审。
- [x] 用户确认进入 `spec_v1.md`。

## 5. 当前不进入 Spec 的实现选择

- 多来源关系使用关系表、数组或其他存储方式。
- Clone 复用新增接口还是提供独立接口。
- 历史补扫复用现有哪个服务端任务入口。
- 暂停计费在现有席位/账本中的具体实现映射。

这些内容由研发技术方案决定，但 Spec 必须定义外部可观察行为和验收结果。
