## 3. 重点一致性检查

- **历史时间语义**：补扫内部保留 `historicalStartAt/historicalEndAt`，终点绑定本次保存确认时间；新建时以服务端确认保存时间作为 `startsAt`，避免浏览器时钟和文案时间漂移。
- **另存为生效门槛**：另存成功但取消立即生效时，规则保持未生效，不启动未来追踪、历史补扫或运行中计费；确认生效后才进入统一追踪链路。该处理与“补扫用户感知上应与未来追踪一致”的约束一致。
- **编辑边界**：更新原规则、改名、改频道、改关键词、暂停和恢复均明确不触发或取消历史补扫。
- **去重与来源**：同一内容只有一个监控任务；多个规则或历史/未来模式命中时追加来源关系，任务、新增统计和通知按任务去重。
- **兼容边界**：旧规则的 `monitor_duration=null` 不直接解释为长期；单来源旧数据按单元素来源展示。

## 4. 发现并修正的问题

1. 新建规则行曾只写 `historicalEndAt=startsAt`，未说明服务端时间含义；已补充为“服务端确认本次新建保存的时间”。
2. 另存为行未明确取消立即生效时的补扫行为；已补充为“只有确认立即生效才启动补扫，取消则不启动”。
3. 已补充收藏夹选择器的实现决策：优先复用 `../kol-next/components/email/detail/recipient/simpleResourceList.vue` 的选择交互；若与自动追踪业务耦合冲突，则复制同交互并隔离提交逻辑。
4. 已修正平台边界：自动追踪允许同一收藏夹内跨平台累积选择；现有组件的单平台读取只作为复用时需要适配的实现限制。
5. 多来源展示已收敛为“自动追踪 · N 个规则”标识的 hover Tips，移除详情展开面板要求。
6. 历史补扫不展示专属进度；仅在统一任务异常时显示“异常”状态、原因和既有重试入口。
7. 表格建议已转为 Spec 约束：单收藏夹跨平台选择、其他规则多选、缺少短链先导入后保存校验，以及静态可运行 Demo 验收边界。
8. Demo 实施复核后补齐常规状态边界：编辑态可回到新建、切换规则保护未保存修改、窄视口保留关闭按钮；生效期和历史补扫配置在编辑态只读，调整通过新建规则完成。
9. 长期定义建议收敛为“无自然到期时间 + 连续 7×24 小时有效追踪无新的未来命中自动终止”；历史补扫、重复内容、暂停和采集失败不计入观察期。该定义合理，但需要服务端新增最后命中时间、有效追踪时长和独立终止原因。
