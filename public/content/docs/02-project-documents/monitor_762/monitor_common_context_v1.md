## 1. 版本目的

本版本在内容监控已有项目、任务、数据看板和筛选能力上增加 AI 项目解读。它的基本单位不是一篇脱离上下文的通用文章，而是一个被冻结的 `analysis scope` 加上一份可回链的事实包和生成式文案。

## 2. 事实分层

| 标签 | 含义 | 文档使用规则 |
| --- | --- | --- |
| `[事实]` | 已由源码、线上请求/响应或现有文档直接支持 | 可以作为现状描述；注明来源和边界 |
| `[建议]` | 本版本为满足目标提出的产品/技术方案 | 不写成现有能力；需在 Spec/Design 再细化 |
| `[待确认]` | 需要服务端、数据、权限、计费或线上复核 | 不可在文案中承诺；进入 Gate 清单 |

## 3. 对象与 scope

首期 `analysis scope` 固定为：

```text
一个用户有权访问的内容监控项目
  + 当前已生效的内容资格筛选
  + 一个数据观察区间
  + 页面时区/服务端返回的快照时间
```

分页、表格排序、局部折叠只改变展示，不改变 scope。刷新、筛选或观察区间变化后，旧报告必须被视为可能过期，不能静默套用到新 scope。

## 4. 报告契约的最小语义

- **事实摘要**：确定性计算，展示数字、范围、变化、贡献和数据状态。
- **AI 解读**：模型生成的中文文案，回答“发生了什么、值得关注什么、下一步看什么”。
- **证据**：主张所引用的指标、内容、频道、标签或数据问题，并能回到原页面。
- **限制**：数据截至时间、覆盖/样本状态、未知 baseline 和不能回答的事项。
- **状态**：`success`、`partial`、`insufficient`、`permission`、`stale`、`error`。

成功态必须有 `generationMode=llm` 且至少一个非空生成式 section；确定性摘要不能伪装成 AI 成功态。数据不足时可以渲染事实和限制说明，但状态必须表达不足，不能用模板句冒充生成结果。

## 5. 允许与禁止的推理

允许：基于当前事实包描述变化、集中度、共现关系、需要复盘的对象，并使用“可能”“建议核查”等限定词。

禁止：因果归因、实时承诺、全量覆盖承诺、ROI/转化判断、项目级评论舆情、视频画面/字幕/ASR/OCR 理解，以及事实包中不存在的数字、实体、时间和比较基线。

## 6. 设计与实现权威

- 设计令牌、组件状态、可访问性：以 `../kol2.0-design-specification` 的当前 `README.md` 与相关 `playbook/` 为准；旧版 760 上下文中的视觉值只作历史参考。
- 现有页面/组件/路由：以 `../kol-next` 对应源码和本版本真实浏览器校验为准。
- 线上事实样本：见 AI 可行性研究包的网络捕获原始记录；样本数字不能硬编码进生产报告。

## 7. 待确认边界

以下不是当前上下文的默认事实：固定采样频率、last collected/freshness、coverage、稳定 baseline、snapshotId、metric/anomaly version、AI endpoint 具体路径、模型/Prompt 版本、配额扣点、缓存重放权限和成本 SLA。它们必须在 Spec/研发联调前补证或显式降级。
