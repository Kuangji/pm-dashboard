# v7.6.2 VDR 计划：内容监控 AI 项目解读

> 状态：`Phase 1 / Input 评审中`
> 模式：`strict`
> 立项约束：版本必须开；首期成功结果必须包含非空生成式 AI 文案。
> 版本日期：2026-08-20

## 1. 目标与阶段

v7.6.2 的目标是在已有内容监控项目数据看板之上，增加与频道详情、品牌监控报告具有统一心智的 AI 解读能力，同时保留确定性项目摘要作为事实骨架和降级说明。

当前只推进到：

```text
事实/代码/线上证据
  -> common_context_v1
  -> input_v0（当前）
  -> Input Gate 评审
  -> spec -> design -> prd
```

## 2. 模块拆分候选

| 模块 | 责任 | 当前状态 | 依赖 |
| --- | --- | --- | --- |
| M1 AI 报告工作面 | 入口、生成前/中/后状态、成功/部分/不足/权限/过期/错误 | 待 Input 评审 | M2、M3 |
| M2 事实包与证据 | scope 冻结、观察区间、指标、贡献、数据健康、证据深链 | 待 Input 评审 | 现有 monitor API |
| M3 生成与校验 | 结构化生成、限定词、数字/实体核对、拒答与审计 | 待 Input 评审 | M2、AI 服务能力 |
| M4 权限/配额/缓存 | entitlement、扣点、授权指纹、失效和重放 | 待确认后拆 | 账号/计费/服务端 |
| M5 评估与灰度 | 离线样本、人工标注、质量门、灰度和回滚 | 待 Input 评审 | M2、M3 |

M1-M3 是首轮规格的最小闭环；M4、M5 不应被省略，只是可在 Input 通过后并入跨团队实施计划。

## 3. Input Gate 退出条件

- [ ] 评审人确认首期对象是“单项目 + 当前资格筛选 + 观察区间”，而不是跨项目报告。
- [ ] 评审人确认确定性事实层与生成式文案层必须同时存在，且成功态 `generationMode=llm`。
- [ ] 评审人确认每条主要主张可以回链到内容、频道、标签或数据问题证据。
- [ ] 数据、服务端、权限/配额、设计、前端各责任人已认领待确认项。
- [ ] 已确认的 V1 out 仍不进入本版本输入范围。

## 4. 下一阶段入口

Input Gate 通过后，按 M2 -> M3 -> M1 的业务依赖顺序写 `spec`，再依据当前设计规范、`kol-next` 代码和真实浏览器校验写 `design`，最后汇总 `prd`。若评审改变分析对象、报告契约或硬性生成条件，必须回退并修订本 Input。

## 5. 主要风险

- 现有接口可提供聚合、趋势和贡献，但尚未证明固定采样频率、稳定 baseline、coverage、snapshotId、metric version。
- 真实 AI 服务的 endpoint、模型、Prompt 版本、延迟、成本、额度扣减和缓存策略仍未由前端证据确认。
- 现有品牌 AI 的空列/无证据表现不能作为内容监控的交互或质量标准。
- 项目内容规模、平台混合和权限变化会放大事实包与深链的一致性风险。
