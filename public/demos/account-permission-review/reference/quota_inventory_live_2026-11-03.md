## 与当前方案的关系

1. **展示清单不等于分配清单。** 某项出现在成员矩阵，不足以证明它可分别设置组上限、组内个人上限或采用相同计算方式；其容量占用、次数扣减、频率限制、共享解锁与重置规则仍须逐项核实。
2. **保留单位和周期差异。** 此页各列标题没有统一标明计量单位；“每天上限”“每月上限”显然不能合为一个额度。其余项不能仅凭名称推定为按月次数、整数次数或统一重置。观察到当期视图显示配额起止时间，但不把当前组织的周期当成全部套餐规则。
3. **Demo 名称暂不强行映射。** 此矩阵没有直接名为“搜索次数”“频道详情页解锁次数”或“邮件发送”的列。不能据名称相近就确认“频道详情页解锁次数 = 基础数据分析”或“邮件发送 = 批量邮件邀约数量”。此前 Demo 的三种配额仍是共存、排列与流程样例，真实映射待核实。
4. **子账号席位单列。** “子账户数量”属于该页面的组织总览项，没有对应的成员矩阵列；不能因此新增“给每名成员分配子账号席位”的流程。
5. **数据导出范围不因盘点扩大。** 深度数据导出及基础数据导出的日/月项纳入现状清单，不因此恢复已后置的数据导出交互需求；按当前 Input 确定其是否仅需接入配额控制，仍须与导出功能需求区分。
6. **支付金额单独处理。** 当前矩阵未展示支付金额项，不影响本版已确认的组织余额、组资金上限及组内个人支付上限规则；不要把“矩阵未列出”解释为取消支付金额约束。

本次不扩展 Demo 到全部 22 项，也不把 Scope 可分配矩阵标为已完成。后续矩阵应在这些原名旁补充真实 Scope 标识、计量单位、发放/控制周期、是否可下分、使用主体及共享/去重口径，再决定 UI 分组与顺序。

## 证据边界

**线上实测：** 中文站上述页面，切换两种用量视图，以组织总览标题和成员矩阵列标题交叉计数。成员分页不用于统计配额项数；不读取或保存成员明细作为本次交付物。

**前端静态核对：** `../kol-next` 当前分支为 `codex/752-brand-reputation-radar`，只读检查 `pages/brand/sub-account/quota.vue`：

- `formatCurrentBorderData` / `formatAllBorderData`：总览名称经 `scopeIdMap` 转译，来自对应总览数据列表，不是写死的全站完整枚举。
- `currentTableColumn` / `allTableColumn`：成员列取各视图首条成员记录的 `scopeList`，所以当前列表不能证明其他套餐或组织没有额外 Scope。
- 模板中 `costNum` 与数值型 `quotaDefault` 分别渲染用量和上限；仅从是否显示斜杠或数值，不能推断后台完整额度规则。

本地分支不是线上部署版本证明；本次没有核对服务端枚举、分配资格或扣量实现。现有[服务端 Scope 产品规则](./scope_quota_product_rules.md)作为后续核对依据，不把静态材料当作本次接口实测。
